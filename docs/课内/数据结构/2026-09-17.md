### 四种逻辑结构

**29:38**

书上把这些数据大致分为四种结构：集合结构、线性结构、树形结构和图。集合结构中，这些数据之间的关系非常松散，没有顺序，但有一个关系：这些元素属于同一个集合，比如我们都是这个[听辨待核对：交纳]数据结构、CS0501 某个班级的，属于这样一个集合。第二种是线性结构。线性结构就是把元素排成一列；排成一列之后，除了第一个元素和最后一个元素之外，每个元素都有一个位置，也都有前驱和后继。例如某个元素的位置是 i，它的前驱就是 \(i-1\) 位置上的元素，后继就是 \(i+1\) 位置上的元素。第三种是树形结构：有一个根节点，根节点没有前驱，但可能有很多子节点；每一个内部节点应该只有一个前驱，它可能没有子节点，也可能有多个子节点。最后是图结构：每一个元素都可以与任意其他元素连一条边，所以每个元素的前驱和后继数目都不限。那么我们要对数据结构进行哪些操作呢？这里总结了一些在四种不同数据结构中大概都会用到的逻辑操作。

### 存储的实现

**34:50**

数据结构的存储实现有两个部分：一个是这些元素的存储，一个是元素之间关系的存储。比如在后面图的学习当中，我们要存储节点，还要存储边。它的物理结构，就是它在内存当中到底是怎么组织的：首先要存储节点，这个节点就是数据元素。我们后面也会看到，这里的数据不一定是数或者字符串，它可以是任意的类型，我们可以给它定义一些不同的类，这个元素可以是任意的类型。

**35:52**

**41:58**

**42:38**

不同的操作有不同的时间方式。比如[听辨待核对：签英表]，我们可以用线性表和链表去实现同一种操作，比如查询。这里主要讲的是：给定一种数据结构，我们如何评价这个查询操作的好与坏。此外还写了正确性——正确性是我们这些操作或者说算法首先要满足的一点：比如查询操作，我们不能随机地输出他在或者不在，而需要保证他真在就输出在、他不在就输出不在。算法还需要满足这些性质。

### 影响程序运行时间的因素

**43:59**

我们主要关注这些操作，或者说它们对应算法的时间复杂度和空间复杂度，下面具体分析算法的时间复杂度和空间复杂度。影响程序运行时间的因素有很多：首先是问题的规模，这最为直接——比如我们有五个同学，去查他的学号，或者有五万个同学，这就是问题规模的区别。其次是输入数据的分布，它也会影响算法的运行时间。比如后面会讲到的排序问题：如果输入的数据基本上快排好序了，那么采用某些算法时，一个 [听辨待核对：n 二边] 的算法就不如采用 \(n^2\) 的算法快。所以输入数据的分布也会影响这些操作实际运行的时间。当然还有硬件因素，这不是本课程考量的内容。最关键的是，我们可以用一些更高效的算法去提升程序的性能。

### 高效算法的重要性

**46:27**

降低程序的运行时间是最为关键的。这里有一个说明高效算法重要性的例子：假设我们有一台计算机，每秒能够处理一千条指令，要处理 \(n\) 个数据，也就是输入规模为 \(n\)。对于运行时间分别为 \(n\)、\(n\log n\)、\(n^2\) 的算法，当 \(n\) 取不同数值时，我们计算用这台计算机跑相应算法需要多长时间。可以看到，比如 \(2^n\) 是指数级的：当 \(n=50\) 时，这台计算机基本就不行了，不能处理；而一个 \(n^2\) 时间的算法，当 \(n=500\) 时，需要花 250 秒。实际上现在的数据规模非常大，比如刚才讲到的基因组测序数据，规模非常非常大，可以是亿级的级别，\(n\) 比如是 \(10^{15}\) 或者 \(10^{18}\) 这么大。这时候 \(n^2\) 也不行了，我们甚至需要比 \(n\) 还要小的算法，计算机才能在很快的、我们能接受的时间之内完成。这就是高效算法的重要性。那么，我们如何去衡量一个算法的效率呢？

**49:12**

我们采用刚才讲的时间复杂度和空间复杂度来衡量，这其实是比较简单的。我们主要先考量它的时间复杂度。时间复杂度实际上就是这样一个概念：它的运算量和输入问题规模的关系。

**49:39**

我们一般假设数据结构或算法的输入规模是 \(n\)，即有 \(n\) 个元素，观察运算量随着 \(n\) 如何增长。刚才也举了一个例子：算法的时间复杂度还与被处理数据的分布有关。

### 算法时间复杂度的衡量

**05:29**

我们回到如何衡量一个算法，或者说衡量对数据结构进行操作所需的复杂度，也就是判断它的好坏。算法的时间复杂度与输入数据的分布有关：例如排序时，如果输入数据几乎已经排好序，那么某些在最坏情况下为 \(O(N^2)\) 的算法，实际上可能只用常数步就能完成排序。因此，算法的时间复杂度与输入数据的分布有关。分析时间复杂度时，我们当然不会去分析最好的情况。

**06:54**

在这门课程中，一般情况下我们考虑最坏情况。比如查找操作，最坏情况是把整个数据结构扫描一遍，最后发现该元素不在数据结构中；这时实际上就是 \(O(N)\)。当然，有些时候我们也会考虑平均时间复杂度。比如后面讲哈希表时会讲到，哈希表的插入也不是每一次都能在常数时间内完成；最坏情况下也可能是 \(O(N)\)，但平均情况下是常数时间复杂度。那么，我们如何去表示或衡量算法的时间复杂度呢？算法运算量的计算，首先需要选择某些操作。

### 标准操作与算法运算量

**08:29**

我们把某些操作当作标准操作，也就是单位操作。这些标准操作所消耗的时间视为一个单位时间。然后数一数在算法运行过程中这些标准操作一共执行了多少次。例如，判断（if）、赋值、i++ 这些都可以看作一次标准操作。把执行次数加起来，就得到算法运算量的一个衡量。下面看一个例子：假设线性表（数组）中存放的都是正整数。

**09:48**

要求设计一个算法，找出数组中的最大值。输入是一个数组和一个常数 d，输出是数组中最大值与 d 的乘积。这个例子很直观：要求最大值，至少要把数组中所有元素遍历一遍。这里给出的算法是：先把数组中每个元素都乘以 d，然后再遍历一遍数组，输出其中的最大值。首先看这个算法是否正确。算法分析中正确性是第一位的。虽然先不考虑时间复杂度和实际运行次数，但这个算法的正确性毫无疑问。这里要问的不是正确性，而是如何分析它的时间复杂度。

**11:42**

分析时间复杂度，首先要找到单位操作，再数一数这些单位操作运行了多少次。例如看 for 循环：赋值 i = 0 是一个单位操作，判断 i < size 是一个单位操作，i++ 也是一个单位操作。循环控制部分中，i = 0 执行 1 次，条件 i < size 执行 n+1 次，i++ 执行 n 次，因为 i 等于 size 时就不再执行。循环体内也要计数：每个元素乘以 d 再赋值，算作两次单位操作，所以循环体共执行 2n 次。因此第一个 for 循环的总运算量是 \(2n + (n+1) + n + 1 = 4n+2\)。下面还有一个循环，结构与前面相同，也是 \(4n+2\)。此外还要算上给 max 赋初值、最后返回等操作。整个算法总操作次数为 \(4n+2 + 4n+2 + 2 = 8n+6\)。

### 大 O 表示法

**13:49**

得到总操作次数 \(8n+6\) 后，这是不是衡量时间复杂度的好办法？对于简单函数可以这样做，但有些函数非常复杂，而且每个单位操作所消耗的时间并不完全一样。因此，我们主要看问题规模很大时，算法运行时间随输入规模 n 变化的规律。也就是说，不考虑具体的函数表达式（如 \(8n+6\)），只考虑它的数量级：运行时间随问题规模增大而增长的速度。平常主要用大 O 表示法。大 O 的定义在算法设计与分析课程中也会学，书上也有。定义是：存在常数 c 和 \(n_0\)，使得当 \(n \ge n_0\) 时，都有 \(T(n) \le c \cdot f(n)\)。假设算法运行时间为 \(T(n)\)，比如刚才的 \(T(n)=8n+6\)。我们需要找到 \(f(n)\)，以及满足条件的 c 和 \(n_0\)。\(f(n)\) 可以取 n，因为可以令 \(c=14\)、\(n_0=1\)，就满足 \(8n+6 \le 14n\)。

### 大 Θ、大 Ω 与小 o

**16:43**

对于足够大的 \(n\)，\(cN\) 大于算法的运行时间，这时我们就说 \(T(N)\) 是 \(O(f(N))\) 的。实际上大 O 是我们经常用的写法，更准确的写法是大 \(\Theta\)。直观地说，大 \(\Theta\) 的意思是：算法的运行时间 \(T(N)\) 和 \(f(N)\) 的增长速率是一样的，比如都是线性的，或者都是平方的。大 \(\Omega\) 和小 \(o\) 这两个符号大家仅供参考，本课程的学习中一般不会用到；大 \(\Omega\) 一般表示运行时间的下界。

### 用大 O 描述运行时间的一个实例

**17:47**

所以本课程当中，包括小 \(o\) 一般也看不到，我们经常用的就是大 O 的写法。它得有一个实例：假设 \(T(N)=(n+1)^2\)，我们怎么说 \(T(N)\) 是 \(O(n^2)\) 的呢？我们找一个 \(n_0\)，比如 \(n_0=1\)，找一个 \(c=4\)，那么对于所有的 \(n\ge 1\)，\(T(N)=(n+1)^2\) 都小于等于 \(4n^2\)，所以 \(T(N)\) 就是 \(O(n^2)\) 的。大 O 表示法就是说，当它后面是一个多项式的时候，你可以很直观地去证明这一点。

### 大 O 表示的是数量级

**18:57**

大 O 表示法所表示的运行时间增长的速率，实际上就是多项式中幂次最高的那一项；它表示的是一个数量级，并不是一个精确的表示。对于本课程当中学习的这些算法或操作，\(f(N)\) 也不是非常复杂的，要么是 \(O(N)\)、\(O(N^2)\)，要么是 \(\log n\) 这类，不会是 \(n+\sin n\) 这样奇怪的；也很少见到根号 \(n\) 的——实际上也有根号 \(n\) 的，但在本课程的学习当中，\(f(N)\) 一般是一个比较简单的形式。这就是刚才讲的：低次项和常数项我们都给它忽略了。

**20:11**

下面其实也讲了，有一些操作可以用常数步完成；还有一些操作，比如 [听辨待核对：finner research]，它大概是 \(\log n\) 的。对于大 O 来说，log 取 2 或者取 10 实际上是没有关系的。另外还有 \(\log n\) 这一量级，在数据结构的学习当中不太常见；线性的 \(n\log n\)，比如有一些排序算法是 \(n\log n\) 的。

**20:50**

还有 \(n^2\) 的、\(n^3\) 的，还有 \(2^n\)，以及 \(n\) 的阶乘，比 \(2^n\) 还要大的就是 \(n!\)。这些对应的时间复杂度的关系，大家应该都比较清楚：\(\log n\) 比 \(n\) 要小，比 \(n\log n\) 要小，比 \(n^2\) 要小；而 \(2^n\) 属于指数时间，\(2^n\) 比 \(n^n\) 要小。

### 时间复杂度的计算步骤

**21:51**

下一个就是时间复杂度的计算，也就是我们刚才讲到的例子。计算时间复杂度的时候，首先需要定义哪些操作消耗单位时间，我们把它叫做标准操作；然后再数一数标准操作的次数，得到一个标准操作次数的和，就像刚才这个取最大值乘以 \(d\) 的例子，它大概是 \(8n+6\)。然后我们取主项，也就是次数最高的那一项，所以它是 \(O(N)\) 的。

### 简化计算：串行取最大值

**22:39**

在实际分析的时候，我们还可以用到一些简化的方法。比如有一个过程，它的运行时间是 \(T_1(n)\)；还有另外一个过程，它的运行时间是 \(T_2(n)\)。假设 \(T_1(n)\) 是 \(O(f(N))\) 的，\(T_2(n)\) 是 \(O(g(N))\) 的。把这两个过程——比如两个循环、两个程序或者两个子程序——串行，先运行 \(P_1\) 再运行 \(P_2\)，总的运行时间要取它们的最大值。比如 \(T_1\) 是 \(O(N)\) 的，\(T_2\) 是 \(O(N^2)\) 的，那么 \(T_1+T_2\) 就是 \(O(N^2)\) 的。当然，如果 \(T_1\) 是 \(O(f(N))\) 的，\(T_2\) 是 \(O(g(N))\) 的，那么 \(T_1\times T_2\) 这种操作我们一般情况下也非常少见。

### 大 O 的计算规则

**23:58**

一般情况下用得比较多的是上面那一个（串行时取最大值）。如果出现 \(T_1\times T_2\)，它是 \(O(f(N)\times g(N))\) 的。下面看大 O 表示法的计算规则，规则一：我们要找出哪些操作是单位的操作，哪些操作是常数时间的操作——这些操作的运行时间跟输入的规模没有关系，所以不管输入规模有多大……

### 大 O 运算规则

**24:48**

判断、赋值、返回等操作的运行时间都是常量，即 \(O(1)\)。规则二针对条件分支：如果满足某种条件，就执行语句一；否则执行 else 语句二。这个条件判断本身也是 \(O(1)\)。

**25:51**

在分析整个条件分支结构的时间复杂度，尤其是最坏情况的时间复杂度时，应取语句一和语句二运行时间的最大值；也就是要考虑程序在什么时候会出现最坏时间复杂度。规则三针对 for 循环。

**26:39**

数 for 循环的时间时，也要把循环控制行的运行时间计入。大多数情况下，循环控制行中的操作是单位操作，例如 i++ 是单位操作，执行 n 次，因此比较好数；但要注意，循环控制行并不一定总是常数时间。例如 for 循环中判断是否停止的 i < n，也需要计入。

**27:40**

循环体中的赋值操作，例如把每个元素都乘以 d，也要把它的运行时间加上。对于嵌套循环：外层 for 循环运行 n 次，对每一次外层循环，内层 for 循环又运行 n 次，所以整个时间复杂度是 \(O(n^2)\)。这就是刚才举的[听辨待核对：求 n 积]的例子。它后面还有连续的循环，即程序中有两个 for 循环。

**28:34**

程序中两个 for 循环并列。根据前面的规则，分析时间复杂度时要把两者相加。第二个 for 循环是 \(O(n^2)\)：对每个 i 跑 n 次，对每个 j 也跑 n 次。前面的 for 循环只跑 n 次，所以是 \(O(n)\)。根据加法规则取较大的量级，整个程序就是 \(O(n^2)\)。大 O 的简化运算就是：在整个程序中找出运行时间最长、最复杂的程序段，用它的时间复杂度代表整个程序的时间复杂度。例如刚才下面那段是 \(O(n^2)\)，整个程序就是 \(O(n^2)\)。这就是大 O 的表示方法。

### 大 O、Θ 与最坏情况

**30:06**

现在思考一个问题：大 O 表示是否总能准确表示程序的时间复杂度？比如刚才的算法是 \(8n+6\)，它当然可以写成 \(O(n^2)\)，但这种表达并不准确，因为我们选取的 \(f(n)\) 不是最小的 \(f(n)\)。我们说某个算法是 \(O(n)\) 的，实际上想表示它是 \(\Theta(n)\) 的；不过在数据结构课程中，把它写成 \(O(n)\) 也没有问题。这是因为很多时候大 O 表示的是最坏情况下的运行时间。例如在线性表中查找一个元素是否在表中：运气好时第一个元素就找到了，运气不好时要比较每一个元素也可能找不到。因此，对数据结构中的操作做时间复杂度分析时，在本课程中写成 \(O(n)\) 是可以的。但在以后，或者当我们拿到一个问题去分析它实际需要多少时间时，需要找到尽可能小的函数 \(f(n)\)。比如 \(8n+6\)，我们一定要把它写成 \(O(n)\)。根据刚才大 O 的定义，它虽然也可以有更大的表示，但最好写成 \(O(n)\)。

**32:58**

这样的函数按大 O 的定义当然也可以写成 \(O(N^2)\)，但我们最好把它写成 \(O(N)\)，这是时间复杂度分析中会遇到的问题。书上还讲了一个例子，这个例子并不属于本课程最主要关注的内容，但我们仍然花时间介绍一下，它叫算法的优化。这个问题在书的第十六章，应该不考了，这里只作为一个比较有意思的问题来讲。

### 最大连续子序列和问题

**33:50**

这个问题是最大连续子序列和问题：假设有 n 个数，这些数可能有正有负，比如 -2、11、-4、13、-5、-2 这样一个序列。

**34:13**

我们要计算的是和最大的连续子序列。子序列必须是连续的：不能取 11、13，必须写成 11、-4、13，即使中间有负数，也要把这个连续的元素包含进去。那么该用什么样的算法来解决这个问题？

**35:03**

这属于算法分析的内容。首先想最直观的办法：把所有子序列都列出来，对每个子序列计算和，然后求最大值。这个算法的时间复杂度是多少？是 \(O(N^3)\)。因为对于输入规模为 n 的 a₁, a₂, …, aₙ 这 n 个数，所有子序列一共有 \(O(N^2)\) 个，而对每个子序列求和平均需要 \(O(N)\)，所以总共就是 \(O(N^3)\)。具体的分析我们在这里不细讲，也不细看伪代码，只讲一个大概的分析。

### 改进：复用已算出的部分和

**36:52**

有没有办法对这个算法进行改进？因为子序列是连续的，可以采用这样的方法：计算 1 到 n 的时候利用前面已经算出的结果，比如计算 1 到 3 的时候，1 到 1、1 到 2 的和已经算出来了，就不需要重新计算，只需要把 1 到 2 的和再加上第三个元素即可。这个算法仍然要枚举 \(O(N^2)\) 个子序列，但每个子序列求和只需常数时间，因此总的运行时间是 \(O(N^2)\)。

**38:18**

书上还给出了递归分治的方法，我们跳过不讲——它应该属于三个学分的课程中学习的内容，不是这本书的主要内容。不过在后面一些数据结构的操作当中，还是会用到分治的方法；递归分治还有一个（复杂度）分析，我们也不讲。

### 线性时间的解法

**39:23**

最后还有一个最好的算法，它是 \(O(N)\) 的，因为不可能比它更好——你必须把所有的输入都扫一遍。它观察到这样一个规律：假设从一开始算，算到某一个地方，发现这个子序列的和已经是负的了。也就是说，如果前面这个子序列的和已经是负的，它就一定不可能包含在（最大连续子序列）当中，可以直接跳到后面去，可以画这样一个图来看。感兴趣的话可以去看一看这个结论：算最大连续子序列和的时候，假设前面某个子序列的和是负的，那么它一定不可能包含在任何最大连续子序列当中，于是直接跳过它。这个算法之所以是 \(O(N)\) 的，我们根本不用去看它具体的实现，大部分的原理就是：你只需要对输入的数据从左向右扫一遍就可以了。

**41:10**

从第一个元素开始累加，一旦当前子序列的和为负，就跳到下一个元素重新开始计算，因为前面那个和为负的子序列一定不可能包含在任何最大连续子序列当中。大概就是这样一个思路。通过这样一个观察，我们可以得到一个 \(O(N)\) 的算法。另外，在数据结构课程的学习当中，我们还比较关注空间复杂度的概念，但空间复杂度的分析往往是非常直观的。

### 空间复杂度

**41:54**

它比时间复杂度的分析还要更简单一些。比如说这个线性表，你肯定需要 \(O(N)\) 的这样一个空间。但我们还是要看一下空间复杂度的定义：它有固定空间的需求，与处理问题的规模无关；有可变空间的需求，与处理的数据量有关。空间复杂度一般情况下分析起来非常简单，也非常直观。

**42:41**

但有的时候，它比时间复杂度分析还要更简单一些。当然，比较困难的是，就像我们刚才讲的，比时间复杂度分析稍微困难一点的是去分析这个算法的正确性。但是我们这是一门数据结构的课程，正确性分析往往也没有这么复杂，所以空间复杂度是最简单的。我们第一章的最后一节是面向对象的数据结构。因为我们这本书对每一个数据结构都给出了 C++ 语言的具体实现，

**43:34**

采用的是面向对象的编程。如果有不熟悉的同学，我们可以稍微讲一下：什么是面向对象，什么是过程化的数据结构。

**44:03**

在编程语言的学习当中，大家应该已经学习过面向对象的编程。我们来看一个例子，这个例子很直观。比如说我们对于某一个线性表，它有插入、删除，还有 find，就是去查询某一个元素在不在这个表里面，这样一些操作。我们可以把这个表输入进去，然后输入它的规模；比如说它要插入元素 x，我们就把这个元素插到位置 i。我们不需要把它写成面向对象的方法，可以直接这样写；我们也可以定义一个类，然后在类里面去实现插入、删除和查询这样一个实现。

**45:24**

面向对象的程序设计方法，就是为程序员提供了创建工具的功能。我们把这些要对对象进行的操作做了一个封装，写成了这样一些函数。比如说这个线性表，它可以有插入、删除或者是查询，我们把它写成了这样一些函数，是对这个线性表的类去调用插入、删除和查询。这样一个数据结构的实现方便了这个数据结构的用户，也就是使用我们这个数据结构的人。我们只需要知道它的逻辑特性，不需要知道它的逻辑结构是如何存储的、它的操作是如何实现的；你在调用的时候，只需要调用插入就行了。但是我们学习数据结构，肯定不仅要知道插入、删除这些操作具体是怎么实现的，

**46:50**

我们把它写出来，还需要在设计这些方法的时候能够满足用户的需求。所以这个课程后面我们看到的，都是使用面向对象的编程。数据结构的描述和实现，书上讲的实际上是这样的：每一个数据结构都用一个抽象类去描述。比如说这个线性结构，它可以支持插入、删除或者是访问某个位置 i 的元素。那么线性的这样一个结构，我们可以用线性表，也可以用链表去实现插入、删除这样一些操作，就用抽象类。

**48:07**

然后这个数据结构的实现，每一种数据结构都可以有不同的实现方法，每一个实现就是一个[听辨待核对：位，疑为“类”]。而这个实现要实现数据结构的逻辑特性。所以比如说这个线性表和链表的插入，或者是对线性表和链表的操作，都从这个对应的抽象类去继承。这个是泛型程序设计，就是上面那个 `template <class T>`，也就是我们刚才讲的那个例子：它不一定是我们这个数据结构里边存的那些常见的 `int` 或者是字符串，它可以是任意的类型，比如上面那个 `template <class T>`。然后我们这个数据结构只关注我们这个抽象类存储的这样一些关系。这个是我们课程第一章的总结。然后，我们到底有哪些数据结构？

### 线性表的定义

**01:27**

我们这里不讲字符串。因为我们这是三个学分的课，只会讲线性表、栈和队列。

线性表是具有 n 个相同特征的节点 \(a_0, a_1, \dots, a_{n-1}\) 构成的这样一个集合。在这个集合当中，除了第一个元素 \(a_0\) 和最后一个元素 \(a_{n-1}\) 之外，为什么说它是一个线性表呢？就是说它是这些元素的一个排列：每一个元素都有一个确定的位置 i，它前面的元素下标是 \(i-1\)，后面的元素下标是 \(i+1\)。第一个元素在最前面，它没有前驱；最后一个元素没有后继。我们一般用 n 表示输入的规模。

**02:50**

对于线性表来说，第一个元素我们称它为首节点或者头节点，最后一个元素称它为尾节点。空表是指我们允许这个表是空的：初始化一个空的表，表里面就没有元素。位置是比较关键的一个信息。线性表会支持这样一个操作，就是要返回在第 i 个位置上的元素，所以这个 i 就表示元素 \(a_i\) 在表中的位置。我们可以看这样一个例子：下面哪些数据适合用线性表去实现。

**03:47**

我们假设给你一些具体的数据。a：一个班级学生的名单，适合用线性表去实现吗？b：一篇文章里所有的单词——比如你在问 AI 的时候说了一些提示词——这个可以用线性表实现。c：一个家族的家谱，这个适合用线性表去实现吗？d：我们手机浏览器里有一些历史记录，这个适合用线性表去实现吗？每条记录有一个前驱、一个后继。

当然，拿到一个问题，它只有适合与不适合。我们有时候也可以用不适合的结构去实现，只是用起来非常不方便。比如这个 c，我们没有写答案——显然它应该用树的结构去实现。这个 d 呢，我们后面可能会举这样一个例子，实际上可以把它做成一个[听辨待核对：“瞻染”]的这样一个结构。a 和 b 当然也可以，或者说可以去用线性表实现。

### 线性表的基本操作

**06:07**

线性表有哪些基本操作？首先，必须支持创建一个线性表，创建之后初始化它是空的。清除（clear）就是把线性表从内存当中删去，删除表中所有的元素；clear 后面还有一个删除（remove），删除是指删除某一个位置的元素。所以清除就是删除所有的元素。线性表还需要支持求它的表长，也就是表里面现在到底有多少个元素；支持在第 i 个位置插入一个新的元素——把元素插在下标为 i 的这样一个位置上，后面的元素都往后移；删除则是删除下标为 i 的元素，把它的后继 \(i+1\) 一直到 \(a_{n-1}\) 都往前移动一个位置。然后是搜索。

**07:28**

搜索这个操作，我们一开始就看到这样一个例子：搜索这个元素是否在表中存在。如果它在表中，我们就返回它的位置；如果不在，按照惯例，我们一般返回 \(-1\)，或者说返回一个你能够明确知道它不在的这样一个值。线性表还支持一个操作，叫 visit：输入它的位置，然后你去访问在第 i 个位置上的元素。也就是说，我们支持这个线性表按位置来访问。

比如我们后面会讲到，在链表里删除的时候，需要把每一个节点都给它删掉；而线性表或者说这种数组一样的，就不需要进行这样的析构操作。接着是求长度 length、insert 插入、remove 删除，然后是 search：我们可以找到元素类型为 elemType 的元素，它可以是任意一个你自己定义的类。这里的 const 就是说，你不会去修改你所访问的对象的这样一个状态；如果 const 加在那里，就是说这个参数不允许被修改。当然还有遍历，它有这个析构函数，还有访问第 i 个位置上的元素，就是我们刚才讲的这个操作。

### 顺序表的存储结构

**10:55**

但它的构造函数可能我们需要回去看一下这个 PPT。线性表的顺序存储，一般情况下我们这里讲的就是数组：我们把它放在一块连续的空间当中。因为它是一个连续的存储空间，所以我们在访问的时候可以直接把第 i 个位置的地址算出来，它的物理位置和逻辑位置实际上是一致的。它那个叫顺序表，我明白了，把它叫做数组；或者说按照这里书上写的，我们就叫它顺序表。在 C++ 语言当中……

**12:13**

一块连续的存储空间，我们用一个数组去实现，它这里是一个动态数组。也就是说我们在实现的时候，向内存申请的数组长度允许超过它里面实际有多少个元素——要留有一点余地，来允许插入的这样一个操作。所以这里有一个变量叫 maxSize，就是我们当前的线性表最多可以放多少个元素；而它的 length 是实际的、在这个表里面我们插入了多少个元素，也就是元素的个数。这个顺序表我们把它叫做 SeqList。这里边 data 就是我们刚才讲的动态数组，currentLength 就是刚才讲的 length，即当前这个表里面有多少个元素；maxSize 就是最多允许它有多少个元素。因为它是一个动态的，后面在插入的时候我们会讲到 doubleSpace 这样一个操作。这里我们又写了一遍这些操作，就是我们刚才已经看过它的抽象类了。

### 顺序表操作的实现

**14:04**

那这些具体的操作我们是怎样去实现的？对于顺序表来说，因为已经存了……实际上它这个应该是 currentLength，他这里写的是 length。这个 PPT 我们还有一些要修改的地方。这个 visit(i) 就是数组或者说顺序表实现的一个优势：我们要去访问位置是 i 的元素，可以非常简单地用一个常数时间的操作，只需要返回它第 i 个元素的值就行了。而且删除表中的元素实际上也是非常简单的：我们不需要管它表里面实际有什么，因为你在写的时候就可以把它覆盖掉，我们只需要把它的 length 置为零即可。

**15:11**

这个是线性表的构造函数：我们初始化一个规模为 initSize 的线性表，把它初始化成一个空表。然后它的 length——实际上这里是 currentLength——就是说这个表里面没有元素，我们把 length 置为零。好，我们刚才讲的这三个：它的 length、visit(i)（返回第 i 个位置的元素）、以及删除表里面所有的元素，显而易见，它们都只需要常数的时间，也就是 \(O(1)\) 就可以实现。那现在我们去看 search：对于输入的一个元素 x，我们看它在顺序表里面到底存不存在，这时候就需要从零开始找——这个就是我们开始举的那个例子。

### 查找与遍历

**16:25**

我们的学号可以用顺序表表示。查找时从第一个元素开始一直往后找，直到 i 等于当前元素个数，发现没有找到，就返回 -1；否则，只要找到该元素存在，就返回它第一次出现的位置。这个 search 操作的时间复杂度是多少？考虑最坏情况：对每一个元素都比较一遍，一直到当前表长。假设表当前长度为 n，那么 search 的时间复杂度为 \(O(n)\)。遍历这个表则非常简单，直接访问每一个下标为 i 的元素即可。这里有一个小问题：对于线性表来说，遍历到底有什么用？举例来说，如果表中存的是大家期末考试的成绩，要计算均值，就需要把成绩求和，这就会用到遍历；很多操作都会用到遍历。

### 插入与扩容

**19:12**

比较重要的是插入和删除。先看插入：要在第 i 个位置插入元素 x，就要把从当前下标为 i 的元素开始，每个元素都往后移。插入时还要考虑一种情况：当前表中元素个数已经等于 max（当前表支持的最大元素个数）。这时有两种方法：一种是实现时直接报错；另一种是书上写的 double space，即扩大数组容量。也就是说，当当前表长度已经等于它能支持的最大元素个数时，需要执行 double space，把当前表扩大两倍，再把当前表拷贝到新表里。此外还需要数据移动；实现时必须从后往前移，也就是从最后一个元素开始移动，否则前面的元素会把后面的元素覆盖掉。最后在位置 i 上把将要插入的元素 x 放进去，并增加当前元素个数。

**21:58**

刚才插入时，如果当前元素个数已经等于当前最大可支持的元素个数，就进行扩大一倍的操作。其实现是：申请一个新的数组，长度是原来数组的两倍；申请一个新的连续空间，先把原来空间里存储的元素逐个复制一份，再把原来空间释放掉。可以看代码实现：先把最大能支持的元素个数加倍，然后申请新数组，再把数据拷过去，最后释放原来空间。

### 顺序表扩容：为什么按倍数而不是加常数

**24:40**

这里提出一个问题：为什么一定要把容量扩展为当前数组规模的两倍？新数组的规模能不能只加上一个固定长度？这个问题留给大家课后思考。实际上实现时肯定可以这样做，例如把 maxsize 加上 10，即再多申请十个空间，也是可以实现的。那为什么一定要在空间不够时把容量增加到原来的两倍？我们先接着往下讲。

### 删除操作

**26:09**

与插入相对应的是删除操作：remove(i) 删除当前下标为 i 的元素，并把后面的元素都往前移。删除时元素个数会减小，因此不会出现当前元素个数超过顺序表最大容量的问题，所以删除时不需要考虑插入时那种加倍扩容（double space）问题。删除只需要把数据往前移，最后把当前长度减一即可。

### 顺序表的时间与空间复杂度

**27:51**

接下来看线性表顺序实现的时间复杂度分析。空间复杂度毫无疑问与元素个数成正比，即 \(O(n)\)。时间复杂度方面，主要关注求元素个数、访问位置为 i 的元素，以及删除所有元素等操作，它们的时间复杂度都是 \(O(1)\)。顺序表比较方便的一点就是可以用常数时间快速访问位置为 i 的元素。traverse 遍历则毫无疑问是 \(O(n)\)，因为需要遍历表中所有元素；假设表中有 n 个元素，遍历就是 \(O(n)\)。构造函数用于生成这样一个表，也是常数时间 \(O(1)\)。

### 插入操作的复杂度与扩容代价

**29:25**

插入操作的时间复杂度分析需要考虑：当当前长度已经等于最大长度时，要给它加倍扩容。所以除了移动节点之外，还需要考虑 double space 这个加倍操作。移动节点在最坏情况下肯定是 \(O(n)\)。在表头插入（i = 0）需要移动 n 个元素；在最后一个位置插入则不需要移动任何元素，时间复杂度为 \(O(1)\)。不过这里好像没有讲到我刚才提到的 double space 问题，它回避了这个问题：书上只考虑了插入操作中移动节点的次数，没有考虑 double space 的次数。我们在分析时间复杂度时，需要把 double space 操作也考虑进去。书上说平均情况下是在中间插入，所以需要移动约 \(n/2\) 个元素。好，这就是顺序表的总结。

### 顺序表小结与链接存储引入

**31:34**

也就是说，插入和删除时需要把元素移动到后面或前面，所以它们已经是 \(O(n)\) 的；但顺序表有一个非常好的地方：访问第 i 个位置的元素可以用常数时间完成。因此，顺序表比较适合于不太经常插入删除、但经常需要访问的数据。马上要下课了，我们开一个头，引入线性表的链接存储结构：它的每一个节点都放在一个独立的存储单元当中，不像顺序表那样需要一整块连续的空间。下一课继续讲。

### 链式存储结构与单链表

**33:00**

节点之间还需要保存前驱和后继的关系，因此使用指针来实现。在链表（链式链接存储结构）中，存储单元在物理位置上可以相邻，也可以不相邻，即可以散落在内存的各个角落。书上主要介绍了三种链接存储结构：单链表、双链表和循环链表。单链表中每个节点只指向它后面的一个节点，只有一个指针，指向该节点的后继节点；最后一个节点没有下一个节点，因此其后继视为空。整体上，链式存储结构的插入和删除所需的时间复杂度，与顺序表相比是比较高效的，只需要常数时间。今天就先开了单链表的头，下节课继续讲。
