### 霍尔逻辑与程序验证

**08:22**

上节课讲得比较快，大家对霍尔逻辑的理解可能还不够充分。霍尔逻辑相对于前面几种逻辑，是为了程序验证而提出的。它是一种可组合的逻辑：可以把一大段程序的证明分解成对每一行程序的证明。以前用谓词逻辑证明一大段程序时，需要把程序转换成谓词逻辑，再写成命题逻辑表达式；只要谓词逻辑有足够的谓词、函数等表达手段，就可以这样做。

**09:26**

霍尔逻辑的方法是把大段程序的证明分解成对每一行程序的证明。

### 霍尔三元组

**09:46**

代价是每一行程序都要写出一个霍尔三元组。为什么是三元组而不是二元组？因为三元组多了一个前置条件。有了前置条件，就可以把下一行代码的前置条件作为上一行代码的后置条件，从而把相邻程序段的证明组合起来。这是霍尔三元组一个非常简单的概念。

**10:22**

经典的霍尔三元组写作 \(\{P\}\,C\,\{Q\}\)，其中 \(C\) 是程序，\(P\) 和 \(Q\) 是谓词逻辑公式。基于霍尔三元组定义正确性：如果在满足 \(P\) 的程序状态下执行 \(C\)，执行后的状态满足 \(Q\)，就说这个程序是正确的。有了 \(\{P\}\,C\,\{Q\}\)，就要建立一个公理系统。公理系统包含公理和推理规则两部分。

### 公理系统与可靠、完备

**11:28**

在定义公理和推理规则之前，还需要定义符号：公理系统里有哪些数学符号，以及形成规则，即如何判断一个表达式是否合法、是否 valid。合式公式就是标准的形成规则。此外还讲了公理系统的 sound 和 complete。

**12:00**

可靠（sound）是指：公理系统中能够证明的命题一定为真；完备（complete）是指：所有为真的命题都能够被证明。换句话说，可靠保证证明出来的结论是真的，完备保证所有正确的结论都能被证明。

### 证明系统的可靠性与完备性

**12:44**

对于一个证明系统，要区分它的可靠性和完备性。之前讲的霍尔逻辑、谓词逻辑、命题逻辑都是公理系统，需要明确它们要证明的命题是什么。对霍尔逻辑而言，\(\{P\}\,C\,\{Q\}\) 所要证明的命题就是程序是否正确；对于输入的程序是否正确，这就是要证明的命题。对于一个证明程序的公理系统来讲，也要讨论可靠性和完备性。

### 霍尔逻辑的可靠性

**13:45**

所谓可靠性：如果系统证明程序是正确的，那么程序一定正确；所谓完备性：如果程序是正确的，那么它一定能够在该系统中被证明。所有正确的程序都能在系统中被证明，才叫完备。今天学的霍尔逻辑也好，谓词逻辑也好，是可靠还是完备？当时问觉得可靠的举手，问觉得完备的举手。结论是可靠。对于霍尔逻辑也是一样，后面会看到，霍尔逻辑这种公理系统其实也是可靠的。

### 语言、形成规则与公理

**16:54**

我们整个这样一个语言实际上定义了一个非常简单的 language，包含它的 statement，以及整个符号系统。接下来要定义公理；这些是它的符号。除此之外还有形成规则：形成规则要说明怎样用这些符号表示一个正式的程序，也就是怎样用这些符号表示出 \(P\{C\}Q\)。中间这个由符号定义的程序由形成规则给出；而 \(P\) 和 \(Q\) 本身是谓词逻辑公式，用来表示中间这个程序的状态。

有了形成规则之后，就涉及公理。公理本身是我如何根据 \(P\) 和 \(C\) 推出 \(Q\)，或者如何根据 \(Q\) 和 \(C\) 推出 \(P\)。定义公理时，本质上要思考霍尔逻辑是什么。

如果要证明 \(P\{C\}Q\) 成立，本质上要证明两步。第一步，根据 \(P\) 和 \(C\) 找到一个 \(Q'\)，使得由 \(P\) 和 \(C\) 能推出 \(Q'\)；这就是上节课一直在学的公理。第二步，证明 \(Q'\) 能推出 \(Q\)。当然也可以反过来证：第一步根据 \(Q\) 和 \(C\) 推出 \(P'\)，第二步证明 \(P\) 能推出 \(P'\)。我们把前一种叫正向证明，后一种叫反向证明。

上节课是怎样根据 \(P\) 和 \(C\) 推出 \(Q'\) 的？\(P\) 是谓词逻辑公式，\(C\) 是用那套公式写成的程序。两者实际上不在同一个语言体系中。所以要根据 \(P\) 和 \(C\) 推出 \(Q'\)，本质上就要对 \(C\) 这种语言进行建模。

### 对程序语言建模

**20:01**

建模要处理 \(C\) 中的等号、大于号、小于号等符号。谓词逻辑和 \(C\) 之间实际上有一个语义互通：对 \(C\) 来讲，之前和今天定义的等号、大于号、小于号，其实就是谓词；加号、减号这些就是函数。谓词逻辑里也有谓词和函数。那什么没有呢？statement 没有，赋值没有，分号没有，控制结构没有，if else、while 实际上也没有。所以可以认为，\(C\) 这个 language 本身是由 statement、谓词和函数建立的。

因此我们只需要关心不同类型的 statement：在给定 \(P\) 的情况下，不同的 statement 到底能推出什么样的 \(Q'\)。所以我们其实就是对不同 statement 定义公理。

### 赋值公理

**21:46**

第一个公理是赋值语句的公理。假设已经有一个 \(P\)，然后执行 \(a=e\)，那么可以推出
\[
Q'=\exists v\,\bigl(a=e[v/a]\land P[v/a]\bigr),
\]
其中 \(v\) 表示赋值语句执行之前 \(a\) 的值；\(e[v/a]\)、\(P[v/a]\) 表示把其中的 \(a\) 替换成 \(v\)。也就是说，存在一个赋值前的值 \(v\)，使得新的 \(a\) 等于替换后的 \(e\)，并且替换后的 \(P\) 成立。

也可以根据后面往前推：假设执行 \(a=e\)，后置条件是 \(P\)。由于赋值后满足 \(P\)，赋值前 \(e\) 也应满足相应的 \(P\)，所以用 \(e\) 替换 \(P\) 中的 \(a\)，得到前置条件
\[
P[e/a].
\]

### 推理规则与顺序组合

**23:19**

有了这样的公理系统之后，自然会有一些推理规则。之前学到的推理规则，本质上就是刚才说的第一步、第二步。正常写的方式是这样：如果要推出 \(P\{C\}R\)，可以先推 \(P\{C\}Q\)，再证明 \(Q\to R\)，这是一条推理规则。也可以反过来：要证明 \(P\{C\}R\)，可以证明 \(Q\{C\}R\) 成立，并且 \(P\to Q\)。

然后开始证明不同的 statement。比如要证明 \(P\{C_1;C_2\}Q\)，也就是先执行 \(C_1\) 再执行 \(C_2\)，等价于证明 \(P\{C_1\}R\) 成立，并且 \(R\{C_2\}Q\) 成立，也就是分别证明这两个 Hoare 三元组成立。

这件事体现了霍尔逻辑的可组合性，也说明了它为什么是 program language。好，我觉得霍尔逻辑还是要夯实基础，因为我们多出两节课。

### if-else 的证明规则

**24:44**

下节课和下下节课会进一步深入讲霍尔逻辑以及具体应用；最后一节课还会讲最近 Cloud 是怎样做霍尔逻辑的。因此，霍尔逻辑的基础要打牢。

接下来看 if-else。要证明
\[\{p\}\ \text{if } b_1 \text{ then } c_1 \text{ else } c_2\ \{q\},\]
本质上要分别证明两个分支：
\[\{p \land b_1\}\ c_1\ \{q\},\qquad
\{p \land \neg b_1\}\ c_2\ \{q\}.\]
这两个分支都成立，就可以推出整个 if-else 语句成立。

### while 循环与循环不变量

**25:41**

对于 loop，直接按循环体展开也可以证明；顺序执行 \(c_1;c_2\) 又该怎么证明？

最初学习霍尔逻辑的动机，就是如何证明 while 循环，上节课也讲过。while 循环的证明比较棘手，和前面 \(c_1;c_2\)、if-else 的证明不太一样：要证明一个 while 循环，需要引入一个 \(i\)，即循环不变量。

所谓循环不变量，是指在循环体 \(c\) 执行之前和执行过程中始终成立的一个谓词；它通常描述 while 循环内部某个状态的性质。一个 while 循环可能有很多循环不变量。无论循环怎样执行，这个状态始终满足该谓词，所以称为循环不变量；当 while 循环结束时，它仍然成立。也就是说，循环前、循环过程中和循环之后，循环不变量都成立。

如果能找到这样一个循环不变量 \(i\)，那么证明
\[\{i\}\ \text{while } b_1 \text{ do } c\ \{i \land \neg b_1\}\]
就等价于证明去掉 while 循环后的那个式子，这样就把 while 循环去掉了。

### 与之前霍尔逻辑规则的区别

**28:06**

也就是要证明
\[\{i \land b_1\}\ c\ \{i\}.\]
这里和之前证明的程序不太一样：以前通常直接写
\[\{P\}C\{Q\},\]
根据 \(P\) 和 \(C\) 用规则推出某个中间后置条件 \(Q'\)，再由 \(Q' \to Q\)；或者反过来，根据 \(Q\) 和 \(C\) 推出某个中间前置条件 \(P'\)，再由 \(P \to P'\)。这是霍尔逻辑的基本做法。

但对 while 循环，如果写的是
\[\{p\}\ \text{while } b_1 \text{ do } c\ \{q\},\]
在这个规则中 \(p\) 和 \(q\) 似乎消失了，只剩下循环不变量 \(i\) 和条件 \(b_1\)。而 \(p\)、\(q\) 是人写的规约，\(i\) 是 while 循环自身的性质。因此，while 循环的处理方式与之前学到的霍尔逻辑规则不同：不是直接由给定的 \(\{p\}C\{q\}\) 按规则推出中间条件，而是要为 while 循环找到一个循环不变量。

### 循环不变量需满足的三个条件

**30:42**

对 while 循环，本质上要找到一个循环不变量，而且它需要满足三个条件。

第一，\(\{i \land b_1\}\ c\ \{i\}\)：以 \(i \land b_1\) 为前置条件执行循环体 \(c\)，仍然能推出 \(i\)。

第二，\(p \to i\)。因为如果 \(i\) 成立，后面的式子就能成立。

第三，\((i \land \neg b_1) \to q\)，即循环结束且 \(b_1\) 为假时，要能推出后置条件 \(q\)。

所以，对于 while 循环，并不是给定一个霍尔三元组 \(\{p\}\ \text{while } b_1 \text{ do } c\ \{q\}\) 后，直接根据 \(p\) 和循环体推出 \(q\)，或者反过来推出 \(p\)；而是要找到一个循环不变量 \(i\)，使上述三个条件成立。上面这些条件成立，就能推出
\[\{i\}\ \text{while } b_1 \text{ do } c\ \{i \land \neg b_1\},\]
再结合 \(p \to i\) 和 \((i \land \neg b_1) \to q\)，就得到原来的
\[\{p\}\ \text{while } b_1 \text{ do } c\ \{q\}.\]

### While 循环规则的证明结构

**32:45**

有了前面得到的式子之后，我们相当于用循环不变量自己构造了一个霍尔三元组。这个霍尔三元组本质上与用户最初写出的 \(P\,C\,Q\) 没有关系；要建立联系，还需要证明 \(P \to I\)，以及 \(I \land \neg B \to Q\)。对于 while 循环而言，证明不是前面的两步，而是三步：第一步，证明 \(\{I \land B\}\,C\,\{I\}\)；第二步，证明 \(P \to I\)；第三步，证明 \(I \land \neg B \to Q\)。具体问题是：怎样找到这样的循环不变量？

### 循环不变量

**33:29**

找循环不变量一直是非常困难的事情。考试如果涉及相关内容，会把循环不变量给出来，大家需要掌握的是如何使用它。找循环不变量过去主要靠感觉，现在也常借助大模型，它一直是很困难的事情。我们把 \(I\) 叫作循环不变量，这是 while 循环的规则。所谓循环不变量，就是循环刚执行零次时 \(I\) 成立；如果 \(I\) 在第 \(n\) 次执行后成立，那么在第 \(n+1\) 次执行后也成立。

### 例：证明 while a != 10 do a := a+1

**34:24**

看一个例子：证明
\[
\{a \le 10\}\ \texttt{while}\ a \ne 10\ \texttt{do}\ a := a+1\ \{a=10\}.
\]
这个结论看上去很容易判断为正确，但要用霍尔逻辑证明。首先找循环不变量。这个例子中循环不变量正好取前置条件，即 \(a \le 10\)；当然循环不变量不一定等于前置条件，只是本例中二者相同。找到
\[
I:\ a \le 10
\]
以后，结合循环体 \(a := a+1\)，需要证明 \(I \land a \ne 10\) 在执行循环体后仍能推出 \(I\)。

### 循环体保持不变量

**35:39**

具体地，由 \(a \le 10\) 且 \(a \ne 10\)，在这个整数情形下可以推出 \(a \le 9\)，从而 \(a+1 \le 10\)。也就是说，
\[
a \le 10 \land a \ne 10 \implies (a+1 \le 10).
\]
左边这个形式正是 \(I \land B\)：其中 \(a \ne 10\) 是循环条件 \(B\)，\(a \le 10\) 是循环不变量。这里再强调一下，\(a \le 10\) 是循环不变量，不一定是原来的前置条件；只是本例中二者恰好相同，后面会看到其他情况。于是得到霍尔三元组
\[
\{a \le 10 \land a \ne 10\}\ a := a+1\ \{a \le 10\}.
\]
这个三元组正好是 while 规则横线上方的前提 \(\{I \land B\}\,C\,\{I\}\)。

### 完成证明与总结

**36:53**

有了上面的三元组，就可以推出 while 循环的三元组：
\[
\{a \le 10\}\ \texttt{while}\ a \ne 10\ \texttt{do}\ a := a+1\ \{a \le 10 \land \neg(a \ne 10)\}. 
\]
后置条件中的 \(a \le 10\) 是循环不变量，而 \(B\) 为 false，即 \(a=10\)。因此后置条件可以写成 \(a \le 10 \land a=10\)。接下来补上另外两步：因为前置条件 \(P\) 与循环不变量 \(I\) 相同，所以 \(P \to I\) 显然成立；最后，
\[
a \le 10 \land a=10 \implies a=10,
\]
所以得到最终结论
\[
\{a \le 10\}\ \texttt{while}\ a \ne 10\ \texttt{do}\ a := a+1\ \{a=10\}.
\]
这就是用循环不变量证明程序正确的方式：要证明 \(\{P\}\,C\,\{Q\}\)，先找到循环不变量 \(I\)，证明 \(\{I \land B\}\,C\,\{I\}\)，再证明 \(P \to I\) 以及 \(I \land \neg B \to Q\)。

### 练习与考试说明

**38:21**

大家看一下这个练习，并尝试确定它的循环不变量。这个循环不变量可以取
\[
i \ge 0 \land i \le a \land a \ge 0,
\]
大家可以尝试用它来完成证明。上面给出的是具体规则；如果考试涉及这部分，一般会给一个循环不变量，再给出规则，大家按规则证明即可。

### 循环证明的局限

**41:23**

循环本身不能直接打包，因此单靠这套规则没有办法保证循环一定能够终止；这个问题我一会儿会专门讲，之前也提到过有一些 PPT 讨论这件事。这里关于前置条件的讨论属于知识点，逻辑中的这些名称都是根据含义推出来的，名字也比较好记。

### 循环体霍尔三元组的证明

**43:55**

下面先证明循环体对应的霍尔三元组。设循环不变式为 \(I: i\ge 0 \land i\le a \land a\ge 0\)，循环条件为 \(B: i<a\)，循环体为 \(C: i:=i+1\)。要证明 \(\{I\land B\}\,C\,\{I\}\)。按照霍尔逻辑的做法，从后置条件 \(I\) 往前推，处理赋值语句 \(i:=i+1\)。

**45:02**

从后往前推时，要把后置条件中的 \(i\) 替换成 \(i+1\)。于是赋值语句对应的前置条件变为 \(i+1\ge 0 \land i+1\le a \land a\ge 0\)。

**46:02**

接下来验证 \(I\land B\) 能推出上述条件。由 \(i\ge 0\) 得 \(i+1\ge 0\)；由 \(i<a\)，且 \(i,a\) 都是整数，得 \(i+1\le a\)；\(a\ge 0\) 仍由 \(I\) 直接得到。因此 \(I\land i<a\) 蕴含 \(i+1\ge 0\land i+1\le a\land a\ge 0\)。

**47:17**

有了这个蕴含关系，就可以应用 while 循环的证明规则：以 \(I\) 为前置条件，以 \(I\land\neg(i<a)\) 为后置条件。因为 \(I\) 中含有 \(i\le a\)，而 \(\neg(i<a)\) 就是 \(i\ge a\)，两者合起来推出 \(i=a\)。因此循环结束时得到 \(i=a\)，相应的霍尔三元组成立。

### 部分正确性

**48:16**

这里要特别注意：如果 while 循环本身永远退不出来，例如 `while true do skip` 这样的死循环，用霍尔逻辑仍然可能把它证明出来。原因是霍尔逻辑证明的是部分正确性（partial correctness）：它假定循环最终会退出，只说明若循环能够终止，则终止状态满足后置条件；它并不证明循环一定终止。对于本质上不终止的循环，霍尔逻辑的证明不保证停机。

### 考试范围与 partial correctness

**49:31**

如果 while 循环本身不终止，霍尔逻辑的证明并不保证它终止。回到考试：不会考“给你一个 while 循环和相应条件，让你把它证出来”这种研究性的问题。如果考这个知识点，考的是什么叫 partial correctness，或者一个正确性证明到底包含哪些内容。

### 顺序结构与 while 循环

**50:17**

## 离散数学｜第 2 节（08:50）

### 循环不变式的验证

**05:09**

好，我们继续看刚才这个例子。先明确循环不变式：\(a\ge2\)，请记下来。

接下来要证：若 \(a\ge2\) 且循环条件成立，执行 \(a:=a-1\) 后仍满足 \(a\ge2\)。根据赋值公理，把后置条件中的 \(a\) 替换成 \(a-1\)，得到 \(a-1\ge2\)。于是需要证明
\[
a\ge2\land a>2\to a-1\ge2.
\]
因为这里的变量是整数，\(a>2\) 就是 \(a\ge3\)，所以 \(a-1\ge2\) 成立。

**06:58**

有同学问，为什么这里默认变量是整数，而不考虑其他程序状态？因为在最开始构建霍尔逻辑时，我们建立的是一个很小的语言；这个语言不是 C，里面没有浮点数，只有整数。

**07:46**

现在能写成这样的形式，就可以推出上面的三元组：
\[
\{a\ge2\land a>2\}\ a:=a-1\ \{a\ge2\}.
\]
其中 \(a>2\) 是循环条件 \(B\)，\(a\ge2\) 是循环不变式；执行 \(a:=a-1\) 后，后置条件 \(a\ge2\) 成立，因此这个三元组成立。

### 循环三元组的证明

**08:05**

由前面已经得到的推理规则，可以推出循环体的三元组，并进一步得到整个 while 循环的三元组。循环不变式取 \(a\ge 2\)。当循环条件 \(a>2\) 成立时，执行 \(a:=a-1\) 后仍有 \(a\ge 2\)，所以
\[
\{a\ge 2\}\ \text{while }(a>2)\ a:=a-1\ \{a\ge 2\land a\le 2\}.
\]
循环退出时 \(a>2\) 为假，即 \(a\le 2\)；结合不变式 \(a\ge 2\)，得到后置条件 \(a\ge 2\land a\le 2\)。因此上述三元组成立。

又因为 \(a\ge 2\land a\le 2\) 可以推出 \(a\ge 1\)，所以把后置条件减弱为 \(a\ge 1\)，仍有
\[
\{a\ge 2\}\ \text{while }(a>2)\ a:=a-1\ \{a\ge 1\}.
\]
这样，关于这个 while 循环的三元组就证明完毕。

### 顺序组合与赋值公理

**09:19**

接着使用顺序执行的推理规则。先看赋值语句 \(a=b\)。若要求执行后 \(a\ge 2\)，由赋值公理，前置条件应为 \(b\ge 2\)，即
\[
\{b\ge 2\}\ a=b\ \{a\ge 2\}.
\]
把这个赋值三元组与前面的循环三元组按顺序组合，就得到
\[
\{b\ge 2\}\ a=b;\ \text{while }(a>2)\ a:=a-1\ \{a\ge 1\}.
\]
其中，\(b\ge 2\) 作为赋值语句的前置条件，经过 \(a=b\) 后得到 \(a\ge 2\)，正好可以作为 while 循环的前置条件。于是整个程序的三元组得到证明。

### 从手工证明到自动验证

**10:15**

证明结束后，回顾前面的做法：无论是证明 \({P}c{Q}\)、while 循环，还是更复杂的程序，之前都是手动证明的。我们根据前置条件 \(P\) 和程序 \(c\)，套用推理规则推出后置条件 \(Q\)。课程当然希望尽可能自动证明。

于是希望有一个自动验证器。但之前的符号执行（symbolic execution）没有办法处理循环（loop），就像猫和老鼠里的机器猫去抓老鼠，抓得很差，因为武器不对。后来提出霍尔逻辑；如果只处理一部分结构、其他都不管，是否能自动推理？换了武器之后结果就对了，说明方法和工具很重要。用霍尔逻辑自动证明的本质，是把之前学的 \({P}c{Q}\) 这一套，包括规则 \({P}c{Q'}\) 和 \(Q'\Rightarrow Q\)，自动化。

### 最强后置条件的动机

**11:59**

要证明 \({P}c{Q}\)，一般分两步：第一步证明 \({P}c{Q'}\)；第二步证明 \(Q'\Rightarrow Q\)。于是问题变成：\(Q'\) 应具有什么性质？如果谓词 \(P\) 能推出 \(Q\)，就说 \(P\) 比 \(Q\) 强（stronger），\(Q\) 比 \(P\) 弱。为了自动地从 \(P\) 和 \(c\) 推出某个 \(Q'\)，这个 \(Q'\) 必须比所有可能的合法后置条件 \(Q_1,Q_2,Q_3,\ldots\) 都强，才能保证由 \(P\) 和 \(c\) 推出 \(Q'\)，并且 \(Q'\) 能推出所有满足条件的正确性规约。因为对于同一个程序，正确性规约可以有无穷多个。

### 正确性规约不唯一

**14:32**

给定一个程序去找它的规约，本身是一个不可判定问题：不存在一个算法，对任意程序都能找到唯一的一个正确性规约。比如前置条件为 \(a=10\)，代码为 \(a:=a+1\)。后置条件可以写成 \(a=11\)，也可以写成 \(a>0\)、\(a>1\)、\(a<100\) 等，这些都是正确的；而 \(a>100\) 则不对。也就是说，同一个程序可以有无穷多种正确的后置条件。这里面最强的是 \(a=11\)，因为由 \(a=11\) 可以推出上述其他条件。因此，当计算机要自动推理程序时，需要保证从 \(P\) 和 \(c\) 推出的 \(Q'\) 是最强的那个。由此引出最强后置条件的定义：给定程序 \(c\)，并给出相应的前置条件 \(P\)，来讨论最强的后置条件 \(Q\)。

### 最强后置条件

**16:50**

给定前置条件 \(P\) 和程序 \(C\)，若 \(Q\) 满足：对所有合法的 Hoare 三元组 \(\{P\}\,C\,\{Q'\}\)，都有 \(Q\Rightarrow Q'\)，则称 \(Q\) 是 \(C\) 和 \(P\) 的最强后置条件。也就是说，最强后置条件能推出所有其他合法的后置条件。

例如，程序先执行 \(a=1\)，再执行 \(a=3\)，其最强后置条件就是 \(a=3\)。此外还可以写出 \(\exists v\,(a=v)\) 等后置条件，但它们不是最强后置条件；\(a=3\) 可以推出它们，而它们不能推出 \(a=3\)。

### 最弱前置条件

**17:40**

类似地，给定程序 \(C\) 和后置条件 \(Q\)，若 \(P'\) 满足：对所有使 \(\{P\}\,C\,\{Q\}\) 成立的前置条件 \(P\)，都有 \(P\Rightarrow P'\)，则 \(P'\) 是 \(C\) 和 \(Q\) 的最弱前置条件。它比所有可能的前置条件都弱。

最弱前置条件记作 \(\mathrm{WP}\)，即 weakest precondition。以后还会讲 \(\mathrm{WLP}\)，现在先记住 \(\mathrm{WP}\) 表示最弱前置条件。

### 例子：赋值语句的最弱前置条件

**18:35**

例如程序 \(a=a+1\)，后置条件取 \(a=3\)，那么最弱前置条件是 \(a=2\)。此外还可以写出 \(a=2\land a=4\)，以及 \(a=2\land a>1\) 等前置条件。这几个 Hoare 三元组本身都没有错，后面的规约也都是正确的，只不过这些前置条件比 \(a=2\) 更强。最弱的前置条件就是 \(a=2\)。

### 把 Hoare 三元组化为 WP 的证明

**19:47**

验证时，先假设程序员写下规约 \(\{P\}\,C\,\{Q\}\)。可以进一步把它形式化：找到一个 \(P'\)，使 \(\{P'\}\,C\,\{Q\}\) 成立，再证明 \(P\Rightarrow P'\)。这里的 \(P'\) 本质上就是 \(C\) 和 \(Q\) 的最弱前置条件。

所以实际步骤是：先求 \(C\) 和 \(Q\) 的最弱前置条件，再证明原前置条件 \(P\) 能推出这个最弱前置条件；若能做到，程序相对于该规约就是正确的。

### 不是最弱前置或最强后置会怎样

**20:47**

如果验证系统找到的 \(P'\) 不是最弱前置条件，会出现什么问题？可以把问题简化为“漏报”和“误报”两种可能；误报就是报出 bug。

如果 \(P'\) 不是最弱前置条件，那么原前置条件 \(P\) 可能推不出 \(P'\)。于是一个本来正确的程序可能无法通过验证，系统会报错，这就是误报。对后置条件 \(Q\) 也一样：如果 \(Q\) 不是最强后置条件，那么用 \(\mathrm{SP}(C,P)\Rightarrow Q\) 去验证时，也可能出现推不出来的情况，同样会把正确程序报错，仍然是误报。

因此系统的 sound 性质没有变，只是覆盖能力范围变小了：系统能证明一个程序正确，它仍然是正确的；但它不能证明的情况变多，误报范围增大。

### 用 SMT solver 检查不可满足性

**22:52**

把前面两步合成一步：证明 \(\{P\}\,C\,\{Q\}\)，本质上可以证明 \(P\Rightarrow \mathrm{WP}(C,Q)\)，或者证明 \(\mathrm{SP}(C,P)\Rightarrow Q\)。这又等价于判断相应式子的不可满足性，例如把 \(P\land\neg\mathrm{WP}(C,Q)\) 或 \(\mathrm{SP}(C,P)\land\neg Q\) 交给 SMT solver，检查它是否不可满足。

所以基本做法是：求 \(C\) 和 \(Q\) 的最弱前置条件，或者求 \(C\) 和 \(P\) 的最强后置条件，然后证明相应公式的不可满足性。证明这样的公式，当然要使用 SMT solver。

### 赋值公理给出的就是最强后置和最弱前置

**24:00**

接下来的问题是：如何找到最弱前置条件和最强后置条件？前面学过的几条公理，实际上推出来的就是最强后置条件和最弱前置条件。

以赋值语句 \(a=e\) 为例。为了得到执行后的结果，可以引入一个变量 \(v\) 表示执行前 \(a\) 的旧值：把 \(e\) 中的 \(a\) 替换成 \(v\)，同时把 \(P\) 中的 \(a\) 也替换成 \(v\)。执行 \(a=e\) 之后，\(a\) 的值应当是表达式 \(e\) 的值；而 \(e\) 中原来的 \(a\) 是旧值 \(v\)。同时，在执行这条语句之前，旧值 \(v\) 要满足 \(P\)。因此后置条件可以写成
\[
\exists v\,\bigl(P[v/a]\land a=e[v/a]\bigr).
\]
这个过程没有语义损失，所以由赋值公理得到的就是最强后置条件；反过来做替换，也能得到相应的最弱前置条件。

### 最强后置与最弱前置

**25:23**

前面由赋值公理推出来的后置条件，正是最强后置条件。这就是上节课花将近半节课重新回顾该式子的原因：这个式子本身求出来的就是最强后置条件。

同样，根据赋值公理推出来的前置条件就是最弱前置条件，因为推导过程没有语义损失：执行 \(a=e\) 后满足 \(P\)，则在执行前 \(e\) 一定满足 \(P\)。

这里之所以主要采用从后置推前置、求最弱前置条件，还因为 SMT solver 对量词没有那么友好。所以后面主要使用 WP，用后置条件推前置条件，求最弱前置条件。

### WLP 与霍尔三元组

**26:37**

严格说，当我们说最弱前置条件时，计算机里常用 WLP，是因为暂时忽略终止性问题，也就是忽略 termination。WLP 只要求：如果程序终止，则后置条件成立，不要求程序一定终止；它是相对较弱的、liberal 的条件。用 WP 和 WLP 都可以，但书写时建议记住 WLP。

对所有的程序 \(c\) 和后置条件 \(q\)，要证明霍尔三元组 \(\{p\}\,c\,\{q\}\)，只需证明 \(p \Rightarrow \mathrm{WLP}(c,q)\)，其中 \(p\) 是前提。下面把之前学过的规则用 WLP 形式表示。

### 基本语句的 WLP

**27:49**

WLP 的基本规则是：
\[
\mathrm{WLP}(\mathbf{skip},q)=q.
\]
对赋值语句 \(a=e\)，若后置条件为 \(P\)，则
\[
\mathrm{WLP}(a=e,P)=P[a/e],
\]
也就是把 \(P\) 中的 \(a\) 换成 \(e\)。

例如，程序 \(a=b+1\)、后置条件 \(a=42\)，最弱前置条件为 \(b+1=42\)。再如程序 \(a=a-b\)、后置条件 \(a>3\)，最弱前置条件为 \(a-b>3\)。

### 顺序复合

**28:51**

对顺序复合 \(c_1;c_2\)，后置条件为 \(q\) 时，
\[
\mathrm{WLP}(c_1;c_2,q)=\mathrm{WLP}(c_1,\mathrm{WLP}(c_2,q)).
\]
也就是先用 \(q\) 和 \(c_2\) 算出最弱前置条件，再把它作为 \(c_1\) 的后置条件，继续往前算。

例如程序为
\[
a=a+1;\quad b=a,
\]
后置条件为 \(a=3 \land b>0\)。先算 \(c_2\) 即 \(b=a\)：
\[
\mathrm{WLP}(b=a,\ a=3\land b>0)=a=3\land a>0.
\]
再把这个结果作为 \(c_1\) 的后置条件，算 \(a=a+1\)：
\[
\mathrm{WLP}(a=a+1,\ a=3\land a>0)
= a+1=3\land a+1>0.
\]
所以整个程序的最弱前置条件是 \(a+1=3\land a+1>0\)。

### 条件语句

**30:35**

若遇到 while 循环，要使用循环的规则；这里先看 if 语句。对
\[
\mathbf{if}\ B\ \mathbf{then}\ c_1\ \mathbf{else}\ c_2,
\]
后置条件为 \(q\) 时，要求
\[
(B \Rightarrow \mathrm{WLP}(c_1,q))\land
(\neg B \Rightarrow \mathrm{WLP}(c_2,q)).
\]
也就是分别求两个分支的最弱前置条件。

例如
\[
\mathbf{if}\ a=0\ \mathbf{then}\ b=1\ \mathbf{else}\ b=0,
\]
后置条件为 \(b=1\lor b=0\)。若 \(a=0\)，执行 \(b=1\)，分支的 WLP 为
\[
1=1\lor 1=0,
\]
这是真；若 \(a\ne 0\)，执行 \(b=0\)，分支的 WLP 为
\[
0=1\lor 0=0,
\]
这也是真。因此整个 if 语句的最弱前置条件为
\[
(a=0\Rightarrow(1=1\lor1=0))\land
(a\ne0\Rightarrow(0=1\lor0=0)),
\]
即为真。

### 练习与回顾

**32:01**

做一个简单练习：假设后置条件是 \(b>5\land a<10\)，用 WLP 的形式推出相应程序的最弱前置条件。霍尔逻辑这部分说难也不难，因为核心反反复复就是几件事：霍尔逻辑三元组，以及如何根据 \(\{P\}\,C\,\{Q\}\) 由 \(P,C\) 推 \(Q\)，或由 \(Q,C\) 反推 \(P\)。

之前讲的是由 \(P,C\) 推出 \(Q\)，此时 \(Q\) 是最强后置条件；而由 \(Q,C\) 推出 \(P\)，此时 \(P\) 是最弱前置条件。换一个写法，就是从最强后置条件和最弱前置条件的角度来思考如何推导。

### 从后置条件反推最弱前置条件

**33:29**

接下来讨论一类典型问题：给定一个程序和后置条件，要求反推出它的最弱前置条件。这一部分涉及的知识点并不多，但符号体系比较完整。

下面看一个具体例子。设后置条件为
\[
b>5 \land a<10,
\]
并给定一段包含 `if-else` 和赋值语句的程序，要求计算它的最弱前置条件。

### 倒推 if-else 结构

**35:29**

这段程序为：
```text
if (a > 2)
    b = c + 1;
else
    b = c - 1;
a = b + 2;
```
计算时采用倒着推的方式：先分别求出 `if` 和 `else` 两个分支在给定后置条件下的最弱前置条件；再结合分支条件，得到整个 `if-else` 结构的最弱前置条件；最后把这个结果作为 `a = b + 2` 的后置条件，继续反推整段程序的最弱前置条件。

### 两个分支的最弱前置条件

**37:00**

先计算 `if-else` 的两个分支。对 `b = c - 1` 这一支，把后置条件中的 \(b\) 用 \(c-1\) 替换，得到
\[
c-1>5 \land a<10.
\]
该分支对应的条件是 \(a\le2\)，即 \(a>2\) 的否定，因此这一支要求
\[
a\le2 \to (c-1>5 \land a<10).
\]
对 `b = c + 1` 这一支，把 \(b\) 用 \(c+1\) 替换，得到
\[
c+1>5 \land a<10,
\]
该分支对应的条件是 \(a>2\)，因此要求
\[
a>2 \to (c+1>5 \land a<10).
\]
把两支合起来，`if-else` 结构的最弱前置条件为
\[
(a\le2 \to (c-1>5 \land a<10))
\land
(a>2 \to (c+1>5 \land a<10)).
\]

### 代入后续赋值并得到结果

**38:00**

再把这个结果作为 `a = b + 2` 的后置条件，继续反推。将 \(a\) 替换为 \(b+2\)，得到整段程序的最弱前置条件：
\[
(b+2\le2 \to (c-1>5 \land b+2<10))
\land
(b+2>2 \to (c+1>5 \land b+2<10)).
\]
这个条件描述了：如果执行完程序后要满足后置条件 \(b>5 \land a<10\)，那么初始状态必须满足上述表达式。该表达式还可以进一步化简，这里先保留这个形式。

### while 循环与循环不变式

**39:20**

接下来看 `while` 循环。`while` 循环的最弱前置条件不能像赋值和 `if-else` 那样直接由后往前推，也无法直接得到最强后置条件。最弱前置和最强后置的初衷是让计算机自动推导，但遇到 `while` 循环时这一点做不到。

因此，使用霍尔逻辑证明带 `while` 循环的程序时，唯一能做的是手动提供循环不变式 \(I\)，然后分别证明：

1. 初始条件 \(P\) 能推出 \(I\)；
2. 循环体在 \(I\land B\) 下保持 \(I\)；
3. 循环结束时 \(I\land\neg B\) 能推出后置条件 \(Q\)。

这些证明必须分别完成。用霍尔逻辑验证程序时，其他结构大多可以自动处理，只有 `while` 循环需要手动写循环不变式。

### Dafny 中的程序验证

**40:21**

下面举一个实际的程序验证例子。Dafny 是一种带验证器的语言：写好程序后，可以直接交给验证器证明它满足规范。例如，一个方法用 `method` 声明，用 `returns` 声明返回值，用 `ensures` 写后置条件：
```text
method Example(...) returns (...)
    ensures ...
{
    ...
}
```
把这样的程序交给验证器，就可以证明它执行完后满足后置条件。若前置条件就是 `true`，那么前置条件不必显式写出；但对于包含 `while` 循环的方法，循环本身仍然需要手动给出循环不变式，验证器会依据这个不变式验证该循环。

### 循环不变量与霍尔逻辑验证

**41:30**

证明带 while 循环的程序时，需要手写循环不变量（loop invariant）。要证明这个程序，首先自己找到循环不变量；验证器会根据循环不变量求出 while 循环的前置条件和后置条件。然后再根据这个前置、后置，分别求 while 循环上方代码和下方代码的最弱前置条件与最强后置条件，并继续往后推，看能否推出所需的结果。这是实际证明中的一个例子。

真正的程序证明使用霍尔逻辑时，循环不变量必须由人手动提供。再看一个例子。

### Dafny 程序示例：数组清零

**42:21**

例如这是一个 Dafny 程序。它的前置条件要求 \(n>0\)，因为 \(n\) 实际上是数组元素的个数。程序要证明：当 \(n>0\) 时，执行后对所有的 \(k\)，只要 \(0 \le k < n\)，都有 \(A[k]=0\)。这个程序所做的，是把数组中所有 \(n\) 个元素全部初始化为零。

要证明这个程序，仍然需要手动提供循环不变量。但提供的循环不变量很可能是错的，因此验证器有可能报错。

### 验证器报错与误报

**43:26**

如果循环不变量不对，就会导致很多错误。报错的效果和前置条件、后置条件不是最弱前置条件、最强后置条件是一个道理：即使程序本身是对的，仍然可能报错，这叫误报。

因此，手动提供的循环不变量要非常精准，同时前置条件也需要比较精准，才能通过验证。真正做程序时，前置条件以及循环不变量都要熟悉并且比较精准，否则就可能导致误报。

### 命题逻辑：状态机与 SAT

**44:59**

第一块是如何把程序转换成数学表达式，第二块是如何让计算机进行求解。对于命题逻辑，我们把程序转换成命题逻辑表达式，其中的知识点是状态机：可以把程序看成一个状态，执行前假设变量为 \(x_0\)，执行后为 \(x_1\)，然后用命题逻辑建立每一个执行前的状态和执行后的状态之间的关系。程序中的变量实际上可以用 bit 表示，刚好对应命题变量，然后用 SAT 求解器进行求解。

### 谓词逻辑：符号执行与 SMT

**45:46**

对于谓词逻辑，我们讲了符号执行引擎。通过符号执行引擎，可以把一个程序转换成谓词逻辑表达式，然后用 SMT 求解器进行求解。

### 霍尔逻辑：公理系统与循环不变量

**46:01**

对于霍尔逻辑，霍尔逻辑本身是一个公理系统。要证明一个程序，实际上要把程序融入这个公理系统，也就是对程序进行建模。例如要说明 \(\{P\}\,C\,\{Q\}\) 是怎么推出来的，赋值语句、if-else 的 \(\{P\}\,C\,\{Q\}\) 是怎么推出来的，以及如何推出最弱前置条件。对于不同的运算符，要根据运算符语义定义公理。

计算机本质上就是根据公理系统的推导规则，去寻找最弱前置条件或最强后置条件。这里有一点：循环不变量需要人提供，计算机没有办法帮你生成循环不变量，它只能帮你检查循环不变量。除此之外，整个程序中有哪些不变量、哪些断言，这些最终也会被检查。

### 三个逻辑之间的关系与教学大纲

**47:06**

所以三个逻辑基本上已经结束了。每一个逻辑都分成两块，但还能看到：谓词逻辑的体系建立在命题逻辑之上。命题逻辑上加入函数和谓词，用 SMT solver 求解谓词逻辑表达式，而 SMT 建立在 SAT 之上，相当于在 SAT solver 上增加了理论求解器。类似地，霍尔逻辑的公理系统也是建立在谓词逻辑的基础上，其中 \(P\) 和 \(Q\) 是谓词逻辑公式；在这个基础上再建立一个公理系统，然后求解 \(\{P\}\,C\,\{Q\}\) 是否成立。它要证明 \(P\) 是否能推出由 \(C\) 和 \(Q\) 得到的最弱前置条件，这也会转换成表达式放到 SMT solver 中求解。

所以整套内容中，每一个逻辑都分为两块；纵向看是依赖关系，横向看也是递进关系。第一次备课时，我们花了大概半年时间，把书上所有知识点全部打碎、重新揉在一起，最后形成了这样的教学大纲。

### Lab：Mini C 符号执行

**49:36**

接下来介绍这个 lab。原本设计了一个更复杂的版本，已经设计完成，但被浩然同学以“对你们来讲太难了”为由打回，所以改成了一个更简单的版本。这个 lab 要求用符号执行引擎加 Z3 来检查：给定输入时，整个函数是 safe 还是 unsafe，还是 fail。

Mini C 本身很简单，实验文档里会给出非常具体的程序和说明。Mini C 有 bool、固定大小的数组，有 if-else 和 bounded loop；没有 unbounded loop，所有循环都是 bounded loop；函数都是非递归函数，并且有 return 和 assert。还增加了 assume 关键字，用来表示程序的前置条件。assume 不满足时系统会 halt；assert 不满足时整个系统会 crash，这就是前置和后置的区别。

符号执行引擎要做的事情是：给定一个程序，把它转换成谓词逻辑表达式，交给 SMT solver 求解，判断结果是 safe 还是 unsafe。你们需要支持 branch、bounded loop、函数和 array，可以自由使用大模型；同时需要处理 32-bit 带符号整数的运算，还要处理类型相关的问题和 runtime error，以及分支状态如何存储和管理。整体 schedule 中这些是最重要的部分。
