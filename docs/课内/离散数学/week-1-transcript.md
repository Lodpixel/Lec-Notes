### 离散数学与 coding agent

**11:27**

现在大家已经进入大模型和 coding agent 的时代。很多同学已经使用过 Codex、DeepSeek 或其他模型来写代码。编程方式正在发生变化，因此我们也要重新思考：在 coding agent 大量参与软件开发的情况下，为什么还要学习离散数学？

过去，我们通常是先分析问题、设计算法、写代码、运行测试，再根据测试结果修改程序。现在的流程往往变成：

- 人定义问题，并提供上下文；
- coding agent 读取现有代码或创建新的代码；
- agent 编写、修改并运行测试；
- 人负责审查结果，并对最终代码负责。

以前主要是“人写代码、机器执行”；现在逐渐变成“人描述目标、agent 生成代码、人审查和承担责任”。

**17:35**

coding agent 的快速发展已经改变了软件开发生态。它可以在很短时间内生成大量代码，但代码量增加并不等于软件质量提高。真正的问题是：谁来检查这些代码的设计是否正确、算法是否满足目标、实现中是否存在隐藏的错误？

以前我们学习了很多如何开发程序、设计算法和优化系统的课程，但很少有课程专门讨论如何系统地审查大模型生成的代码，以及如何自动检查程序是否满足预期。

离散数学，尤其是数理逻辑，正好提供了这类工具。我们希望把程序的正确性写成数学上可以检查的形式，再利用自动化验证工具去判断它是否成立。

**22:42**

代码规模正在以前所未有的速度增长。大模型可以生成大量代码，但如果没有人检查这些代码的设计和语义，整个软件系统就可能像一座结构不稳的建筑。

测试能够发现某些 bug，却不能保证不存在 bug。一个测试用例通过，只能说明程序在这个输入上表现正确，不能说明程序对所有输入都正确。

因此，我们需要从“测试程序”进一步走向“证明程序”。这也是本课程和 coding agent 的核心联系：未来的瓶颈可能不再是写代码，而是定义正确性、审查代码和验证代码。

**30:08**

程序正确性的讨论很早就出现了。程序员会使用 assertion，在程序运行到某个位置时检查一个条件是否成立。后来，随着软件规模变大，研究者开始发展形式化验证理论，例如霍尔逻辑、时序逻辑等。

这些理论本身并没有失效，但传统方法往往需要人手动完成大量推理，而 coding agent 生成代码的速度远远超过了人工审查的速度。因此，我们需要把数学基础和自动化工具结合起来，让计算机协助完成严格验证。

大模型的基础更多来自连续数学，而程序的结构、状态和正确性验证则大量依赖离散数学。要让 AI 辅助编程形成闭环，需要连续数学和离散数学共同发挥作用。

### 什么是离散数学

**10:38**

离散数学首先是一门数学。它研究的对象通常是彼此分离、可以逐个讨论的离散对象。对象集合可以是有限的，也可以是可数无限的；除了研究对象本身，还要研究对象之间的关系，以及对象状态如何按照规则发生变化。

这正是离散数学适合描述计算机的原因。温度、时间和距离常常用连续量表示，而程序状态、变量取值、状态机中的状态以及程序执行的步骤，都可以看作离散对象。

例如，一个程序可以有若干种状态；执行一条指令后，从一个状态转移到另一个状态。我们可以用集合表示状态，用关系表示状态之间的转移，再用规则描述状态如何变化。

离散数学中常见的分支包括数论、集合论、逻辑和图论。

- 数论研究整数及其运算和关系；
- 集合论研究对象的集合、子集、集合运算和映射；
- 逻辑研究命题的真假以及命题之间的推理关系；
- 图论用于描述程序结构、网络和状态之间的连接。

这些概念在程序设计中经常出现。例如，程序能够访问哪些文件、接受哪些输入、有哪些可能的状态，实际上都可以用集合来抽象。

### 从逻辑门到程序验证

**19:02**

在数字电路中，信号通常用高电平和低电平表示，可以抽象为 1 和 0。在逻辑中，我们把它们对应为 true 和 false。

常见的逻辑门可以对应命题联结词：

- OR 门对应“或”；
- NOT 门对应“非”；
- AND 门对应“与”。

电路设计完成后，通常还需要优化：用更少的门、更小的面积或更低的成本实现相同功能。芯片制造成本很高，因此不能只凭几个测试输入判断优化前后的电路等价，而需要用形式化方法证明它们对所有输入都有相同的输出。

例如，电路等价问题可以转化为逻辑表达式的等价问题。把高电平映射为 true、低电平映射为 false 后，电路验证就变成了：两个命题表达式是否对所有输入都有相同的真值。

### 从测试走向规约

**24:22**

再看一个程序例子：判断整数 n 是否是 2 的幂。

一种直接的算法是逐位检查 n 的二进制表示，统计其中为 1 的 bit 数量。若只有一个 bit 为 1，则 n 是 2 的幂。另一种更简洁的写法利用性质：

~~~text
n > 0 且 (n & (n - 1)) = 0
~~~

这段代码更短、性能也可能更好，但对第一次阅读的人来说不一定更容易理解。代码越短，不代表证明它正确越容易。

我们当然可以生成很多 test case，例如测试 0、1、2、4、8 以及一些不是 2 的幂的数。但无论测试多少组有限输入，都不能穷尽所有整数，也不能由此保证程序对所有输入都正确。

**30:43**

因此，验证程序之前必须先明确“正确”是什么意思。我们需要先给程序写出一个形式化的正确性描述，这个描述叫作 specification，中文通常译为“规约”。

以计算 1 到 n 的和为例。程序的目标是返回：

~~~text
1 + 2 + ... + n = n(n + 1) / 2
~~~

如果输入要求为自然数，可以把前置条件写成：

~~~text
n ≥ 0
~~~

把程序执行后的要求写成后置条件：

~~~text
result = n(n + 1) / 2
~~~

规约通常包含两个部分：

- 前置条件（precondition）：函数执行前输入或状态必须满足的条件；
- 后置条件（postcondition）：如果前置条件成立，函数执行结束后必须满足的条件。

程序验证的目标，就是证明：当输入满足前置条件时，程序的执行一定能推出后置条件。

**38:41**

所以，程序验证大致分成两步：

1. 把程序的正确性写成规约；
2. 把程序和规约转换成数学逻辑表达式，再检查这个表达式是否成立。

命题逻辑是第一步基础工具。之后还会学习更强的谓词逻辑，以表达变量、函数和量词。计算机负责求解这些逻辑表达式的工具叫 solver；我们还会讨论如何使用 agent 优化 solver。

### 自动化验证的边界

**42:09**

自动化验证并不能解决所有问题。对于带有复杂循环的程序，不存在一个算法能够对所有程序都自动完成验证。这类问题在理论上可能是不可判定的。

因此，实际验证往往需要自动化和人工结合：自动化工具负责处理可判定、结构清晰的部分，人负责提供循环不变量、辅助引理或公理系统。课程后面的实验会涉及自动化验证和半自动化验证。

本课程会安排多个 lab。大家会得到一定的模型和 token 额度，在限定条件下使用 agent 完成实验，并观察 agent 如何生成、修改和验证程序。实验评价的重点是理解验证过程，而不只是把测试用例跑通。

### 从数学证明到程序证明

**08:33**

前面我们讨论了离散数学和程序验证。现在开始讲命题逻辑。数理逻辑要处理的核心问题是：给定一个程序，以及这个程序的正确性规约，如何用数学逻辑表示它，并让计算机自动检查这个证明。

先说 proof。证明是一种论证：我们依据已经接受的事实、定义和推理规则，说明为什么某个结论成立。

数学证明，就是使用数学语言和数学规则，证明某个数学陈述成立。程序证明也遵循同样的思想，只是被证明的结论变成了“程序满足某个正确性定义”。

因此，程序验证并不是直接问“这段代码看起来对不对”，而是先明确：

1. 程序要实现什么；
2. 什么条件下运行；
3. 执行结束后必须满足什么性质；
4. 如何根据规则证明程序确实满足这些性质。

### Lean 与形式化证明

**15:52**

近年来，大模型经常与 Lean 等形式化证明工具结合使用。Lean 是一种形式化证明语言和证明检查器。你可以把数学理论、定义、定理和证明写成 Lean 能理解的形式；Lean 会检查证明中的每一步是否符合规则。

例如，要证明自然数加法满足交换律，可以写出“a + b = b + a”，并依据自然数的定义、递归规则和已有引理进行证明。Lean 的价值不在于替你理解问题，而在于对形式化后的证明提供严格反馈：某一步不成立，就会明确指出。

这对 coding agent 很重要。大模型可以生成证明草稿，但如果没有可靠的检查器，草稿是否正确仍然需要人工判断。形式化工具能够提供机器可检查的反馈，帮助 agent 继续修正证明。

### 直接证明：偶数的平方仍为偶数

**22:54**

考虑一个简单命题：

> 如果 n 是偶数，那么 n² 也是偶数。

先给出定义。整数 n 要么是偶数，要么是奇数；偶数可以写成 2k，奇数可以写成 2k + 1。这里还隐含了两个基本事实：每个整数至少属于这两类中的一类，并且不可能同时既是偶数又是奇数。

证明如下。假设 n 是偶数，那么存在整数 k，使得 n = 2k。因此：

~~~text
n² = (2k)²
   = 4k²
   = 2(2k²)
~~~

所以 n² 可以写成 2 乘以一个整数，按照偶数的定义，n² 是偶数。证明结束。

这个例子展示了直接证明的基本结构：

1. 明确目标；
2. 引入定义；
3. 假设前提成立；
4. 根据定义进行代数推导；
5. 得到目标结论。

对人来说，“整数要么奇要么偶”似乎是常识；但对计算机来说，定义和假设必须明确写出。形式化证明要求我们把所有推理依据都表达出来。

### 枚举证明：二皇后问题

**31:58**

再看一个枚举证明。n 皇后问题是在 n×n 的棋盘上放置 n 个皇后，使任意两个皇后都不在同一行、同一列或同一条对角线上。

当 n = 2 时，问题变成：能否在 2×2 棋盘上放置两个互不攻击的皇后？

棋盘上共有 4 个位置，选择两个位置一共有：

~~~text
C(4, 2) = 6
~~~

种情况。逐一检查这 6 种摆法，可以发现任意两个位置都会共享一行、共享一列或共享一条对角线。因此，2 皇后问题无解。

这种证明方法叫作枚举证明或分类讨论。形式化写法可以把所有位置编号，再逐一讨论每一对位置。Lean 或其他工具也可以帮助我们把这些有限情况形式化并检查。

### 数学归纳法：前 n 个整数之和

**36:59**

考虑另一个熟悉的结论：

~~~text
1 + 2 + ... + n = n(n + 1) / 2
~~~

可以使用数学归纳法证明。

第一步是证明基础情形 n = 1 成立：

~~~text
1 = 1(1 + 1) / 2
~~~

第二步是假设公式对 n = k 成立，即：

~~~text
1 + 2 + ... + k = k(k + 1) / 2
~~~

然后证明它对 k + 1 也成立：

~~~text
1 + 2 + ... + k + (k + 1)
= k(k + 1) / 2 + (k + 1)
= (k + 1)(k + 2) / 2
~~~

基础情形成立，且“对 k 成立能够推出对 k + 1 成立”，所以公式对所有正整数 n 成立。

### 为什么要学习证明

**39:38**

前面三个例子分别展示了直接证明、枚举证明和归纳证明。大模型在这些问题上表现较好，原因是问题定义明确、目标清晰，而且生成的结果可以交给形式化工具检查。

这也说明了大模型能力的边界：它擅长在问题已经被准确描述、结果又能够被验证时寻找解答；但它不擅长替我们定义一个新的问题，或者为一个程序自动确定正确的规约。

如果程序本身存在 bug，那么仅仅让大模型根据这个程序生成“正确性定义”可能会把错误也一起合理化。软件工程师需要做的，不只是快速求解问题，还包括定义问题、定义正确性、选择合适的验证方式。

### 命题与程序正确性

**43:23**

命题是一个断言或陈述，它必须能够确定地判断为 true 或 false，并且不能同时为 true 和 false。

例如：

- “2 + 2 = 4”是命题；
- “如果 n 是偶数，那么 n² 是偶数”是命题；
- “n > 1”单独看不是命题，因为 n 没有被具体指定，也没有量词；
- 疑问句、感叹句和单纯的拟声词通常不是命题。

回到程序验证：我们先给程序规定一个正确性定义，这个定义本身必须是一个命题。然后把程序的行为转换为数学表达式，最后检查“程序是否满足这个规约”这一命题为真还是为假。

这就是后面命题逻辑要完成的事情：用明确、没有二义性的形式表达程序的正确性，再让计算机帮助我们推理。

## 2026 年 9 月 18 日｜第 2 节回放

### 命题逻辑的基本对象

**05:16**

前面我们从数学证明引入命题，又把程序的正确性规约看成命题。整个逻辑关系可以概括为：

1. 先给定程序；
2. 定义程序应当满足的正确性规约；
3. 把程序行为转换成逻辑表达式；
4. 证明程序满足这个规约。

现在正式回答：什么是命题？

命题是一个有确定真值的陈述。它要么为 true，要么为 false，不可能同时为真或同时为假。注意，命题为假并不意味着它不是命题；只要它的真假可以确定，它仍然是命题。

### 命题逻辑与命题变量

**08:56**

命题逻辑是在命题概念基础上建立的数学系统，用来推理命题的真值，以及多个命题之间的关系。

命题逻辑的表达式主要包含两类基本元素：

- 命题变量：用大写字母 p、q、r 等表示简单命题；
- 命题联结词：把一个或多个命题连接成更复杂的表达式。

例如，令 p 表示“Tom 是一只猫”，q 表示“Jerry 是一只老鼠”。p 和 q 都是原子命题或简单命题；如果写成“Tom 是一只猫，并且 Jerry 是一只老鼠”，则它是由 p、q 和联结词“且”组成的复合命题。

每个命题变量都有两个可能的真值：true 和 false。

### 否定、合取与析取

**13:41**

第一个联结词是否定，记作 ¬p。它把 p 的真值反转：

| p | ¬p |
|---|---|
| true | false |
| false | true |

第二个联结词是合取，记作 p ∧ q，表示“p 且 q”。只有当 p 和 q 都为 true 时，p ∧ q 才为 true。

第三个联结词是析取，记作 p ∨ q，表示“p 或 q”。只要 p、q 中至少有一个为 true，p ∨ q 就为 true。这里的“或”是通常的逻辑或，不排斥两者同时成立。

合取和析取都满足交换律：

~~~text
p ∧ q 与 q ∧ p 的真值相同；
p ∨ q 与 q ∨ p 的真值相同。
~~~

证明它们满足交换律的直接方法是列真值表。p、q 只有四种取值组合；逐行比较两个表达式的结果即可。

### 蕴含

**19:13**

蕴含词记作 p → q，读作“如果 p，那么 q”。它想表达：在 p 成立的情况下，q 也必须成立。

蕴含的真值表如下：

| p | q | p → q |
|---|---|---|
| true | true | true |
| true | false | false |
| false | true | true |
| false | false | true |

蕴含只有一种情况为假：前件 p 为真，而后件 q 为假。也就是说，真正违反“如果 p，那么 q”的，是 p 确实发生了，但 q 没有发生。

当前件 p 为假时，p → q 在命题逻辑的定义下为真，无论 q 是真还是假。这一点比较反直觉，但必须记住：逻辑蕴含不是日常语言中简单的因果关系，而是由真值表定义的联结词。

例如，“如果太阳从西边升起，那么鱼会在天上唱歌”在形式逻辑中为真，因为它的前件为假。这个例子不是在讨论现实因果，而是帮助我们理解蕴含的真值定义。

### 双条件

**23:01**

双条件词记作 p ↔ q，表示“p 当且仅当 q”或“p 与 q 等价”。它在 p、q 真值相同的时候为 true，在真值不同时为 false。

| p | q | p ↔ q |
|---|---|---|
| true | true | true |
| true | false | false |
| false | true | false |
| false | false | true |

双条件可以表示为两个方向的蕴含同时成立：

~~~text
p ↔ q  等价于  (p → q) ∧ (q → p)
~~~

证明两个表达式等价的一种直接方法，也是列出它们的真值表，逐行比较结果。

### 合式公式：命题逻辑的语法

**28:41**

到目前为止，我们讨论的是联结词的语义，即表达式在不同输入真值下到底是真还是假。接下来需要说明哪些字符串本身是合法的命题逻辑表达式，这属于语法问题。

我们把合法的命题逻辑表达式称为合式公式（well-formed formula，简称 WFF）。合式公式可以递归定义：

1. 每个原子命题都是合式公式；
2. 如果 A、B 都是合式公式，那么 ¬A、A ∧ B、A ∨ B、A → B、A ↔ B 也都是合式公式；
3. 除此之外的形式都不是合式公式。

这个定义允许我们构造任意复杂的表达式。例如，A 可以本身是 p ∨ q，B 可以是 r → s，于是 A ∧ B 仍然是合式公式。

语义回答“这个表达式在某组真值下是真是假”；语法回答“这个表达式是否按规则构造出来”。命题逻辑需要同时具备这两部分。

### 为什么需要研究完备性

**34:49**

我们目前介绍了否定、合取、析取、蕴含和双条件。问题是：这些联结词是否足够？能不能用它们表示所有可能的命题逻辑函数？

例如，异或表示 p、q 真值不同时为 true，相同时为 false。它可以由现有联结词表示：

~~~text
p ⊕ q  等价于  (p ∧ ¬q) ∨ (¬p ∧ q)
~~~

因此，异或不一定要作为新的基本联结词加入系统。

如果一组联结词能够把任意命题逻辑表达式改写成只使用这组联结词的等价表达式，就称这组联结词是完备的。完备性意味着：这套基本工具足以表达整个布尔函数空间，不需要不断增加新的基本运算。

### 用真值表构造表达式

**40:33**

设 g 是一个有 n 个命题变量的布尔函数。它的输入是 n 个真值，输出是一个真值。我们希望证明：对于任意这样的 g，都能构造一个与它等价的合式公式。

先看 n = 2 的情况。p、q 有 4 种输入组合；每一行的输出都可以独立取 true 或 false，因此一共存在：

~~~text
2^4 = 16
~~~

个不同的二元布尔函数。

对真值表中输出为 true 的每一行，我们构造一个“最小项”：

- p 为 true，就写 p；
- p 为 false，就写 ¬p；
- q 为 true，就写 q；
- q 为 false，就写 ¬q；
- 这一行的条件用 ∧ 连接。

例如，若某一行是 p = false、q = false，那么对应的条件就是：

~~~text
¬p ∧ ¬q
~~~

如果真值表中有多行输出为 true，就把这些行对应的最小项用 ∨ 连接。这样得到的表达式，恰好在这些行上为 true，在其他行上为 false，因此与原来的布尔函数等价。

这种“先按行构造，再用或连接”的方法，就是由真值表构造析取范式的基本思路。输出为 false 的情况也可以用类似方法处理，或者通过整体取反得到。

**50:27**

完备性的证明会继续把二元情形推广到任意 n。核心思想始终不变：每一个真值表都可以按照输出为真的行构造出一个等价的合式公式。

到这里，第一周的命题逻辑基础已经建立起来了：

- 命题有确定的真值；
- 命题变量表示原子命题；
- 命题联结词用于组合命题；
- 真值表描述语义；
- 合式公式描述语法；
- 完备性说明一组联结词是否足以表达所有布尔函数。

后续课程会在这些基础上继续讨论等价变换、自动求解，以及如何把程序转换成命题逻辑公式并验证其正确性。
