### 命题逻辑第一部分回顾

**06:36**

我们之前整个命题逻辑讲的是什么？先讲了命题，然后讲了最基本的五个联结词；用联结词把命题连接起来，命题之间可以是等价的；然后讲了怎么化简，把一些表达式化成合式公式。现在把第一部分串一下，因为这节课马上开始命题逻辑的第二部分。

先看什么是命题：命题是一个能够确定判断 true 或 false 的陈述句。基于这个简单概念，我们构建了一个数学系统，也就是命题逻辑。命题逻辑的数学系统里包含什么？包含命题变量。有了数学系统、有了命题变量之后，它们之间的关系怎么表示？用命题联结词。我们选择的是哪五个？用命题联结词把命题变量连接起来。

### 回顾：语义、真值表与合式公式

**08:04**

命题逻辑表达式的含义叫语义，语义用真值表来表示。一个命题联结词只能连接一个或两个命题变元；如果要写很长的命题表达式，就需要规定怎样写才是合法的，这就是合式公式。合式公式定义了什么形式的命题表达式是合法的。写完合式公式之后，我们接着讲为什么定义这五个联结词，而不是四个或三个。

### 联结词的完备性与方便性

**08:42**

这五个联结词最重要的性质是完备性。完备性需要五个吗？不需要：只需要其中两个，例如否定词与合取，或者否定词与析取；上次作业题里，否定词与蕴含其实也可以。它们都是完备的。那为什么选这五个？是为了方便。学会这些之后，我们就有能力把之前的二皇后问题表示成什么？

### 二皇后问题与真值表求值

**09:19**

把它用数理逻辑表达式表示出来，但表达式会非常复杂。证明二皇后问题无解，本质上就是证明对应的命题逻辑表达式恒等于 false。那怎样证明它恒等于 false？最简单的方法是列真值表。真值表的问题是很麻烦：对命题表达式求一个真值，真值表的行数是 \(2^n\)，其中 \(n\) 是命题变元的数目；而每一行的计算量又取决于整个命题中联结词的数目。所以它会很复杂。

### 用等价公式化简

**10:06**

因此我们就想办法简化。简化要用到等值公式：有很多等值规则，比如德摩根律、交换律、结合律等等。这些规则可以把一个命题表达式换成另一个命题表达式，换着换着，最后通过化简，并根据定义好的计算先后顺序，把整个命题逻辑表达式简化。化简到最后可能得到 false，等于 false。上节课最后还举了一个 matching problem：有三个小卡通人物抢两种食物，这肯定是无解的。

### 新的 matching problem：三种食物与三个人

**12:18**

现在有三个卡通人物：Tom、Jerry 和小不点，尝试分配三种不同的食物：鸡肉、奶酪和牛奶。这次分配相对合理一些：Tom 想吃鸡肉或者喝牛奶；Jerry 想吃鸡肉或者吃奶酪；小不点太小了，只能喝牛奶。问题是我是否能找到一种分配方式，自动找到一种分配方式，使得他们彼此没有冲突。

### 形式化：true/false 是否够用

**13:00**

不会两个人抢同一种食物。首先尝试把它形式化为一个非常简单的命题逻辑表达式。这里有一个问题：现在有三种食物，用 true/false 够不够？如果只有前两种食物，要么选 A、要么选 B，真值取值空间只有两个，没有任何问题。现在有三种食物怎么办？看这个问题，虽然有三种食物，但每个人只有两个选择，是二选一，所以 true/false 还是够的。对这个问题来讲，true/false 就够。因此可以定义：\(P_1\) 为 true 表示 Tom 吃鸡肉，false 表示喝牛奶；\(P_2\) 为 true 表示 Jerry 吃鸡肉，false 表示吃奶酪；\(P_3\) 表示小不点喝牛奶。

### 构建命题逻辑表达式

**13:58**

他们不能共享同一种食物，所以不可能都为 true。于是构建这样一个逻辑表达式：小不点只能喝牛奶，所以有 \(P_3\)；\(P_1\) 和 \(P_2\) 不能同时吃鸡肉，即 \(\neg(P_1 \land P_2)\)；\(P_1\) 和 \(P_3\) 不能同时表示喝牛奶，也就是 \(\neg(\neg P_1 \land P_3)\)。因此

\[
\Phi = P_3 \land \neg(P_1 \land P_2) \land \neg(\neg P_1 \land P_3)
\]

此外，对 Tom 来说要么吃鸡肉、要么喝牛奶，对 Jerry 来说要么吃鸡肉、要么吃奶酪；这些条件实际上是永真式，跟上次一样省略掉了。因为他要么 true 要么 false，这是基本的表示。然后要做的事情就是对这个表达式进行求解。

### 化简并求解

**15:14**

化简之后得到

\[
P_3 \land P_1 \land (\neg P_1 \lor \neg P_2)
\]

进一步简化，把括号打开，会出现 \(P_1 \land \neg P_1\)，这个合取项就没有了，于是变成

\[
P_3 \land P_1 \land \neg P_2
\]

对于这样的求解方式，如果要找到 matching 的一个 solution，使这个表达式为 true，就意味着可以给每个卡通人物分配一种食物。这个解是：\(P_3\) 为 true，\(P_1\) 为 true，\(P_2\) 为 false。

### 从 matching problem 到可满足性

**16:07**

对于 matching problem，一种分配是 \(P_1\) 吃鸡肉，\(P_2\) 吃奶酪，\(P_3\) 喝牛奶。上面这些就是上一课所学的知识。可以看到，它和上一个 matching problem 的区别是：上一个 matching problem 尝试证明那个式子无解，它永远为 false，最后化简得到 false；而这个式子本质上是要尝试找到一组真值，为每个命题变元找到一组真值，使得上面的命题逻辑表达式为 true。那么这种问题叫什么？

### 可满足性的定义

**16:57**

这种问题叫做可满足性。什么叫可满足性？首先定义：如果一个命题逻辑表达式在某一种解释（interpretation）下为真，就认为它是可满足的。也就是说，式子中存在一组命题变元的赋值，使得最终这个命题逻辑表达式的真值为真，那么就认为它是可满足的。

### 永真、矛盾与可满足的关系

**17:40**

上节课结束的时候，我们学过永真式、矛盾式和可满足，它们之间的关系是什么？关键是：

- 如果 \(P\) 是永真式，那么等价于 \(\neg P\) 是矛盾式；
- 如果 \(P\) 是可满足的，那么等价于 \(\neg P\) 不是永真式；
- 如果 \(P\) 是不可满足的，那么等价于 \(P\) 是矛盾式。

大家想一下是不是这样。如果 \(P\) 是永真式，表示对式子中的任意命题变元赋任何一个值，这个式子都是 true，那么 \(\neg P\) 肯定就是矛盾式。如果 \(P\) 是可满足的，就说明存在一组解，存在一组赋值，使得它的命题逻辑表达式为 true；那么 \(\neg P\) 一定会存在一组赋值使它为 false，所以 \(\neg P\) 一定不是永真式。同时，如果一个式子不可满足，就意味着不存在一个解释可以使得它为 true，那么它就是矛盾式。所以有两个关系比较重要：第一，如果 \(P\) 是永真式，那么 \(\neg P\) 是矛盾式；第二，\(P\) 不可满足等价于 \(P\) 是矛盾式。所以有的时候，我们要证明一个 \(P\) 是永真式，会去证明 \(\neg P\) 是不可满足的。后面我们会讲为什么可以这样做。好，大家看一下。

### 判断永真式、可满足式与矛盾式

**19:22**

大家快速看一下，给大家一点时间：哪些是永真式，哪些是可满足式，哪些是矛盾式。第一个是什么？那它是永真吗？不是永真，对吧？第一个是可满足，不是永真。第二个呢？第二个是矛盾式。第二个为什么是矛盾？我可以把它展开，然后列真值表。还有另外一种方式：如果让这个式子为 true，就意味着三个括号必须都是 true。那也就是如果先让它为 true，\(A\) 必须等于 \(B\)，对吧？那么要么它同为真，要么同为假。同为真时它是 false，同为假时它也是 false。OK，下一个呢？\(P \rightarrow P\) 嘛，对吧？永真，是不是？再下一个呢？\(A\) 成立，且 \(A \rightarrow B\) 成立，能推出 \(B\) 成立。很好。这里有一点：我要证明它，也可以证明这个式子是不可满足的。其实它们之间是有一个关系。那接下来的一个问题是：

### 用程序求解 matching problem

**22:45**

刚刚那个 matching problem，大家看到，对吧？假设我能把这个式子写出来，我们刚刚用的是什么？用的是之前各种等值规则，最后推出来。等值规则再加上算法，最后推出 \(P_1\)、\(P_3\)、\(P_2\) 之间的关系。那我们先用计算机，看能不能做这件事情。给大家展示一个程序，稍等我切一下 PPT。这就是刚才那个 matching problem，我们把它写成一个程序。

### Python 与 SymPy 定义命题变元

**23:35**

其实这是大家熟悉的 Python 程序，但是好像又没那么熟悉，因为这里用 Python 写的是命题逻辑表达式，后面能看到。这个表达式具体是：首先我引入了一个叫 SymPy 的包。SymPy 是专门用来做命题逻辑表达式的一个 Python 包。然后我定义三个命题变元 \(P_1\)、\(P_2\)、\(P_3\)，用 symbols 表示它们是三个命题变元。接着我要 check 一件什么事情呢？要 check \(P_3 \land \neg P_1\)。

### 用程序检查可满足性

**24:14**

回到 matching problem 的程序。程序里首先定义三个命题变元 \(P_1,P_2,P_3\)，然后把前面 matching problem 中的约束逐条写成命题逻辑表达式，例如小不点的条件、Tom 和 Jerry 不能同时吃鸡肉、Tom 和小不点不能同时喝牛奶等。这里用到的是 SymPy 中做命题逻辑表达式的包。把表达式交给可满足性函数后，它会返回一个模型：如果模型中有值，就说明这个式子是可满足的，可以打印出满足它的赋值；否则就是不可满足的。

也可以直接让大模型去猜可满足性，但它不保证猜出的数值一定正确。大模型每次可能给出不同答案，无法保证结论一定对；这种问题本身属于离散推理，和连续数据的问题不同。

### 可满足性检查的第一步：合式公式

**26:01**

回到刚才的程序。我们定义命题变元，然后输入一个命题逻辑表达式；它本质上应该是一个合式公式。后面会讲可满足性到底怎么实现。对于任意一个函数，可满足性函数大致逻辑是：写一个函数，输入公式，要求解它。它第一步会检查输入是否是一个有效的 formula，也就是 valid formula。这里快速回顾一下合式公式的定义：每个简单命题 \(P,Q\) 都是合式公式；如果 \(A,B\) 是合式公式，那么 \(\neg A\)、\(A\land B\)、\(A\lor B\)、\(A\rightarrow B\)、\(A\leftrightarrow B\) 等也都是合式公式；其他情况下不是。这是一个递归定义。因此可以写一个简单的递归函数来检查一个式子是否为合式公式：先检查它的基本元素，再递归检查各个子表达式。

### 用递归和语法树检查合式公式

**27:58**

现在假设在课上布置一个作业或 quiz，要求大家写一个伪代码来 check 是否为合式公式。具体可以举一个递归方式的例子；这件事其实没有那么简单，这里先举一个简化例子。合式公式里一定有左括号和右括号。首先可以把合式公式转化成一棵树，根节点就是整个命题逻辑表达式，然后一点点往下拆。

如果所有叶子节点全都是命题变元，就返回 true，表示它是正常形式；否则选择一个叶子节点，这个叶节点是一个命题逻辑表达式，同时它不是一个命题变元。举个例子：现在树里面只有一个根节点，这个根节点也是叶节点，节点里面是一个命题逻辑表达式，它不是命题变元。这时就要看这个表达式是否包含左括号和右括号。这里是简化版本：假设每一个 operator（每个逻辑联结词）左边和右边连接完之后都会用括号保护起来。把任何一个命题逻辑表达式转换成带括号版本其实比较简单，就是把括号插进去。基于这个假设，左括号和右括号应该是成对的。

### 递归规则与示例

**30:18**

如果表达式一开始没有左括号，就 return false；如果没有右括号，也 return false，因为它破坏了之前的假设。假设逻辑联结词 \(A\land B\)、\(A\lor B\)、\(\neg A\)、\(\neg B\) 等都有括号保护好。如果命题逻辑表达式是 \(\neg Q\)，就会增加一个叶节点 \(Q\)，相当于把非号和括号去掉。如果是 \(A\land B\)、\(A\lor B\)、\(A\leftrightarrow B\) 等形式，就给这个树的一个节点增加两个子节点，左节点和右节点分别是 \(A\) 和 \(B\)。看右边这个式子，它刚开始时有左括号也有右括号，符合第五步。

### 示例：语法树展开与合法性判断

**31:16**

对于形如 \(A\lor B\) 的式子，设 \(A\) 是 \(\neg(P\lor Q)\)，\(B\) 是 \(R\)，所以会增加两个叶节点 \(\neg(P\lor Q)\) 和 \(R\)。接着看 \(\neg(P\lor Q)\) 符合第几个规则：它符合第四个规则，也就是 \(\neg A\) 的形式，这时里面的 \(P\lor Q\) 就是它的子公式；而 \(P\lor Q\) 又符合第五个规则，于是拆成 \(P\) 和 \(Q\)。按照这个算法对命题逻辑表达式画出语法树，如果所有叶节点都是 \(P,Q,R\) 三个命题变元，就说明它符合第一条规则，返回 true。对于另一个式子，它明显不是一个合法的合式公式。

### 合式公式检查与可满足性求解

**32:29**

接着用前面的算法检查一个式子：处理过程中发现它不符合规则四或规则五，最后走到第六步返回 false。这个式子也是错的，因为左右括号的数目不满足要求。

现在第一步要做的事情很简单：用上节课学过的合式公式概念检查一个式子是否合法。这也是前面展示的 Python 中 satisfiable 函数所做的第一件事。第二件事是求解：给定一个式子，如何判断它是否可满足？

最直接的方法是列真值表，但上节课已经讲过，对于给定 \(n\) 个命题变元的式子，真值表有 \(2^n\) 行；每一行的计算复杂度还由命题联结词的数目决定。于是引出新的问题。

### SAT 问题与 NP、NPC

**34:03**

如何让计算机或图灵机求解一个式子的可满足性问题？这个问题称为 SAT 问题。在计算机科学中，可满足性问题就是自动判定一个表达式是否存在一种解释，使其为真。SAT 问题是计算机领域第一个被证明为 NPC 的问题。老师问大家是否听过 NP、NPC 问题以及 NP 是否等于 P，并请听过 NP 问题的同学举手、请一位同学回答。

### NP 与 NPC 的含义

**35:53**

有同学回答：NP 应该就是非确定性多项式时间。还有 NPC，它是 NP 问题里面最复杂的一类。

所谓 NP，是说问题在非确定性的意义下可以在多项式时间内求出解，同时可以在多项式时间内验证一个解是对还是错。比如一个非常复杂的式子，求一个解的复杂度很高，不一定能在多项式时间内求解；但如果已经知道一个解，把它代入计算，则比较简单。SAT 也是一样：找到一个解并判断它是否可满足很难，但给定一个解去验证它是否使式子满足，则比较简单。

NPC 问题就是这一类问题中最难的一类，从复杂度上讲是最难的，早在 1971 年就已经被证明。这里只是给大家一个概念：NP 和 NPC 不在考试范围之内。SAT 非常重要，它是计算机史上第一个被证明为 NPC 的问题。那么如何求解 SAT？或者说上世纪科学家是如何设计算法，让计算机求解 SAT，并沿用到现在所有软件中的？

### 范式、文字与子句

**38:14**

求解 SAT 的第一步，是把它转换成我们认识的表达式；计算机也一样。

对于同一个语义，实际上可以写出不同的命题逻辑表达式。例如 \(A \to B\)、\(\neg A \lor B\) 和 \(\neg(A \land \neg B)\)，这三个式子的真值是一样的。如果分别针对这些不同形式去编写算法，会非常冗余。因此 SAT 求解器所做的第一件事，是把所有命题逻辑表达式转换成统一的一种形式，称为范式。范式是命题逻辑表达式的一种规范表达形式。

范式里包含一个叫作文字（literal）的概念：一个命题变元是一个文字；一个命题变元的否定，例如 \(\neg B\)，也是一个文字。在范式中，\(P\) 和 \(\neg P\) 被统一成文字这一概念。第二个概念是析取式，或者叫子句：子句是很多文字用析取词连接在一起，也就是用“或”连接在一起，例如 \(A \lor B \lor C \lor D\)，我们叫它子句或析取式。

还有合取式，它用合取词把多个部分连接在一起。首先学到的第一个范式叫作合取范式。

### 合取范式（CNF）的定义

**40:40**

把子句再用合取词连接起来，就得到合取范式。所谓合取范式，就是用合取词 conjunction 把许多子句连接起来；而子句按前面的定义，是由文字用析取词连接而成的。也就是说，一个合取范式中可能有很多括号，每个括号内部都是用析取词连接的，括号与括号之间则用合取词连接。合取范式简称 CNF。

### 用真值表写出合取范式

**41:23**

例如 \((a \lor \neg b) \land (b \lor \neg a) \land a \land b\) 也可以看成是一个简单的合取范式。

接下来的问题是：拿到任意一个式子之后，怎样把它转换成合取范式？最简单的方法就是列真值表。前面讲过，根据真值表中为 T 的那些行，可以写出与该函数等价的表达式；反过来，如果根据为 F 的那些行来写，写出来的就是合取范式中的子句，例如可以写出 \(\neg p \lor q\)、\(\neg p \lor \neg q\) 这样的子句。这就说明，对于任何一个命题逻辑表达式，都可以把它写成 CNF 的形式。

### 两种特殊情形

**42:57**

那么，如果没有输出为 F 的行、全都为 T，怎么办？这时可以写成 \(p \lor \neg p\)，它是一个永真式，这是第一种情形。第二种情形是全都为 F，那样的式子本身就是矛盾式，不需要再去求它的可满足性。

但问题在于，计算机不可能先列出真值表、再根据真值表去求合取范式。因为给定一个式子，我们本来就是要判断它的可满足性，而真值表太复杂，所以才要做这样的转换。刚才讲真值表，只是给大家展示一个很简单的道理。

### 用等价变换把任意式子转换成合取范式

**43:54**

也就是说，任何一个命题逻辑表达式都一定可以写成 CNF 的形式。那么，怎样把任意一个命题逻辑表达式改写成 CNF 呢？

看一个例子，把 \(\neg(p \leftrightarrow q)\) 转换成 CNF。第一步：合取范式中不含蕴含词和等价词，所以要先消去等价词。等价符号 \(p \leftrightarrow q\) 本身等于（左边蕴含右边）且（右边蕴含左边），而 \(a \to b\) 就是 \(\neg a \lor b\)，于是先把原式改写成 \(\neg\big((\neg p \lor q) \land (\neg q \lor p)\big)\)。

第二步用德·摩根律把否定词移进括号里面，使每个命题变元都变成文字（literal），也就是带否定词或不带否定词的命题变元，得到 \((p \land \neg q) \lor (\neg p \land q)\)。然后再用分配律（distributive law）把式子展开；展开过程中会同时消去一些冗余项，例如 \(q \land \neg q\)、\(q \lor \neg q\) 这样的部分，最后就得到：
\[(p \lor q) \land (\neg p \lor \neg q)\]

**46:04**

好，给大家一些时间，把上面的式子转换成 CNF。

### 练习：消去等价符并展开公式

**49:03**

我们看一下，这道题跟之前的套路是一样的：先把等价符去掉，变成左边一个蕴含、右边一个蕴含，也就是 \((a \land b) \to e\) 和 \(e \to (a \land b)\)，再用合取把它们连接起来，表示两者同时成立。

蕴含消去之后，这个式子变成 \(\neg(a \land b) \lor e\) 与 \(\neg e \lor (a \land b)\)。再把括号打开：\(\neg(a \land b) \lor e\) 变成 \(\neg a \lor \neg b \lor e\)；\(\neg e \lor (a \land b)\) 这一边分开，得到 \(\neg e \lor a\) 和 \(\neg e \lor b\)。最后去掉冗余项，再合并一次，就得到

\[ (\neg a \lor \neg b \lor e) \land (\neg e \lor a) \land (\neg e \lor b) \]

### 语法树的构建：看括号

**50:43**

有人问，这个算法是不是通过构建一棵树来计算的。老师说，首先要把整个表达式括起来，根节点就是最外层括号中间的那个运算符，也就是要先确定出来的那个位置。所以关键就是看括号：所有的符号都要带括号，每一个运算符都强制加括号，例如 \(a \land b \land \cdots\) 也要写成带括号的形式，这样简化之后判断起来就容易了。只要有括号，就很容易判断它是不是 \(a \land b\) 这样的子式；遇到拿不准的地方，就把它拆开来，再继续往下看。判断过程就是看括号。

### 求解器的第一步：检查合式公式

**11:45**

我们现在有两种不同的求解器（solver）。以其中一种为例，它拿到输入后的第一步，是检查这个式子是不是合式公式（WFF）。如果随便输入一个不是 WFF 的表达式，它会直接指出这不合法。检查通过之后，接下来才是如何把它转换成范式。

### 应该转成 CNF 还是 DNF

**12:09**

于是就有两个选择：输入一个公式之后，到底应该把它转成 CNF，还是转成 DNF？老师请同学们先猜一猜，同学们给出了不同的猜测，有同学是因为 DNF 与某个同名的游戏而想到它。课堂上最后给出的答案是 CNF，而不是 DNF。接着老师追问：为什么是 CNF，而不是 DNF？

**13:47**

原因其实很简单，但先要想清楚 CNF 和 DNF 本身是什么样子：CNF 是用括号把析取括起来，括号之间用合取连接；DNF 正好相反。对任何一个表达式来说，把它转成 CNF 和把它转成 DNF，整个表达式的复杂度是一样的。下面举个例子。

**14:46**

先看把 DNF 转成 CNF。做结合的时候，\(a\) 要和所有的项分别结合，\(b\) 也要和所有的项分别结合，所以会指数爆炸。反过来，把 CNF 转成 DNF 也一样爆炸。比如这样一个式子：\((a \vee b) \wedge (a_1 \vee b_2) \wedge (a_1 \vee b_3)\)，每展开一层括号，项数都会成倍增加。

所以无论是 CNF 转成 DNF，还是 DNF 转成 CNF，都是爆炸的，结合的过程完全一样，只是符号相反。也就是说，无论输入的是哪一种范式、要求转成另一种，代价都是指数级增长。

### 开关变量与可满足性等价

**15:51**

无论怎么转换都会爆炸，那到底应该怎么办？这里就要引入一个新概念：开关变量（switching variable）。以原来的式子为例，如果把它写成 DNF：
\[
A_1 \wedge A_2 \wedge A_3 \vee B_1 \wedge B_2 \wedge B_3
\]
它可以与下面这个式子对应：
\[
(z \rightarrow (A_1 \wedge A_2 \wedge A_3)) \wedge (\neg z \rightarrow (B_1 \wedge B_2 \wedge B_3))
\]
这两个式子是**可满足性等价**的。开关变量这个知识点后面还会专门学到。

**16:50**

先说等价。两个式子等价，是指它们的真值表相同：对任意一组变量赋值，两个式子取到的真值都相同。

**17:12**

那么什么叫可满足性等价？本质上是说：如果 \(A\) 可满足，就能推出 \(B\) 也可满足；如果 \(B\) 可满足，也能推出 \(A\) 可满足。但要注意，使两个式子可满足的解不一定是同一个解：使 \(A\) 可满足的那个解，很可能让 \(B\) 为假；使 \(B\) 可满足的那个解，也很可能让 \(A\) 为假。这就是可满足性等价。

### 证明两个式子可满足性等价

**17:59**

开关变量的作用，就是把式子 \(A \vee B\) 改写成 \((z \rightarrow A) \wedge (\neg z \rightarrow B)\)，两者可满足性等价。下面来证明这件事：直接画真值表，要证的就是 \(A \vee B\) 与 \((z \rightarrow A) \wedge (\neg z \rightarrow B)\) 可满足性等价。也就是说，如果有一个解使 \(A \vee B\) 可满足，那么也能推出另一个式子可满足。

### 可满足性等价的证明

**18:57**

继续证明 \(A \lor B\) 与 \((Z \to A) \land (\neg Z \to B)\) 的可满足性等价。所谓可满足性等价，就是二者要么同时可满足，要么同时不可满足。

先证明左边可满足推出右边可满足。\(A \lor B\) 可满足时，只需考虑三种赋值：\(A\) 真、\(B\) 真；\(A\) 真、\(B\) 假；\(A\) 假、\(B\) 真。对第一种情况，取 \(Z\) 为真，右边 \((Z \to A) \land (\neg Z \to B)\) 为真；对第二种情况，取 \(Z\) 为真，\((Z \to A)\) 为真，\((\neg Z \to B)\) 也因 \(\neg Z\) 为假而为真；对第三种情况，取 \(Z\) 为假，\((Z \to A)\) 因 \(Z\) 为假而为真，\((\neg Z \to B)\) 也因 \(\neg Z\) 为真且 \(B\) 为真而为真。于是只要左边可满足，就能找到合适的 \(Z\)，使右边可满足。

反过来证明右边可满足可以推出左边可满足，可以证明它的逆否命题：如果 \(A \lor B\) 不可满足，那么右边一定不可满足。若 \(A \lor B\) 不可满足，则 \(A\) 和 \(B\) 都为假。此时若 \(Z\) 为真，则 \(Z \to A\) 为假；若 \(Z\) 为假，则 \(\neg Z \to B\) 为假。所以无论 \(Z\) 取真还是取假，\((Z \to A) \land (\neg Z \to B)\) 都为假，右边不可满足。至此就证明了两个式子可满足性等价。

### 可满足性等价与逻辑等价

**21:58**

由此可知，如果两个逻辑表达式等价，它们一定可满足性等价。但反过来不成立：可满足性等价不一定推出逻辑等价。例如取 \(A\) 为真、\(B\) 为假、\(Z\) 为假。此时左边 \(A \lor B\) 为真；右边 \((Z \to A) \land (\neg Z \to B)\) 中，\(Z \to A\) 为真，而 \(\neg Z \to B\) 是“真蕴含假”，为假，所以整个右边为假。于是二者在同一组赋值下真值不同，并不等价。

所谓可满足性等价，是指 \(A\) 可满足当且仅当 \(B\) 可满足；也可以说，\(A\) 不可满足当且仅当 \(B\) 不可满足。使两个式子同时可满足的解可以是同一个解，也可以是不同的解。如果使它们可满足的解完全相同，那么二者的关系还会更强，成为逻辑等价；如果解不一定相同，那就只是可满足性等价。因此，逻辑等价可以推出可满足性等价，但可满足性等价推不出逻辑等价。

### 开关变量与 CNF 转换

**23:58**

为什么要讨论这种转换？因为 SAT 问题本身是：给定一个公式，判断它到底是可满足还是不可满足。为此可以借助一组表达式，引入一个开关变量 \(Z\)，把原式变成一个可满足性等价但复杂度更低的式子。

把蕴含打开后，\(Z \to A\) 变成 \(\neg Z \lor A\)，\(\neg Z \to B\) 变成 \(Z \lor B\)。如果原式是形如两个合取分支的析取，例如 \((A_1 \land A_2 \land A_3) \lor (B_1 \land B_2 \land B_3)\)，就可以用一个开关变量写成 \((Z \to A_1) \land (Z \to A_2) \land (Z \to A_3) \land (\neg Z \to B_1) \land (\neg Z \to B_2) \land (\neg Z \to B_3)\)，再打开蕴含得到 \(\neg Z \lor A_1\)、\(\neg Z \lor A_2\)、\(\neg Z \lor A_3\) 以及 \(Z \lor B_1\)、\(Z \lor B_2\)、\(Z \lor B_3\)。这时一共有 \(3+3=6\) 个子句。

SAT solver 里通常使用 CNF 而不是 DNF，原因就在这里：从 DNF 转成 CNF 可以借助开关变量保持可满足性等价，避免直接展开造成规模爆炸；转成 CNF 后，原来的约束信息仍然保留。

### SAT solver、CNF 与主范式

**25:32**

SAT solver 要做的第一件事是检查输入是否为合式公式（WFF），第二件事是把它变成范式，具体来说变成 CNF。对任意公式转成 CNF 时，如果展开导致复杂度爆炸，就引入开关变量；得到的新式子与原式可满足性等价。

不过还有一个问题：即使都写成 CNF，同一个式子也可以写出很多种不同的 CNF 表达式。例如上面那个式子是 CNF，下面那个式子也是 CNF，所以 CNF 还不够唯一。能不能进一步得到唯一形式？SAT solver 本身不一定做这种唯一化，但这是教材上的一个知识点：任意一个命题逻辑表达式都可以写出多个 CNF，但它只有唯一一个主析取范式或主合取范式，主析取范式和主合取范式一般统称为主范式。主范式的特点是，它的每一个子句都是一个极小项，子句本身是用合取连接起来的。

### 极小项与主范式

**27:08**

极小项要包含该命题逻辑表达式中出现的所有命题变项。例如整个表达式中有三个命题变项，那么每一个极小项里都要包含这三个变项。若只有两个命题变项 \(P_1\) 和 \(P_2\)，则 \(P_1\land P_2\)、\(\neg P_1\land P_2\)、\(P_1\land\neg P_2\)、\(\neg P_1\land\neg P_2\) 都属于极小项。主析取范式本质上就是根据真值表，把输出为 true 的那些行写出来。比如 \(m_0\) 对应 \(\neg P\land\neg Q\)，再或上 \(\neg P\land Q\)，或上 \(P\land Q\)。每一个合取项都是极小项，并且都包含有关的全部命题变项。任何一个命题逻辑表达式都只有一个主析取范式，也只有一个主合取范式；主合取范式是根据真值表中输出为 false 的行来写的。

### 例：求 \(P\to Q\) 的主析取范式

**28:28**

这是一个书上的练习：把一个式子改写为主析取范式。以 \(P\to Q\) 为例。先将其转换为
\[P\to Q \equiv \neg P\lor Q.\]
为了让每个合取项包含全部变项，可以给 \(\neg P\) 补上 \(Q\lor\neg Q\)，于是
\[\neg P\lor Q \equiv (\neg P\land Q)\lor(\neg P\land\neg Q)\lor Q.\]
其中 \(Q\lor\neg Q\) 本身为 true，所以这样添加没有问题。再用结合律展开，得到
\[(\neg P\land Q)\lor(\neg P\land\neg Q)\lor Q.\]
这里的 \(Q\) 还不是极小项，因为它没有包含 \(P\)，所以还要与 \(P\lor\neg P\) 合取，再展开：
\[(\neg P\land Q)\lor(\neg P\land\neg Q)\lor(P\land Q)\lor(\neg P\land Q).\]
最后一式和第一式相同，可以删去。于是 \(P\to Q\) 的主析取范式为
\[(\neg P\land\neg Q)\lor(\neg P\land Q)\lor(P\land Q).\]
书上也把它记作 \(m_0\lor m_1\lor m_3\)。真值表有一个规范：\(\neg P,\neg Q\) 是第 0 行，\(\neg P,Q\) 是第 1 行，\(P,\neg Q\) 是第 2 行，\(P,Q\) 是第 3 行；\(m\) 的下标就表示对应的行号，所以这里是第 0、1、3 行。

### 例：\((a\land b)\leftrightarrow e\) 的等价展开

**30:32**

再看一个例子：\((a\land b)\leftrightarrow e\)。首先把等价号去掉，可以得到
\[(a\land b)\leftrightarrow e \equiv (a\land b\land e)\lor(\neg a\land\neg e)\lor(\neg b\land\neg e).\]
这里没有直接使用 \(\neg a\lor\neg b\) 的形式，而是使用与它等价的合取项；从上面的式子到下面的式子用的是等价变换。这里使用的也是等价关系，而不是定义符号。

### \(a\leftrightarrow b\) 的 CNF 与 DNF

**33:51**

再一个就是 \(a\leftrightarrow b\)。它可以写成 \((a\to b)\land(b\to a)\)，再用蕴含消去，得到
\[(\neg a\lor b)\land(\neg b\lor a).\]
这是 \(a\leftrightarrow b\) 的典型 CNF。若写成 DNF，则为
\[(a\land b)\lor(\neg a\land\neg b).\]
两者是等价的：\(a\leftrightarrow b\) 为真，当且仅当 \(a,b\) 同时为真或者同时为假；DNF 的两个析取项正好分别对应这两种情况。

### 从真值表写主析取范式与主合取范式

**35:11**

为什么从上面这个式子可以直接写成下面这个式子？因为它可以直接写成 DNF，中间不需要再用“或”去补，本质上就是根据真值表写出来的，和刚才说的意思差不多。写成这种形式之后，把各项逐步展开，再用结合律、交换律整理，最后就变成

\[
\lnot a \land \lnot b \land \lnot c \lor \lnot a \land b \land \lnot c \lor a \land \lnot b \land \lnot c \lor a \land b \land c
\]

里面每一个合取项都是一个极小项。展开的过程中会引入原来缺少的变量：比如某一项里缺 \(b\)，就把 \(b\) 引入，用 \(b \lor \lnot b\) 去补；缺 \(a\) 就引入 \(a\)，然后再展开、再交换，最后按真值表的行号去对应（例如第 0 行、第 2 行这样的行号）。有了主析取范式，也就有主合取范式：主析取范式中每一项对应的是极小项，而换成合取式之后，每一项就变成了极大项。

在合取范式里，每个子句同样都要包含这些变量，只不过它们是用析取连接起来的；合取范式本身就是根据真值表中取值为 F 的那些行写出来的。

**36:42**

比如说把 \(p \land q\) 写成主合取范式。\(p\) 这一边没有 \(q\)，就要引入 \(q\)：写成 \(p \lor (q \land \lnot q)\)，也就是 \(p \lor F\)，它仍然等于 \(p\)；再用分配律打开，就得到 \((p \lor q) \land (p \lor \lnot q)\)。同样，\(q\) 这一边缺 \(p\)，就补上 \(p \lor \lnot p\)，得到 \((q \lor p) \land (q \lor \lnot p)\)。把这些合起来展开，最后得到 \((p \lor q) \land (p \lor \lnot q) \land (\lnot p \lor q)\)，再按真值表对应到使 f 为 false 的那几行。

这里的做法和刚才是一样的。但你看上一个例子，我们用的是下面这个式子：因为可以直接在中间引入变量，把它直接改写成了析取范式；而这里我要写主合取范式。

**37:59**

写主合取范式时，我就直接用这样一个等价式：把 \(a \land b \leftrightarrow c\) 写成 \((a \land b \to c) \land (c \to a \land b)\) 这样两项的合取，再把这两个式子打开，然后把否定词移进去，就得到 \(\lnot a \lor \lnot b\)。移进去之后，这一项里缺 \(b\)，就引入 \(b\)，补上 \(b \lor \lnot b\)；另一项缺 \(a\)，就补上 \(a \lor \lnot a\)；然后再展开成下面的式子，并把里面冗余的项去掉。

这样就变出了最后的式子，大家回去有时间可以做。对真值表来说，对应的是第一行、第二行、第四行这样的行。所以 PCNF 和 PDNF，实际上就是根据真值表中取值为 true 和 false 的那些行写出来的。

### 求解 CNF：从真值表到 DPLL

**39:10**

假设检查合式公式合法性这一步已经做完了，接下来我要把任意一个逻辑表达式转成 CNF：展开变量也好，直接转也好，都转成 CNF，然后去求解。那假设我已经把这个式子写成了 CNF，应该用什么算法来解决问题？最简单的办法当然是用真值表枚举所有的 case，但这显然是不合理的。所以这里要介绍一个新的算法，叫 DPLL。到目前为止，我们用的所有求解器，包括芯片验证的 EDA 工具、程序验证中的求解器，底层都是这个算法以及这个算法的变体。

DPLL 的基本思路就是两个字：一个是猜，一个是推——根据你猜的值进行推理，判断这个值到底靠谱还是不靠谱；如果不靠谱，就重新去猜。一个变量最多能猜几次？两次，因为只有 true 和 false 两种取值。所以它第一步是什么？

**40:52**

第一步要猜。我们把变量的初始状态叫 undefined：如果这个变量它的真值还没有被猜过，我们就叫 undefined；如果它的真值之前已经被猜过了，就叫 defined，带上 defined 标记。然后我再根据猜出来的值去推理其他变量的值，这里会有一些推理规则，一会儿会讲。

然后如果有一个子句——因为我们是 CNF，如果它是可满足的，那么所有的子句一定都为 true，也就是每个子句里至少有一个文字为 true；所以我一旦出现了一个子句为 false，我就知道我猜错了。至少对于“可满足”这个目标来说，这个猜测一定是错的，那么我要重新猜。好，那我们看一个最简单的例子。

### 一个简单例子

**42:01**

举一个最简单的例子：\((a \lor \lnot b) \land (b \lor \lnot c) \land (c \lor a)\)。首先猜 \(a\)，它现在是 undefined，之前没有被猜过；假设我猜 \(a\) 是 false，那么 \(a\) 就已经被猜过了，这一步是一个 decision，\(a\) 的值就定下来了。

如果 \(a\) 是 false，我们能推出什么？\(b\) 一定是 false——因为子句 \(a \lor \lnot b\) 一定为 true，而 \(a\) 已经是 false，所以 \(\lnot b\) 必须为 true，也就是 \(b\) 一定是 false。那如果 \(b\) 是 false，我们又能推出 \(c\) 也是 false——因为子句 \(b \lor \lnot c\) 一定要为 true。推出来 \(c\) 是 false 之后你会发现，第三个子句 \(c \lor a\) 就变成 false 了，因为 \(c\) 和 \(a\) 都是 false。对于这种出现了 false 的子句，就说明这一次猜错了。

### 从矛盾子句到 pure literal 规则

**43:17**

这个子句称为矛盾子句。它说明：如果最开始把 \(a\) 设为 false，就会推出矛盾；如果公式本身可满足，\(a\) 并不一定必须为 false，因此需要回溯，重新猜 \(a\) 为 true，并从重新开始的流程继续。

重新猜 \(a\) 为 true 后，\(a\) 为 true 已经确定，于是可以让 \(b\) 为 true，这样问题就解决了。观察这个式子：每个子句里只有 \(a\)，没有 \(\neg a\)。在这种情况下，可以直接把 \(a\) 赋为 true；如果公式可满足，这样做能让求解器以较大概率找到可满足解。

这就是 pure literal 规则：当某个文字在所有子句中都只以正形式出现、没有对应的否定形式时，就直接把它置为 true；反过来，如果只出现 \(\neg a\) 而没有 \(a\)，就直接把它置为 false。下面根据这个例子快速看上面的文字。

### DPLL 的五条规则

**45:13**

这套算法由几个规则组成。第一条是 decide：如果还有命题变元没有猜过，就去猜；一旦猜了 \(a\)，就认为 \(a\) 已经被 decide 过。第二条是单元传播（unit propagate）：如果一个子句中除一个文字外，其余文字都已经推出为 false，那么剩下的那个文字一定为 true，否则子句不成立。这些内容在 lecture notes 上，不在教科书上。

第三条是回溯（backtrack）：如果推出一个矛盾子句，就回到之前的状态重新猜。什么时候会直接 fail 呢？当所有命题变元都已经 decide 过、已经没有可以猜的变元时，如果仍然出现矛盾子句，就说明整个公式不可满足，这叫 fail。最后一条是 pure literal：如果每个子句里某个文字只以 \(a\) 或只以 \(\neg a\) 的形式出现，就直接把 \(a\) 赋为 true 或 false。规则非常简单，一共四五条，它们就组成了一个算法。

### 回溯并找到可满足赋值

**48:56**

根据第一个子句，2 一定是 false。再根据第二个子句，如果 2 为 false，就推出 3 为 true。继续看第三个子句，如果 3 为 true、4 也为 true，那么第三个子句一定是 false。这说明最开始把 1 猜成 true 是错误的，它不是 decide 的结果，而是一个失败的猜测。按照 decide 的含义，需要把这个猜测状态去掉；既然 1 为 true 不满足，就改为 1 为 false。

如果 1 为 false，根据最后一个子句，可以推出 4 为 true。4 为 true 后，再根据中间的子句，可以猜 3 为 false——这一步肩膀上有 d，表示 decision，即猜 3 为 false。如果 3 为 false，根据第二个子句就推出 2 一定是 true。到现在为止，每个子句都找到了一个文字使其为 true。

### DPLL 的基本规则

**52:10**

DPLL 的第一条规则是分支：随便选择一个尚未赋值的命题变项进行猜测，例如先猜 \(a\) 的取值。第二条规则是单元传播：如果某个子句中只剩下一个文字，就可以直接推出它的取值；例如，若假设 \(a\) 为 false，则 \(b\) 一定为 false。

如果一旦发现冲突（conflict），就说明之前的分支猜错了，需要回溯（backtrack），回去重新选择。

如果所有变量都已经赋值完，并且仍然没有发现冲突，那么这个表达式就是可满足的。

另外还有一个规则：如果某个命题变项在所有子句中都只以同一种符号出现，就可以直接把它赋成使这些子句满足的值。

**53:28**
