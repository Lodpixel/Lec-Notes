## 2026 年 9 月 18 日｜第 1 节回放

### 从数学证明到程序证明

**08:33**

前面我们讨论了离散数学和程序验证。现在开始讲命题逻辑。数理逻辑要处理的核心问题是：给定一个程序，以及这个程序的正确性规约，如何用数学逻辑表示它，并让计算机自动检查这个证明。

先说 proof。证明是一种论证：我们依据已经接受的事实、定义和推理规则，说明为什么某个结论成立。

数学证明，就是使用数学语言和数学规则，证明某个数学陈述成立。程序证明也遵循同样的思想，只是被证明的结论变成了“程序满足某个正确性定义”。

因此，程序验证并不是直接问“这段代码看起来对不对”，而是先明确：

1. 程序要实现什么；
2. 什么条件下运行；
3. 执行结束后必须满足什么性质；
4. 如何根据规则证明程序确实满足这些性质。

### Lean 与形式化证明

**15:52**

近年来，大模型经常与 Lean 等形式化证明工具结合使用。Lean 是一种形式化证明语言和证明检查器。你可以把数学理论、定义、定理和证明写成 Lean 能理解的形式；Lean 会检查证明中的每一步是否符合规则。

例如，要证明自然数加法满足交换律，可以写出“a + b = b + a”，并依据自然数的定义、递归规则和已有引理进行证明。Lean 的价值不在于替你理解问题，而在于对形式化后的证明提供严格反馈：某一步不成立，就会明确指出。

这对 coding agent 很重要。大模型可以生成证明草稿，但如果没有可靠的检查器，草稿是否正确仍然需要人工判断。形式化工具能够提供机器可检查的反馈，帮助 agent 继续修正证明。

### 直接证明：偶数的平方仍为偶数

**22:54**

考虑一个简单命题：

> 如果 n 是偶数，那么 n² 也是偶数。

先给出定义。整数 n 要么是偶数，要么是奇数；偶数可以写成 2k，奇数可以写成 2k + 1。这里还隐含了两个基本事实：每个整数至少属于这两类中的一类，并且不可能同时既是偶数又是奇数。

证明如下。假设 n 是偶数，那么存在整数 k，使得 n = 2k。因此：

~~~text
n² = (2k)²
   = 4k²
   = 2(2k²)
~~~

所以 n² 可以写成 2 乘以一个整数，按照偶数的定义，n² 是偶数。证明结束。

这个例子展示了直接证明的基本结构：

1. 明确目标；
2. 引入定义；
3. 假设前提成立；
4. 根据定义进行代数推导；
5. 得到目标结论。

对人来说，“整数要么奇要么偶”似乎是常识；但对计算机来说，定义和假设必须明确写出。形式化证明要求我们把所有推理依据都表达出来。

### 枚举证明：二皇后问题

**31:58**

再看一个枚举证明。n 皇后问题是在 n×n 的棋盘上放置 n 个皇后，使任意两个皇后都不在同一行、同一列或同一条对角线上。

当 n = 2 时，问题变成：能否在 2×2 棋盘上放置两个互不攻击的皇后？

棋盘上共有 4 个位置，选择两个位置一共有：

~~~text
C(4, 2) = 6
~~~

种情况。逐一检查这 6 种摆法，可以发现任意两个位置都会共享一行、共享一列或共享一条对角线。因此，2 皇后问题无解。

这种证明方法叫作枚举证明或分类讨论。形式化写法可以把所有位置编号，再逐一讨论每一对位置。Lean 或其他工具也可以帮助我们把这些有限情况形式化并检查。

### 数学归纳法：前 n 个整数之和

**36:59**

考虑另一个熟悉的结论：

~~~text
1 + 2 + ... + n = n(n + 1) / 2
~~~

可以使用数学归纳法证明。

第一步是证明基础情形 n = 1 成立：

~~~text
1 = 1(1 + 1) / 2
~~~

第二步是假设公式对 n = k 成立，即：

~~~text
1 + 2 + ... + k = k(k + 1) / 2
~~~

然后证明它对 k + 1 也成立：

~~~text
1 + 2 + ... + k + (k + 1)
= k(k + 1) / 2 + (k + 1)
= (k + 1)(k + 2) / 2
~~~

基础情形成立，且“对 k 成立能够推出对 k + 1 成立”，所以公式对所有正整数 n 成立。

### 为什么要学习证明

**39:38**

前面三个例子分别展示了直接证明、枚举证明和归纳证明。大模型在这些问题上表现较好，原因是问题定义明确、目标清晰，而且生成的结果可以交给形式化工具检查。

这也说明了大模型能力的边界：它擅长在问题已经被准确描述、结果又能够被验证时寻找解答；但它不擅长替我们定义一个新的问题，或者为一个程序自动确定正确的规约。

如果程序本身存在 bug，那么仅仅让大模型根据这个程序生成“正确性定义”可能会把错误也一起合理化。软件工程师需要做的，不只是快速求解问题，还包括定义问题、定义正确性、选择合适的验证方式。

### 命题与程序正确性

**43:23**

命题是一个断言或陈述，它必须能够确定地判断为 true 或 false，并且不能同时为 true 和 false。

例如：

- “2 + 2 = 4”是命题；
- “如果 n 是偶数，那么 n² 是偶数”是命题；
- “n > 1”单独看不是命题，因为 n 没有被具体指定，也没有量词；
- 疑问句、感叹句和单纯的拟声词通常不是命题。

回到程序验证：我们先给程序规定一个正确性定义，这个定义本身必须是一个命题。然后把程序的行为转换为数学表达式，最后检查“程序是否满足这个规约”这一命题为真还是为假。

这就是后面命题逻辑要完成的事情：用明确、没有二义性的形式表达程序的正确性，再让计算机帮助我们推理。

## 2026 年 9 月 18 日｜第 2 节回放

### 命题逻辑的基本对象

**05:16**

前面我们从数学证明引入命题，又把程序的正确性规约看成命题。整个逻辑关系可以概括为：

1. 先给定程序；
2. 定义程序应当满足的正确性规约；
3. 把程序行为转换成逻辑表达式；
4. 证明程序满足这个规约。

现在正式回答：什么是命题？

命题是一个有确定真值的陈述。它要么为 true，要么为 false，不可能同时为真或同时为假。注意，命题为假并不意味着它不是命题；只要它的真假可以确定，它仍然是命题。

### 命题逻辑与命题变量

**08:56**

命题逻辑是在命题概念基础上建立的数学系统，用来推理命题的真值，以及多个命题之间的关系。

命题逻辑的表达式主要包含两类基本元素：

- 命题变量：用大写字母 p、q、r 等表示简单命题；
- 命题联结词：把一个或多个命题连接成更复杂的表达式。

例如，令 p 表示“Tom 是一只猫”，q 表示“Jerry 是一只老鼠”。p 和 q 都是原子命题或简单命题；如果写成“Tom 是一只猫，并且 Jerry 是一只老鼠”，则它是由 p、q 和联结词“且”组成的复合命题。

每个命题变量都有两个可能的真值：true 和 false。

### 否定、合取与析取

**13:41**

第一个联结词是否定，记作 ¬p。它把 p 的真值反转：

| p | ¬p |
|---|---|
| true | false |
| false | true |

第二个联结词是合取，记作 p ∧ q，表示“p 且 q”。只有当 p 和 q 都为 true 时，p ∧ q 才为 true。

第三个联结词是析取，记作 p ∨ q，表示“p 或 q”。只要 p、q 中至少有一个为 true，p ∨ q 就为 true。这里的“或”是通常的逻辑或，不排斥两者同时成立。

合取和析取都满足交换律：

~~~text
p ∧ q 与 q ∧ p 的真值相同；
p ∨ q 与 q ∨ p 的真值相同。
~~~

证明它们满足交换律的直接方法是列真值表。p、q 只有四种取值组合；逐行比较两个表达式的结果即可。

### 蕴含

**19:13**

蕴含词记作 p → q，读作“如果 p，那么 q”。它想表达：在 p 成立的情况下，q 也必须成立。

蕴含的真值表如下：

| p | q | p → q |
|---|---|---|
| true | true | true |
| true | false | false |
| false | true | true |
| false | false | true |

蕴含只有一种情况为假：前件 p 为真，而后件 q 为假。也就是说，真正违反“如果 p，那么 q”的，是 p 确实发生了，但 q 没有发生。

当前件 p 为假时，p → q 在命题逻辑的定义下为真，无论 q 是真还是假。这一点比较反直觉，但必须记住：逻辑蕴含不是日常语言中简单的因果关系，而是由真值表定义的联结词。

例如，“如果太阳从西边升起，那么鱼会在天上唱歌”在形式逻辑中为真，因为它的前件为假。这个例子不是在讨论现实因果，而是帮助我们理解蕴含的真值定义。

### 双条件

**23:01**

双条件词记作 p ↔ q，表示“p 当且仅当 q”或“p 与 q 等价”。它在 p、q 真值相同的时候为 true，在真值不同时为 false。

| p | q | p ↔ q |
|---|---|---|
| true | true | true |
| true | false | false |
| false | true | false |
| false | false | true |

双条件可以表示为两个方向的蕴含同时成立：

~~~text
p ↔ q  等价于  (p → q) ∧ (q → p)
~~~

证明两个表达式等价的一种直接方法，也是列出它们的真值表，逐行比较结果。

### 合式公式：命题逻辑的语法

**28:41**

到目前为止，我们讨论的是联结词的语义，即表达式在不同输入真值下到底是真还是假。接下来需要说明哪些字符串本身是合法的命题逻辑表达式，这属于语法问题。

我们把合法的命题逻辑表达式称为合式公式（well-formed formula，简称 WFF）。合式公式可以递归定义：

1. 每个原子命题都是合式公式；
2. 如果 A、B 都是合式公式，那么 ¬A、A ∧ B、A ∨ B、A → B、A ↔ B 也都是合式公式；
3. 除此之外的形式都不是合式公式。

这个定义允许我们构造任意复杂的表达式。例如，A 可以本身是 p ∨ q，B 可以是 r → s，于是 A ∧ B 仍然是合式公式。

语义回答“这个表达式在某组真值下是真是假”；语法回答“这个表达式是否按规则构造出来”。命题逻辑需要同时具备这两部分。

### 为什么需要研究完备性

**34:49**

我们目前介绍了否定、合取、析取、蕴含和双条件。问题是：这些联结词是否足够？能不能用它们表示所有可能的命题逻辑函数？

例如，异或表示 p、q 真值不同时为 true，相同时为 false。它可以由现有联结词表示：

~~~text
p ⊕ q  等价于  (p ∧ ¬q) ∨ (¬p ∧ q)
~~~

因此，异或不一定要作为新的基本联结词加入系统。

如果一组联结词能够把任意命题逻辑表达式改写成只使用这组联结词的等价表达式，就称这组联结词是完备的。完备性意味着：这套基本工具足以表达整个布尔函数空间，不需要不断增加新的基本运算。

### 用真值表构造表达式

**40:33**

设 g 是一个有 n 个命题变量的布尔函数。它的输入是 n 个真值，输出是一个真值。我们希望证明：对于任意这样的 g，都能构造一个与它等价的合式公式。

先看 n = 2 的情况。p、q 有 4 种输入组合；每一行的输出都可以独立取 true 或 false，因此一共存在：

~~~text
2^4 = 16
~~~

个不同的二元布尔函数。

对真值表中输出为 true 的每一行，我们构造一个“最小项”：

- p 为 true，就写 p；
- p 为 false，就写 ¬p；
- q 为 true，就写 q；
- q 为 false，就写 ¬q；
- 这一行的条件用 ∧ 连接。

例如，若某一行是 p = false、q = false，那么对应的条件就是：

~~~text
¬p ∧ ¬q
~~~

如果真值表中有多行输出为 true，就把这些行对应的最小项用 ∨ 连接。这样得到的表达式，恰好在这些行上为 true，在其他行上为 false，因此与原来的布尔函数等价。

这种“先按行构造，再用或连接”的方法，就是由真值表构造析取范式的基本思路。输出为 false 的情况也可以用类似方法处理，或者通过整体取反得到。

**50:27**

完备性的证明会继续把二元情形推广到任意 n。核心思想始终不变：每一个真值表都可以按照输出为真的行构造出一个等价的合式公式。

到这里，第一周的命题逻辑基础已经建立起来了：

- 命题有确定的真值；
- 命题变量表示原子命题；
- 命题联结词用于组合命题；
- 真值表描述语义；
- 合式公式描述语法；
- 完备性说明一组联结词是否足以表达所有布尔函数。

后续课程会在这些基础上继续讨论等价变换、自动求解，以及如何把程序转换成命题逻辑公式并验证其正确性。
