### 公理系统与 SMT 求解器

**13:04**

因此，求解谓词逻辑时，需要构建公理系统来做 deduction（推理、推演）。另一个办法是使用 SMT solver。SMT solver 并不能保证对所有表达式都给出解；但只要它判定一个系统可满足或不可满足，这个结论一定正确。也就是说，SMT solver 是 sound（可靠的），但不是 complete（完备的）：它给出的解一定正确，但并非所有表达式都能被它解出来，所以不能保证一定给出答案。

### 霍尔三元组与面向程序的验证

**14:53**

霍尔逻辑面向程序，关键变化在验证方式：它提出霍尔三元组 \(\{P\}\,C\,\{Q\}\)。原来是把一个大的程序直接转换成一个谓词逻辑表达式，再检查这个表达式是否满足最后的 assertion；现在则把这个大的谓词逻辑表达式拆分，通过霍尔三元组把大程序变成对每一行代码的证明。如果执行代码前满足 P，执行完代码块 C 后满足 Q，就说代码块 C 满足该三元组；P 和 Q 分别是前置条件和后置条件。

### 从命题逻辑到霍尔逻辑

**16:48**

从整体上看，命题逻辑、谓词逻辑和霍尔逻辑是贯穿课程的三块内容。可以这样理解：命题逻辑和谓词逻辑把书上的知识点打散，重新用程序验证的方式组织了一遍，并进行了穿插；霍尔逻辑则是把书上的公理系统做成一个更加具体的案例。

一个公理系统包含两部分：公理和推理规则。定义公理系统时，首先要规定系统中有哪些符号，然后给出形成规则。例如在命题逻辑和谓词逻辑中，符号包括联结词、谓词符号等；形成规则规定哪些表达式是合式公式（well-formed formula）。有了符号和形成规则之后，才可以定义公理，再定义推理规则。霍尔逻辑也是按这个结构展开的。

### 霍尔逻辑的公理与推理规则

**18:20**

在霍尔逻辑里，我们定义了哪些公理？定义这些公理的目的是什么？核心是两类推理：已知 P 和 C，如何推出 Q；或者已知 Q 和 C，如何推出 P。这里的 C 可以是不同的程序构造：它可以是顺序程序，也可以是 if-else，还可以是 while 循环。在 while 循环中，我们会引入循环不变量。

根据 P 和 C 推出 Q'，再用 Q' 推出 Q，最终生成 {P}C{Q}，并证明 {P}C{Q} 是 valid；这就是推理规则。由 P 和 C 推出的 Q' 需要满足什么性质？它要取最强后置条件。也就是说，对所有正确的规约 {P}C{Q}，这个 Q 都应该能够由 Q' 推出来。

反过来，由 Q 和 C 推出 P 时，P 需要满足最弱前置条件。也就是说，对所有正确的规约 {P}C{Q}，由 Q 和 C 推出的前置条件要取最弱前置条件；原来的 P 应该能够推出这个最弱前置条件，即 P 不比它弱。霍尔逻辑的规则其实可以总结得很简单。

### 验证器的基本流程

**26:20**

这节课先介绍第一件事：对于刚才那样的 Dafny 程序，它内部到底怎样实现一个验证器，用霍尔逻辑把这个程序验证出来。上上节课学了霍尔逻辑，之后又学了最弱前置条件等内容；现在要问的是，怎样构建一个 Dafny 这样的验证器，把整个程序验证出来。它的基本输入是什么？首先是一个程序，同时这个程序上要有前置条件（`requires`）、后置条件（`ensures`），以及 `assertion` 等断言；还有循环不变量。这些和程序一起作为输入，交给自动化验证器。它的过程是：首先把刚才看到的 Dafny 程序转换成控制流图（control flow graph），用一张图表示整个程序的运行控制流；然后把前置条件、后置条件和循环不变量插入到控制流图中；再把控制流图变成霍尔三元组，用之前的最弱前置条件等方法去证明。

### 控制流图与基本块

**28:50**

先看什么是控制流图。它实际上是用图表示每个程序可能执行的所有路径。举一个简单的例子，比如一个 while 循环，右边就是它的图形表示。图中每个节点叫一个基本块（basic block）。基本块内部的指令顺序执行，不会发生跳转；当遇到跳转指令时，这个基本块结束，开启下一个基本块。每条有向边表示：这个基本块执行完指令后，下一条控制流可能跳到哪个基本块。比如 `while (a > 0) { a = a - 1; }` 这样的 while 循环，首先有一个 `start` 节点，表示入口，默认都会有 `start`。然后有一条判断 `if (a > 0)`。一般会把 while 变成 if：如果 `a > 0`，就执行 `a = a - 1`。为什么 while 可以变成 if 呢？因为执行完 `a = a - 1` 之后，还有一条控制流可以回到 `if (a > 0)` 这里；这样一个环就表示 while loop。当执行到 `a == 0` 或 `a < 0` 时，控制流走下面那条边，退出循环。这边是 `return`；一般一旦有返回值，就把返回值叫 `result`，然后返回 `result`。想一下，假设没有这条回边，这个程序会变成怎样？

### 没有回边时的程序

**31:09**

如果没有这条回边，这个程序会变成怎样的程序？它对吗？假设没有这条回边，它就变成 `if (a > 0) { a = a - 1; } else { return a; }`。这样 if 分支实际上没有返回值，所以它不是一个完整的程序，而是一个带 warning 的程序。对于顺序程序（sequential program），实际上可以把所有顺序指令都放到一个基本块里执行。例如：

```c
a = a + 1;
b = 3;
a = b + a + b;
```

这些顺序指令会变成同一个基本块。

### 控制流图的递归构造

**31:59**

控制流图实际上可以递归地定义。例如 `if (b) { c1 } else { c2 }`：如果 `b` 成立就执行 `c1`，否则执行 `c2`；`c1`、`c2` 内部还可以进一步展开。如果 `c1` 内部还有控制流（跳转），它可以进一步展开成新的控制流图。举个例子：

```c
if (a == 0) {
    b = 3;
} else {
    b = 4;
}
```

这种 if-else 在控制流图中变成：判断 `a == 0`，成立则执行 `b = 3`，否则执行 `b = 4`；两条路径随后汇合，再执行下面一段。

**32:51**

这是一个分支结构。如果只有一个分支，就是 `if b` 中 \(b=1\) 时执行 \(c_1\)，然后直接到下面的路径；否则也直接到下面的路径。这是外层循环。

刚刚已经讲过，大家画一下这个程序的控制流图，并简单看一下这个控制流图。

### 从控制流图插入前置、后置条件

**35:31**

这个控制流图就是：首先第一个基本块是循环入口，所以上面是 `if c`；如果 \(c\) 满足条件，就会进入这样的循环。循环里第一个基本块是 `x = y + 1; y = 2 * z; if d`。在 `if d` 这里出现第二个分支：如果 \(d\) 成立，就执行左边的 `x = y + z`；否则直接跳到 \(z\) 的那一步。执行完这一段之后，会返回到 `if c`，形成一个环路；当 \(c\) 不满足时，就会跳出循环，直接执行 \(z\) 那一步。

### 把前置和后置条件变成基本块中的代码

**37:02**

后置条件是 `result = 2`，也就是刚刚展示的那个例子；这个例子的前置条件是 \(a=1\)。代码里执行 `a = a + 1`，然后 `return result`。对于这个函数，验证器把它输入进来之后，会先做分析，构建这样的控制流图。构建好之后，它会识别到前置条件是 \(a=1\)，后置条件是 `result = 2`，所以把前置条件单独作为一个基本块放进来：在执行这些代码之前，先 `assume a = 1`。后置条件则是在执行完这段代码之后，要求 `result = 2`，于是 `assert result = 2`。可以看到，这两个条件从前置和后置变成了基本块里面的一行代码。

### assert 语句的最弱前置条件

**38:14**

那就要把它考虑成一行代码，来看怎么证明这个程序。如果把它看成一行代码，假设它后面有个后置条件；当然现在这个后置条件是 true。它有后置条件，那么 `assert p; q` 的最弱前置条件是什么？是 \(p \land q\)，对不对？反过来，我把后置条件和前置条件插到了控制流图里面，它就变成了普通的一行代码。

如果把它看成一行代码，我需要求这行代码的最弱前置条件。假设它还有一个后续条件 \(q\)，推理规则是什么？假设这条语句是 `assert p`，后面的后置条件是 \(q\)，它们的最弱前置条件就是 \(p \land q\)。因为 `assert p` 要求 \(p\) 成立；\(q\) 是我执行完 `assert p` 之后要求的条件。所以最弱前置条件就是 \(p\) 成立并且 \(q\) 成立。大家想一想。

### assume 语句的最弱前置条件

**39:34**

接下来看 `assume`。对于 `assume`，我们也把它变成一行代码。假设 `assume p` 执行完之后，要求的后置条件是 \(q\)。那么我假设 \(p\) 成立，然后能推出 \(q\) 成立。它的最弱前置条件就是 \(p \to q\)，是不是？大家想一想这个有没有什么问题。先看一下这个例子；如果还不理解，我们再讨论。

### 回到霍尔逻辑的推导

**40:18**

我们可以线上直接讨论这个问题。上节课讲霍尔逻辑的时候，我们是怎么推的呢？\(a=1\)，执行 `a = a + 1`，`return a`，然后要求后置条件是 `result = 2`。这就相当于我要证明 \(a=1\) 能够推出什么；把 `result = 2` 作为后置条件，并且求执行完 `a = a + 1` 这段代码的最弱前置条件。本身就是要证明这个程序正确，对不对？这个问题应该没有问题。

### 从后置条件倒推最弱前置条件

**41:00**

这里的思路是：如果前置条件能推出这段代码的最弱前置条件，就说明程序满足要求。具体做法是从后置条件 \(result=2\) 开始倒推。先看 `result = a`：要使执行后 \(result=2\)，执行前必须有 \(a=2\)，所以把 \(a=2\) 作为它的后置条件。接着看 `a = a + 1`：把后置条件中的 \(a\) 替换成 \(a+1\)，得到 \(a+1=2\)。因此，需要证明前置条件 \(a=1\) 能推出 \(a+1=2\)。这一步成立，就证明了这个程序满足要求。

### 把 assert 和 assume 当作普通代码

**41:47**

再看右边这种实现方式。真正实现时并不是直接把 \(result=2\) 当作最终后置条件倒推，而是把 `assert result == 2` 也当作一条普通代码放进程序。这样它的默认后置条件就是 `true`。前面的 `assume a == 1` 同样作为普通代码放入。把 `assert` 和 `assume` 都作为程序中的一行代码后，再用同样的最弱前置条件算法去求，得到的结果与前面是等价的。为什么要做这种转换？从编译器实现角度看，把前置条件、后置条件以及代码都统一看成代码来执行，实现起来最简单、最统一。这里有一个实现上的技巧，下面说明为什么两种做法等价。

### 基本块与 AOK、BOK

**43:10**

为了简化，假设有两个基本块 \(c_1\)、\(c_2\)。把 \(c_1\) 的最弱前置条件记作 `AOK`，把 \(c_2\) 的最弱前置条件记作 `BOK`。如果 `BOK` 是 \(c_2\) 的前置条件，那么它应当成为 \(c_1\) 的后置条件。于是，要证明 \(c_1\) 没有问题，就是把 `BOK` 作为后置条件，与 \(c_1\) 一起推出 `AOK`。

具体分两步：第一步，证明 \(c_2\) 的最弱前置条件确实是 `BOK`；第二步，把 `BOK` 作为后置条件，把 `assume a == 1` 作为代码，推出 `AOK`。这里的 `BOK` 对应代码：先执行 `a = a + 1`、`result = a`，再执行由 `assert result == 2` 变成的普通代码。因为 `assert` 已经变成代码，它的默认后置条件是 `true`。

### 最弱前置条件的计算

**45:10**

用上节课的规则：
\[
wp(c_1;c_2,Q)=wp(c_1,wp(c_2,Q)).
\]
先求后一段代码的最弱前置条件：把 `assert result == 2` 作为代码，`true` 作为后置条件。对于 `assert P`，其最弱前置条件是 \(P \land Q\)；这里 \(Q=true\)，所以得到 \(result=2\)。接着把 \(result=2\) 作为后置条件，`result = a` 作为代码，得到 \(a=2\)。再把 \(a=2\) 作为后置条件，`a = a + 1` 作为代码，得到 \(a+1=2\)。这就是 `BOK`，也就是这段代码的最弱前置条件。

然后，把 \(a+1=2\) 作为后置条件，`assume a == 1` 作为代码，得到 `AOK` 为 \(a=1 \to a+1=2\)。这个蕴含式恒为真，所以 `AOK` 就是 `true`。因此，把 `assume` 和 `assert` 都作为普通代码放进来后，程序默认后置条件是 `true`；从 `true` 开始用最弱前置条件往上推，推出前置条件为 `true`，就说明程序没有问题。

真正实现中采用的就是这种办法：它仍然属于霍尔逻辑，但不是直接把断言作为后置条件倒推，而是把 `assert`、`assume` 当作代码，从默认后置条件 `true` 开始倒推。这样做的目的，是统一整个算法的实现。按上节课的思路和这种实现分别计算，得到的结果完全一致。

### if-else 的控制流图

**47:39**

对于 `if-else` 这种分叉的控制流图，做法是类似的。对于 `if-else`，先把各个分支的最弱前置条件取合取，作为汇合后的后置条件；再对前面的代码求最弱前置条件。

例如代码：
```
a = 1;
if (b == 0)
    a = a + 1;
else
    a = 2;
return a;
assert result == 2 || result == 3;
```
它的控制流图变成：判断 `b == 0`；成立时执行 `a = a + 1`，否则执行 `a = 2`；然后 `return`，最后是 `assert`。需要把前置条件放到最上面的基本块，把后置条件和 `assert` 放到返回值后面。

### 用 assume 表示 if-else 的分支条件

**49:20**

这里 `if (b == 0)` 实际上对应两种情况：如果 \(b = 0\)，就走这个分支；如果 \(b \ne 0\)，就走另一个分支。也就是说，可以进一步解析它的语义，把条件判断所在的位置变成一个 `skip`，即一个空的基本块。若执行 \(a = a + 1\)，其前提条件是 \(b = 0\)；若执行 \(a = 2\)，则加入 `assume(b != 0)`，这个条件也变成该分支的前提条件。

这样，在分析代码时把 `assume` 和 `assert` 作为代码语句放进来，好处是对于 `if-else` 可以很自然地把 `assume` 放到相应分支中：当 \(b = 0\) 时执行 \(a = a + 1\)，当 \(b \ne 0\) 时执行 \(a = 2\)。

### 用霍尔逻辑计算 if-else 的最弱前置条件

**00:08**

对于 else 分支，真正用霍尔逻辑进行推理时，会把 if 变成两个 assume，也就是两个前置条件：一个 assume \(b\ne 0\)，一个 assume \(b=0\)。然后先推出这个代码块的最弱前置条件。

首先它的后置条件是 true。这里分别有两行代码，涉及 \(result=2\)、\(result=3\)；把 true 作为后置条件，把这个代码块作为一个整体，它的最弱前置条件就变成 \(result=2 \lor result=3\)。

接着把 \(result=2\) 和 \(result=3\) 作为后置条件，把 \(result=a\) 作为代码，那么 EOK 的最弱前置条件就变成 \(a=2 \lor a=3\)。然后再算 DOK 的最弱前置条件，并把 EOK 作为它的后置条件。EOK 本身是 \(a=2 \lor a=3\)，这边是 \(a=2\)。

然后 \(b\ne 0\)，并且 \(a=2\)，这是它的代码块。如果仅求 \(a=2\) 的最弱前置条件，根据 EOK 的部分，就变成 \(a+2=2 \lor a+2=3\)，也就是做一个替换。把 \(a+2=2 \lor a+2=3\) 作为后置条件，用 \(b\ne 0\) 作为前置条件，那么最终前置条件就变成：根据前面讲过的规则，\(b\ne 0\) 能够推出 \(a+2=2 \lor a+2=3\)。

有了 DOK 之后，同理可以算出 C 的最终前置条件。这里既然一边是 \(b\ne 0\)，另一边就变成 \(b=0\)；\(b=0\) 能推出 \(a+1=2 \lor a+1=3\)，这是 \(a+1\)。

### if-else 的最弱前置条件

**08:19**

接着上面的 if-else 分析。两个分支分别把 \(a\) 改成 \(a+1\) 和 \(a+2\)。合并点 \(B\) 是一个 `skip`，它的后置条件要汇合两个分支的 \(C_{OK}\) 和 \(D_{OK}\)；因为 `skip` 不改变状态，所以对 `skip` 求最弱前置条件仍然得到这个后置条件。以 \(a=2\lor a=3\) 作为后置条件，对 \(a:=a+1\) 求最弱前置条件得到 \(a=1\lor a=2\)，对 \(a:=a+2\) 求最弱前置条件得到 \(a=0\lor a=1\)。

把 `assume` 也看成一行代码，从下往上推：\(b=0\) 时，`assume b=0` 的最弱前置条件是 \(b=0\to(a=1\lor a=2)\)；\(b\ne0\) 时，`assume b≠0` 的最弱前置条件是 \(b\ne0\to(a=0\lor a=1)\)。再与最上面的初始条件 \(a=1\) 合在一起，得到
\[
a=1\to\bigl((b=0\to(a=1\lor a=2))\land(b\ne0\to(a=0\lor a=1))\bigr).
\]
这个式子是永真式：当 \(a=1\) 时，无论 \(b\) 是否为零，相应的析取式都成立。这就是用霍尔逻辑从后向前计算最弱前置条件、做程序分析的过程。

### 循环示例与回边

**10:02**

下面进入循环部分，这是整个霍尔逻辑分析中最难的地方。老师说明：即使今天的内容最终纳入考试范围，循环这一部分也不会列入考试。

例子是：前置条件 \(a\ge100\)，执行 `while a > 0`，循环体为 \(a:=a-1\)，最后返回 \(a\)，后置条件为 \(a=0\)。把控制流图画出来后，循环条件成立时进入循环体，执行 \(a:=a-1\) 后再回到循环条件；条件不成立时退出。

按照前面 if-else 的做法，可以把循环条件分别写成 `assume a>0` 和 `assume a≤0`：前者进入循环体，后者走向出口。回边上的块可以看成一个 `skip`，但它回到循环头仍然形成环；把它当成 `skip` 并不能消除语义上的重复执行。直接去掉回边会改变程序语义：程序本来会反复执行 \(a:=a-1\)，去掉回边后就只执行一次。例如当 \(a>0\) 时做一次 \(a:=a-1\)，然后不再回到循环条件；当 \(a\le0\) 时直接退出。所以不能靠简单删掉环来保持语义。

### 循环不变量

**12:14**

为了在去掉回边时不改变语义，需要引入循环不变量。循环不变量是在 `while` 循环执行之前、执行过程中以及执行结束后都保持成立的性质。它必须在进入循环前为真，并且每次循环体执行后仍然为真，这样循环执行前后都能保持它。

这个例子的循环不变量是 \(a\ge0\)。之前曾尝试把它改成 \(a>0\)，但证明无法通过：循环退出时 \(a=0\)，不再满足 \(a>0\)。

引入 \(a\ge0\) 后，要把它插入到几个关键位置。首先，在进入循环之前，\(a\ge0\) 一定成立，所以在第一个块 `assume a≥100` 下面插入 \(a\ge0\)，表示进入循环前满足不变量。其次，执行完循环体后，要么回到循环头继续下一次循环，要么跳出循环；无论哪种情况，都要保持 \(a\ge0\)。因此也要把循环不变量插入到循环体之后、回边以及出口附近，使循环执行前后都能保持它。

### 把不变量放入基本块

**14:07**

在程序分析时，还会在循环的每个基本块前后加入循环不变量的断言。这样，在基本块内部执行代码时，循环不变量始终作为可用的前提和需要保持的结论。

具体做法是：把 `while` 循环的回边处理掉，使控制流图变成无环图；在循环入口、循环体前后、回边和出口这些位置放入循环不变量。例如在 `skip` 处，后置条件就是前置条件本身，因此可以在这里检查不变量是否成立。分析器会在循环的每个基本块前、后都加上循环不变量的保证，确保整个基本块执行完后不变量仍然成立。

在控制流图中，把 `while` 的判断和回边拆开，回边所在的位置可以看成一个 `skip`；再把循环不变量放到相关基本块前后，就可以去掉这个环。这样就能在去掉回边后，用循环不变量保留原来循环的语义。

**15:57**

不过这里还有一个问题。对 `while` 循环来说，循环入口处写的是 `assume a≥100`，这是整个程序最初的前置条件；但循环体执行一次并回到循环头时，只能保证循环不变量 \(a\ge0\)。由于循环体把 \(a\) 减 1，回到循环头时 \(a\) 可能已经小于 100，所以不能再保证最初的前置条件 \(a\ge100\)。因此，循环入口处的前置条件与回边传回来的条件并不一致，不能把两者直接当成同一个条件使用；这正是后面需要引入额外谓词来处理的地方。

### 引入 HAVOC 处理循环

**16:25**

这里要保证的循环条件是：如果循环不变量 \(I\) 成立，并且循环守卫 \(b\) 成立，那么执行循环体 \(c\) 后仍要能保证 \(I\) 成立。问题在于，这里的 assume 与后面的条件并不一致，所以不能直接把 assume 移除。外部循环里有一个比较棘手的地方。为了在霍尔逻辑中把循环建模完整，需要引入一个新的谓词。

**17:41**

这个新谓词记为 HAVOC。可以把 HAVOC 看成一个谓词，也可以把它看成一段代码或一个函数；它的含义是变量 \(a\) 可以取任意值。这样就能把循环表示出来。若执行完 `HAVOC a` 后要满足后置条件 \(q\)，那么它的前置条件应是：对任意 \(v\)，用 \(v\) 替换 \(q\) 中的 \(a\) 都成立，即

\[
\forall v\, q[v/a].
\]

因此，在循环前插入一行 `HAVOC a`，就表示 \(a\) 是任意变量；有了任意变量，才能表示 while 循环，循环的回边也就补全了。

### HAVOC 的语义与循环建模

**18:57**

例如，插入 `HAVOC a` 后，\(a\) 可以取任意值；接着写 `assume a ≥ 0`、`assume a > 0`，再执行 `a = a - 1`。这里引入任意变量能够表示循环，是因为 while 循环每一轮中 \(a\) 的状态都会变化：每一轮都相当于让 \(a\) 重新取任意值，只要满足前置条件，执行完循环体后仍满足后置条件。无论循环执行多少次，都不影响这一点。

`HAVOC` 本质上是通过一条指令对整个循环建模：无论执行多少次，\(a\) 都可以是任意变量；只要先 `assume a ≥ 0`，再 `assume a > 0`，执行 `a = a - 1`，后置条件都会成立。

### 把 while 循环化为无环控制流图

**20:31**

有了 `HAVOC` 之后，就可以把 while 循环的回边正式删掉。这样得到的基本块（basic block）和控制流图（control flow graph）就是没有回边的有向无环图，同时仍能表达原来的 while 循环。

对于带有循环不变量的 while 循环，本质上要做的事情就是想办法去掉回边。具体做法是：在基本块内部通过增加前置条件、后置条件来处理它，同时在前面增加一条 `HAVOC a`，用任意变量来表示循环。这样，只要对任意的 \(a\)，先满足 `assume a ≥ 0`，再执行 `a = a - 1`，后面就都会满足后置条件。

### 最弱前置条件与量词

**22:04**

接下来从后往前倒推。对于 DOK 这个块，后置条件是 true；执行完这三行代码后，倒推得到的前置条件是 \(a\le 0\)。结合循环不变量 \(a\ge 0\)，可以推出 \(a=0\)。

再把 DOK 作为后置条件、COK 作为前置条件，就得到：\(a>0\) 能推出 \(a-1\ge 0\)。注意，因为前面引入了 `HAVOC a`，所以从这一边倒着推，先得到该块的最弱前置条件，再继续推出整个程序的前置条件。推到 BOK 的最终前置条件时，由于其中有一个“任意 \(a\)”，最终前置条件会引入量词。

这也是为什么 while 循环求解时时间会比较长：求解过程中涉及 while 循环，对应的逻辑表示里就会出现量词。

### 用 assume 和 assert 参与程序证明

**23:08**

引入量词的原因在于，`HAVOC` 的语义就是：对任意的 \(a\)，只要它满足前面的条件，执行完这段代码后仍然满足后面的条件。这里涉及循环不变量。具体的推理规则前面讲过，但不作为考试内容。

有了 BOK 之后，再根据前面的式子就可以推出 AOK，最后得到相应的表达式。到这里，用霍尔逻辑证明一个程序的流程已经讲完：把 `assume` 和 `assert` 也作为一行代码插入控制流图，并引入两个新的规则。例如，假设后置条件是 \(q\)，那么 `assert p` 的最弱前置条件就是 \(p\land q\)。

### 循环与不变式

**24:35**

我们先推出最弱前置条件，再一步步往上推。对于 while 循环来说会稍微棘手一些：不仅要把 assert、前置条件和后置条件放进相应的基本块（basic block）中，还要把 while 的循环不变式（invariant）也加进来。与此同时，还要引入一个表示任意 v 的 ∀v。引入任意 v 之后，条件就变成：对任意的 v，假设前置条件成立，执行完循环体之后，循环不变式仍然成立。这样处理是可行的。

### 分离逻辑的引入

**25:51**

这个知识点叫分离逻辑（separation logic）。它建立在霍尔逻辑之上，是一个新的知识点。分离逻辑和前面的知识点相对独立，但都以霍尔逻辑为基础。先看分离逻辑要解决什么问题。

### 动态内存分配

**26:37**

大家用过 `malloc` 和 `new` 吗？在程序设计课、C/C++ 里应该都做过动态内存分配。看这个例子：`p = malloc(...)`，也就是申请一块内存；`int` 占 4 个字节，这里申请 10 个这样的单位，之后执行 `free(p)`。`malloc` 做的事情，就是让程序在运行时动态分配内存、动态生成变量。

### 程序的状态机抽象

**27:37**

这里有一个问题：无论是霍尔逻辑、命题逻辑还是谓词逻辑，我们对程序的抽象是什么？从最开始讲命题逻辑时，这一点就贯穿始终：我们把程序翻译成逻辑表达式，用来描述执行前和执行后的状态。执行前后的状态会变化，所以要把程序看成一个状态机。逻辑本身表示的是：执行一段代码之前的状态与执行之后的状态之间的关联关系。谓词逻辑是这样，霍尔逻辑更明显：用霍尔三元组的前置条件、代码和后置条件，直接描述执行代码之前程序应满足什么状态，以及执行完之后后置条件应满足什么状态。所以归根到底都是状态机问题。那么，有 `malloc` 这样的程序，给状态机抽象带来了什么挑战？

### 动态状态带来的挑战

**29:10**

首先，霍尔逻辑的验证是静态的。为什么说是静态的？因为在程序执行之前和执行之后，我们都会提前知道程序有哪些状态。举之前那个例子：已知程序的输入是 a，返回值是 result，需要知道它输入什么、返回什么。但还有另一种情况：程序的状态是在运行时动态生成的。假设一个程序的状态是在运行时动态分配出来的，那么霍尔逻辑就没有办法在执行之前用谓词逻辑表达式把这个状态表示出来，它的前置条件就写不出来。类似地，如果程序执行过程中有一句 `p = malloc(sizeof(int))`，执行之前其实不知道 p 指向哪里，也没有办法用谓词逻辑公式表示 p。最典型的例子是链表：程序分配一个链表，并不断往里面动态添加节点；执行之前并不知道这个链表会有多少个节点，也就没有办法用谓词逻辑描述这个链表处于什么状态。这些都是堆造成的。

### 堆与动态状态

**31:05**

大家知道堆（heap）这个概念。所有内存分配实际上都是在堆上进行的。比如 `malloc` 申请 4 个字节，它会在堆上找一块 4 字节的空间占用；之后再 `free`，例如释放 64 字节的空间。这就是堆的概念。分离逻辑本质上要解决的，就是当程序在堆上动态生成状态、动态分配内存，而这些内存又处于动态状态时，如何对这种东西进行建模。下面就是一个例子，这是一段伪代码。谁能解释一下这个函数干了什么？有同学说：删除节点，然后呢？

### 验证递归删除链表函数

**32:43**

这个函数并不只删除一个节点，而是递归地删除 \(x\) 以及 \(x\) 之后的所有节点，也就是把从 \(x\) 开始的整条链表删掉。若要对这个函数建模并验证它是否正确，前置条件应当是：\(x\) 是一条链表的头指针，或者 \(x\) 为空；删除完成后，这条链表所占的堆空间应当全部释放，对应的集合为空。进一步把前置条件写成关于 \(x\) 的表达式，就是“\(x\) 指向一条链表，或者 \(x\) 为空”。执行到 `if (x != null)` 分支后，可以知道 \(x\) 不为空；执行删除并返回后，\(x\) 及其后继节点所占的堆空间都不再存在，后置条件对应一个空堆。

### 霍尔逻辑的局限

**34:35**

接下来考虑：怎样用霍尔逻辑把上述状态变化表示出来？这里很难直接表示。原因在于函数是递归的，而且前置条件并不知道链表中究竟有多少个节点；这些节点是在运行时动态分配出来的，不运行程序就无法知道数量。因此，仅用前面学过的霍尔逻辑符号无法表达这种动态堆结构，需要引入一种新的逻辑——分离逻辑。

### 分离逻辑与堆断言

**37:08**

分离逻辑是在 2001 年前后从霍尔逻辑发展出来的，主要针对动态内存分配；随着 Java、C++ 等语言的使用，它变得非常通用。分离逻辑也可以用于并发程序的证明，但本课程不展开。这里先引入几个符号。第一个是 \(\mathrm{emp}\)，表示堆是空的。第二个是 \(x \mapsto y\)：\(x\) 是指针，表示 \(x\) 指向堆上的一个对象或节点，并且堆上为这个节点分配了一块空间；\(x\) 本身不是空指针，\(y\) 是该节点中相应字段的值。

### 分离合取

**38:08**

第三个符号是 \(f * g\)，读作“\(f\) 乘以 \(g\)”，称为分离合取。它的含义是：存在一个堆，可以把它分成两块不相交的内存，一块满足断言 \(f\)，另一块满足断言 \(g\)；\(f\) 和 \(g\) 都是分离逻辑的断言。这个运算符和普通的合取 \(\land\) 不同：\(f \land g\) 只表示 \(f\) 和 \(g\) 同时成立，二者可以描述同一个堆；而 \(f * g\) 要求 \(f\) 所描述的堆对象与 \(g\) 所描述的堆对象完全不相交。分离合取是分离逻辑中最重要的运算符。除了引入 \(\mathrm{emp}\)、\(\mapsto\) 和 \(*\) 这三个符号，其余部分与霍尔逻辑一致。

### 用分离逻辑表示链表

**39:59**

例如，要表示链表关系 \(x.next = y\)，可以先用 \(x \mapsto y\) 说明 \(x\) 指向堆上的一个节点，且该节点的 next 指针等于 \(y\)。如果还要说明 \(y\) 指向堆上的另一个节点，就用分离合取把 \(x \mapsto y\) 与描述 \(y\) 所指节点的断言相乘。这里的 \(*\) 表示 \(x\) 和 \(y\) 所指向的是堆上两个不相交的部分，同时 \(x\) 的 next 指针保存的地址与 \(y\) 相同。

### 分离合取与普通合取的区别

**41:09**

这个式子表示：\(x\) 和 \(y\) 分别指向堆上不同的对象，并且 \(x.\text{next}=y\)。因此它描述的链表结构是：\(x\) 所在结点的 next 指向 \(y\) 所在结点。

如果把它改写成 \(\mathrm{ACC}(x)\land \mathrm{ACC}(y)\land x.\text{next}=y\)，含义就不同。\(\mathrm{ACC}(x)\) 和 \(\mathrm{ACC}(y)\) 用普通合取连接，表示 \(x\)、\(y\) 指向堆上的同一个对象；于是 \(x.\text{next}=y\) 就变成这个对象的 next 指向它自己，形成自环。分离合取 \(*\) 则要求左右两部分描述不同的堆对象：\(\mathrm{ACC}(x) * \mathrm{ACC}(y)\) 表示 \(x\) 和 \(y\) 指向不同对象。

### 链表的递归谓词

**42:46**

用递归方法形式化链表谓词。设 \(\operatorname{list}(x)\) 表示 \(x\) 指向一个链表。分两种情况：\(x=\mathrm{null}\) 时链表为空，对应空堆 \(\mathrm{emp}\)；\(x\ne\mathrm{null}\) 时，\(x\) 指向链表头结点，\(x.\text{next}\) 指向剩余链表。因此可定义为
\[
\operatorname{list}(x) \triangleq (x=\mathrm{null}\land \mathrm{emp}) \lor (x\ne\mathrm{null}\land \mathrm{ACC}(x) * \operatorname{list}(x.\text{next})).
\]
这里 \(*\) 很关键：左边 \(\mathrm{ACC}(x)\) 描述 \(x\) 指向的头结点，右边 \(\operatorname{list}(x.\text{next})\) 描述剩余内存区域，二者必须是不相交的堆区域。这样就能用递归方式把链表表示出来。

### 分离逻辑能检查什么

**44:56**

引入分离逻辑后，不仅能证明前置条件和后置条件，还能检查越界访问、释放后使用（use after free）、重复释放（double free）等内存安全问题。先看一个成立的三元组：
\[
\{\mathrm{ACC}(x)\} \quad x.\text{next}=y \quad \{\mathrm{ACC}(x)\land x.\text{next}=y\}.
\]
这个三元组成立：前置条件保证 \(x\) 已分配并指向堆上一个对象；执行 \(x.\text{next}=y\) 后，\(x\) 仍指向该对象，且其 next 指针为 \(y\)。

### 缺失分配前提的例子

**45:54**

再看一个不成立的霍尔三元组：
\[
\{\mathrm{ACC}(y)\}\quad x.\text{next}=y\quad \{\mathrm{ACC}(y)\land x.\text{next}=y\}.
\]
按之前学过的推理规则，似乎可以由前置条件推出后置条件，但在分离逻辑中它不成立。原因是 \(x\) 虽然被当作堆指针使用，前置条件却没有保证 \(x\) 已被分配；分离逻辑会报错，指出 \(x\) 可能指向未分配的内存。要让它成立，前置条件中必须包含 \(\mathrm{ACC}(x)\)。

### 分配结点

**47:07**

例如分配结点的三元组
\[
\{\mathrm{emp}\}\quad x=\text{new node}\quad \{\mathrm{ACC}(x)\},
\]
是成立的：初始堆为空，执行分配后 \(x\) 指向堆上一个新对象。这里同样要求 \(x\) 被正确分配。

### 释放操作

**47:29**

若前置条件为 \(\mathrm{emp}\)，也就是堆上没有任何已分配对象，却执行 \(\text{free}(x)\)，该三元组不成立，因为 \(x\) 没有对应的已分配对象；分离逻辑会检查出这个问题，也能暴露 double free 一类错误。正确的释放写法是：
\[
\{\mathrm{ACC}(x)\}\quad \text{free}(x)\quad \{\mathrm{emp}\}.
\]
前置条件保证 \(x\) 已指向堆上一个对象，释放后堆为空。

### 把结点接入链表

**48:17**

再看把结点接入链表的例子。设 \(x\)、\(y\) 都是堆上的指针，执行 \(x.\text{next}=y\)。前置条件应包括 \(\mathrm{ACC}(x)\)、\(\mathrm{ACC}(y)\)，以及 \(y.\text{next}=z\)：\(x\) 指向一个对象，\(y\) 指向另一个对象，并且 \(y\) 的 next 为 \(z\)。于是有：
\[
\{\mathrm{ACC}(x)*\mathrm{ACC}(y)\land y.\text{next}=z\}\quad x.\text{next}=y\quad \{\mathrm{ACC}(x)*\mathrm{ACC}(y)\land x.\text{next}=y\land y.\text{next}=z\}.
\]
这个霍尔三元组说明：可以成功分配一个结点，并把它放到堆上、接入链表。后置条件同时描述 \(x\) 的状态、\(y\) 的状态以及链表中指针的变化。

### 分离逻辑与内存安全

**49:29**

分离逻辑自带语义，它本身就是用来描述堆的。因此，它不仅能理解 free、new 这类操作，还会把这些操作与其前置条件结合起来检查：是否存在内存安全问题，例如 double free、use-after-free、空指针等。
