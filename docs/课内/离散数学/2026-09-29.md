### 先判定合式公式，再转换成范式

**09:18**

求解的第一步是检查这个表达式是否为合式公式。这回应了上节课关于什么样的表达式才是合法的合式公式的内容。合式公式的定义是：原子命题是合式公式；如果 \(A\) 和 \(B\) 是合式公式，那么 \( \neg A \)、\( A \land B \)、\( A \lor B \)、\( A \to B \)、\( A \leftrightarrow B \) 也都是合式公式；除了这些形式以外都不是合式公式。根据这个递归定义，就可以自动判定一个表达式是否为合式公式。

判定为合式公式之后，接下来要把它转换成合取范式（CNF）或析取范式（DNF）。我们学过 CNF 和 DNF。

### CNF 与 DNF 的区别；辅助变量

**10:18**

CNF 和 DNF 的区别是：合取范式（CNF）的子句内部是析取，子句之间是合取；析取范式（DNF）反过来，子句内部是合取，子句之间是析取。

这里有一个非常重要的知识点，这节课还会用到：为什么最终送入 SAT 求解器的是 CNF 而不是 DNF？这是因为转换时可以引入辅助变量。引入辅助变量后，只需要满足可满足性等价，而不要求完全等价。这样转换出来的式子虽然在逻辑上不一定与原式完全等价，但可满足性保持一致，同时 CNF 表达式可以变得更简单。上节课也举过例子说明为什么引入辅助变量：目的就是保持可满足性等价。

### DPLL 的基本步骤与优化

**15:23**

基本思路是：给定一个 CNF 表达式，先猜一个变量为 true 或 false，然后根据猜出的值去推断其他变量的值。一旦推出某个子句为 false，就说明最初的猜测是错的，需要重新猜。

猜测当然可以有一些优化方式。例如，如果某个命题变量在所有子句中都只以正文字出现，没有 \( \neg P \)，那么猜的时候就不必猜它为 false；直接令它为 true 就可以。因为它为 false 对“所有子句为真”这件事没有任何作用。所以基本步骤就是：第一步猜，然后根据猜的值推断其他命题变量的值，再重新猜。

下面用之前的标准 CNF 表达式例子再走一遍。我先猜 a 是什么？假设 a 为 false。

### decision literal 与 unit propagation

**16:39**

先看 \(a\) 是 true 还是 false。我们继续要猜。这个时候如果猜 \(a\) 是 false，就要把 \(a\) 标记成 decision literal。decision literal 表示这个值属于猜测：我只猜了它的一个值，还没有两个值都遍历过。所以 \(a\) 是 decision literal。

然后我会根据 \(a\) 来推断其他命题变量的值，这个规则叫 unit propagation。什么是 unit propagation？就是每个这样的子句，我管那个叫一个 unit。根据这个子句，如果要满足每个子句必须为 true 的要求，就可以尝试推断其他命题变量到底应该是 true 还是 false。

### unit propagation 的作用

**17:24**

比如 \(a\) 是 false，那么 \(b\) 一定也是 false，因为要让相应子句为 true。\(b\) 是 false，那么 \(c\) 也一定是 false，因为要让相应子句为 true。这个叫 unit propagation 规则。

当推出 \(a\) 是 false、\(b\) 是 false、\(c\) 也是 false 时，最后一个子句自然就一定是 false。这个子句为 false 说明整个式子为 false。也就是说，如果 \(a\) 是 false，整个式子不可满足。所以如果存在一个可满足解，\(a\) 一定不是 false。

### 回溯与不可满足

**18:10**

于是知道之前 \(a\) 猜错了，所以要 backtrack，回到 \(a\) 重新猜 \(a\)。如果 \(a\) 的 true 和 false 都猜完，仍然出现 conflict，那整个式子不可满足，我就不用再猜了。这就是这样一条规则。

### pure literal 规则

**18:38**

假设重新猜。刚才 \(a=false\) 肯定不对，现在猜 \(a\) 是 true。如果 \(a\) 是 true，那么这两个子句就是 true。然后我再猜 \(b\) 是什么。\(b\) 是 true 就继续。

这里有一点：整个子句里面 \(a\) 这个值本身只有正的，没有 \(\neg a\)。所以如果让整个式子可满足，让 \(a\) 是 true，可以使得找到一个可满足解的概率最大。因此这里有一个 pure literal 规则：当所有子句里面只存在 \(a\)、没有 \(\neg a\) 时，直接让 \(a\) 设为 true 就可以了，不用猜。这是上节课的一个案例。

### 四变量的 CNF 例子

**19:47**

这是仅仅针对 SAT solver 或者 DPLL 场景下的写法。假设有四个变量 \(p_1,p_2,p_3,p_4\)，把 \(p\) 省掉，写成 1、2、3、4。1 上面有个小横杠表示 \(\neg p_1\)，2 上面有小横杠表示 \(\neg p_2\)。这个表达式实际上表示它是一个 CNF，但是把中间的合取 and 去掉了。去掉之后写成这样的形式：

\[
(\neg p_1 \lor \neg p_2) \land (p_2 \lor p_3) \land (\neg p_1 \lor \neg p_3 \lor p_4) \land (\neg p_3 \lor p_4) \land (p_2 \lor \neg p_3 \lor \neg p_4) \land (p_1 \lor p_4)
\]

这就是一个 CNF 表达式。我只是简化成这样的形式。根据 DPLL 最原始那篇论文作者的写法，我用这样的写法来求解。现在尝试用 DPLL 算法求解这个式子是否可满足。第一步，

### 尝试 p1 为 true

**21:03**

现在什么都不知道，所以先猜一下。左边表示整个计算的推理过程。第一步假设 \(p_1\) 是 true。

如果 \(p_1\) 是 true，那么 \(p_2\) 一定是 false，因为第一个子句是 \(\neg p_1 \lor \neg p_2\)。紧接着，如果 \(p_2\) 是 false，根据第二个子句 \(p_2 \lor p_3\)，\(p_3\) 一定是 true。然后再根据 \(p_1\) 是 true、\(p_3\) 是 true，根据第三个子句 \(\neg p_1 \lor \neg p_3 \lor p_4\)，推出 \(p_4\) 是 true。

这样推出：假设式子可满足，如果猜 \(p_1\) 是 true，那么 \(p_2\) 一定是 false，\(p_3\) 一定是 true，\(p_4\) 一定是 true。由这个结论，就能推出子句 \(p_2 \lor \neg p_3 \lor \neg p_4\) 是 false。如果这个子句是 false，那么说明 \(p_1\) 这个猜测怎么样？我们猜它是 true 是错的。如果式子可满足，\(p_1\) 一定不是 true。所以反过来知道，

### 改猜 p1 为 false

**23:08**

如果可满足，那么 \(p_1\) 一定是 false，就直接按照 false 去推。这时 \(p_1\) 之前已经猜过一次了；一个变量只会取两个值，猜过一个值，只剩一个。所以第二次它就不再是 decision literal。去掉剩余值之后，看 \(p_1\) 是 false。第一个子句本身就变成 true，所以不用管。

但是根据最后一个子句 \(p_1 \lor p_4\)，能推出 \(p_4\) 是 true。\(p_4\) 是 true，那么第三个子句也不用管了。如果 \(p_1\) 是 false、\(p_4\) 是 true，第一个子句和第三个子句已经为 true。

看剩下的子句，也没有推理空间。比如有些子句里有三个文字，且不包含 \(p_1\)、\(p_4\)，而我们已经根据已推出的值处理了。

### 找到可满足解与唯一性问题

**24:10**

所以需要重新猜。剩下的子句是 \(p_2 \lor p_3\) 以及 \(p_2 \lor \neg p_3 \lor \neg p_4\)。可以直接猜，比如猜 \(p_3\) 是 false。如果 \(p_3\) 是 false，根据 \(p_2 \lor p_3\) 就能推出 \(p_2\) 是 true。

这就找到了一组可满足解，求解结束。下一个问题是：根据这样的算法，让一个式子找到的可满足解是不是唯一的？使用 DPLL 算法，给定一个 CNF，它找到的值是否唯一？

### 可满足解是否唯一

**25:00**

关于 DPLL 找到的可满足解是否唯一，认为唯一的一方可以举例，认为不唯一的一方也可以举例。好，那就你来说。这要看具体的算法实现：在需要猜测时，有两个可以猜测的选项，具体取决于算法怎么写。一般算法里会默认按某种规则来猜，比如在这个题中，有多个变量可以猜。后面 \(P_2\) 和 \(P_3\) 都可以猜，猜不同的值就会得到不同的结果。

同一个表达式，猜测的顺序以及每个变量具体猜成哪个值，结果都不是唯一的。所以刚刚这个答案非常标准。我们再回顾之前那个 matching problem，回到最开始举的例子。我们会发现这门课最后一节课会和数学逻辑相呼应。

### 回顾 matching problem

**26:09**

最后一节课会和我们第一节课首尾相扣。这样我们开始这个 matching problem：Tom 想吃鸡或者牛奶，Tom 和 Jerry 想吃鸡或者奶酪，小不点想喝牛奶。我们要找到一个匹配方案，使得三个人不会冲突，并且每个人都有东西吃。

当时给了一个命题逻辑表达式。\(P_3\) 成立，因为小不点一定要喝牛奶。\(\neg P_1 \lor \neg P_2\) 等价于 \(\neg(P_1 \land P_2)\)，表示 Tom 和 Jerry 不能同时吃鸡。另一个条件是 \(\neg(\neg P_1 \land P_3)\)，展开就是 \(P_1 \lor \neg P_3\)，表示 Tom 和小不点不能同时喝牛奶。

也就是说，Tom 和小不点不能同时喝牛奶。这就是最开始展示的 matching problem 的式子。那具体怎么算呢？在 DPLL 里面，首先找到一个可以使得这个式子可满足的分配方案。

### 用 DPLL 求解 matching problem

**27:25**

\(P_3\) 自己是一个单独子句。所以如果这个式子可满足，\(P_3\) 一定为 true。然后看所有子句，\(P_2\) 取 false 时整个式子更容易满足，所以先猜 \(P_2\) 为 false。

同时，\(P_3\) 是单独子句，所以 \(P_3\) 肯定是 true。根据 \(P_2\) 为 false、\(P_3\) 为 true，可以推出 \(P_1\) 一定是 true；这样才满足第三个子句。最后得到这样的分配方案：\(P_2\) 为 false，即 Jerry 吃奶酪；\(P_1\) 为 true，即 Tom 吃鸡；小不点喝牛奶。

### DPLL 求解步骤演示

**31:38**

首先第一步，有一个一般性的预处理：看所有子句里面，比如 \(P_4\) 只以肯定形式出现，只有 \(P_4\)，没有 \(\neg P_4\)，没有否定，所以就把 \(P_4\) 直接设置成 true。

然后我们再去猜，一个个去猜。从第一个子句往后看，第一个子句的第一个变量是 \(P_1\)，那么 \(P_1\) 就可以直接猜成 true。如果 \(P_1\) 为 true，那么根据第二个子句推出 \(P_2\) 为 false。蓝色表示在这一步已经可以使这些子句为真。

\(P_2\) 为 false 之后，再根据子句 \(P_2 \lor P_3\)，由 \(P_2\) 为 false 推出 \(P_3\) 为 true。这样之前猜的 \(P_2\) 为 false、\(P_3\) 为 true。但这时某个子句成为矛盾子句，说明最开始对这个 decision variable 的猜测是错的，需要把之前的 decision variable 去掉，把 \(P_1\) 改成 false。这有点像回溯。

把 decision variable 后面的全部 pop 出去，因为后面的赋值都依赖于这个 decision variable。pop 之后只留 \(P_4\)，因为 \(P_4\) 没有问题，没有受到当时对 \(P_1\) 猜测值的影响。

### 回溯后的推导与不可满足判定

**33:14**

接着看原来的猜测：一开始把 \(P_1\) 猜为 true，这个猜测是错的，于是把 \(P_1\) 改成 false。\(P_1\) 为 false 之后可以推出 \(P_2\) 为 false，接着又推出 \(P_3\) 为 false，这时就发现子句 \(P_2 \lor P_3\) 没有办法满足。而到这里为止，所有取值都不是猜出来的，没有重新引入任何决策变量，全部是推导得到的结果。出现这种情况就说明该式子不可满足。

### 建模示例：聚会问题

**34:22**

最后把所有内容汇总到一个大的例子中。这是一个 dating problem，也可以看成 meeting problem。人物有痞老板，他的老婆是一台电脑；蟹老板和他的女儿，女儿是一条鲸鱼；还有派大星、海绵宝宝；以及驾校老师泡芙，还有松鼠 Sandy，她是一个宇航员。现在一共有四组，每组需要派出一个代表来参加这个聚会。

约束条件是：

- 有些两个人不能同时参加。比如两位竞争对手，见面就掐架；海绵宝宝和泡芙老师也不能同时参加，因为海绵宝宝每次去学车都会出事故，把泡芙这条小河豚气炸。
- 蟹老板暗恋泡芙，所以如果泡芙老师参加，那么蟹老板也想参加。
- 类似地，如果 Sandy 想参加，那么海绵宝宝也想参加。

老师请大家花一点时间想一想：怎样用命题逻辑对这个聚会问题进行建模。只需要建模，不需要求解。

### 同学给出的建模思路

**37:54**

老师请同学起来回答建模思路，并说明不用写下来，讲思路就可以。

同学的思路是：用 \(a\)、\(b\)、\(c\)、\(d\) 来表示相关的人物。痞老板和他老婆不能同时参加，写成 \(\neg(a \land c)\)；同理，另一组不能同时参加的约束写成 \(\neg(b \land d)\)。此外还要加上两个蕴含关系：由 \(d\) 可以推出 \(c\)，由 \(d\) 也可以推出 \(b\)。

老师接着改用更习惯的 \(p_1、p_2、p_3、p_4\) 来重新表述这个建模。

### 用 p₁ 到 p₄ 重新建模

**39:03**

每个组只有两个人，所以每一组完全可以用一个布尔变量表示：\(p_1、p_2、p_3、p_4\) 都取 true 或 false，true 表示参加、false 表示不参加。例如 \(p_1\) 为 true、\(p_2\) 为 false，就表示组里这个人参加、那个人不参加。

“不能同时参加”的约束写成：

\[\neg(p_1 \land p_3) \land \neg(p_2 \land p_4)\]

也就是 \(p_1\) 和 \(p_3\) 不能同时为 true，\(p_2\) 和 \(p_4\) 也不能同时为 true。

此外还有两条蕴含关系：如果 Sandy 参加，那么海绵宝宝也想参加；如果泡芙老师参加，那么蟹老板也想参加。写成命题逻辑就是：

\[p_4 \to p_2 \qquad p_4 \to p_3\]

这就是整个问题的建模。

### 合式公式检查与 CNF 转换

**40:23**

有了建模之后，剩下的就可以扔到 SAT solver 里面去求解了。这里把之前学过的内容重新串一遍。第一步是先 check 它是不是一个合式公式。合式公式的定义是：原子命题是合式公式；如果 \(A\)、\(B\) 是合式公式，那么 \(\neg A\)、\(A \land B\)、\(A \lor B\)、\(A \to B\)、\(A \leftrightarrow B\) 也都是合式公式。上面这个表达式显然是合式公式。

确认它是合式公式之后，第二步要把这个式子转换成一个 CNF 表达式。大家可能不太记得我们用什么方法来转换，接下来就来看这个转换过程。

### 从等值公式到 CNF

**41:17**

我们之前学过等值公式。等值公式就是把一个命题逻辑表达式或符号转换成与它等值的符号，然后逐步化简。其中有很多定理可用。首先，因为 CNF 和 DNF 里不允许出现箭头，所以要把所有的双箭头和单箭头去掉。例如，\(p_4 \to p_3\) 等价于 \(\neg p_4 \lor p_3\)，以此类推。类似地，某个式子可以化为 \(\neg p_4 \lor p_2\)；对另外两项，把否定词移进括号，并用“且变成或”，得到 \(\neg p_1 \lor \neg p_4\)、\(\neg p_2 \lor \neg p_4\)。再处理双重否定，例如消去 \(\neg\neg p_4\) 后得到 \(p_4 \lor p_3\)，其他不变，最后就得到标准的 CNF 表达式。

得到 CNF 表达式后，下一步是用 DPLL 算法进行求解。之前包含 \(p_1\)、\(p_3\) 等的式子，最终可以写成用于 DPLL 求解的形式。

### DPLL 求解与匹配方案

**42:47**

在 DPLL 中，这个 CNF 表达式由若干子句合取而成，例如 \(\neg p_1 \lor \neg p_3\) 等。首先观察到，命题变元 \(p_1\) 在所有子句里只出现在第一个子句中，并且以否定的形式出现，因此可以直接令 \(\neg p_1\) 为真，也就是令 \(p_1\) 为 false。这样第一个子句就为 true。接下来，对后面的式子先猜 \(p_3\) 为 true；如果 \(p_3\) 为 true，再去猜 \(p_2\) 为 true。若 \(p_2\) 为 true，根据相应子句，\(p_4\) 一定为 false；\(p_3\) 为 true 使某个子句为真，\(p_2\) 为 true 也使某个子句为真。只剩最后一个子句时，令 \(p_4\) 为 false，就可以使所有子句都可满足。

在赋值 \(p_1=false, p_2=true, p_3=true, p_4=false\) 下，对应的匹配是：\(p_1\) 为 false；\(p_2\) 为 true，海绵宝宝参加；\(p_3\) 为 true，蟹老板参加；\(p_4\) 为 false，珊迪参加。这个方案满足条件。其中“泡芙没有参加、蟹老板参加”这个命题仍然成立，因为 false 可以推出任意命题。这样我们就找到了一个匹配方案。

### 从命题逻辑到程序分析

讲完命题逻辑，我们回顾一下整个命题逻辑的内容。到目前为止，我们已经完成了“什么是命题逻辑”以及“如何求解一个命题逻辑表达式”的全部知识点。接下来要讲的是，如何给一个程序建模，把它转换成命题逻辑表达式。这件事其实并不难，可以结合之前举过的例子：章鱼哥和海绵宝宝去送披萨，结果迷路了，一直走，终于快要送到了。最开始他们不知道送什么，或者刚起步时，我们用真值表对整个命题逻辑表达式，或者说对命题逻辑的语法进行语义建模；第二步是用命题的等值公式指导如何化简；第三步是用 SAT solver 自动求解；最后是程序分析，即把程序转换成 SAT 表达式来做这件事。

程序分析要做的事情，是用 SAT 的基本方法来做程序分析，也就是把程序转换成命题逻辑表达式，再转换成 SAT。刚刚那个 CNF 程序就可以转成 CNF，扔到 SAT 里面去求解，这是本质。为什么要把程序转成 SAT？为什么 SAT 是程序验证最基础的东西？因为二者之间有一个非常好的对应关系：程序里面的每个 bit，即 0 和 1，刚好对应 true 和 false，两个都是二值空间。命题逻辑不是为验证程序而发明的，它的历史比计算机还要悠久，是离散数学的一部分；但刚好二者之间有完美的映射关系，所以在做程序分析时会转换成用命题逻辑来求解。下面先关注一个非常简单的案例，看看这个程序在干什么。

### 异或的复习

**05:10**

再复习一下异或：若 \(a\) 和 \(b\) 的值相同，则返回 false；若值不同，则返回 true。

那这是异或。把它转换成命题逻辑，真值表比较小，它的主要挑战是什么？挑战在于 \(a = a \oplus b\)。异或很容易用命题逻辑的联结词表示出来；之前已经有一张专门做异或的真值表，其实很简单。

### 程序状态的变化

**06:33**

难点在于 \(a\) 的值随着执行时间发生变化，也就是说它具有时间上的变化。比如等号右边的 \(a\) 和等号左边的 \(a\) 不是同一个 \(a\)。命题逻辑表达式只表示命题变项之间的关系，没有能力表示随着程序执行，变量以及变量值的变化。这是命题逻辑不具备的，也是这里的主要挑战。

那怎么做？我们有布尔变量 \(a\) 和 \(b\)，很自然会把它和命题变项联系起来，用 \(P_A\) 和 \(P_B\) 表示。但只用 \(P_A\) 和 \(P_B\)，无法表示在执行 \(a = a \oplus b\) 之前和之后它们之间的变化。

因此需要一种新的建模方法。这个建模方法本质上要把整个程序的执行过程看成程序状态的变化：在执行一条指令之前是一个状态，执行之后是另一个状态。也就是说，用两个不同的命题变项来区分执行 \(a = a \oplus b\) 这句话之前 \(a\) 的值和之后 \(a\) 的值。接下来看怎样区分。

### 用命题变项表示程序状态

**08:32**

程序开始执行、还没有执行任何代码时，\(a\) 和 \(b\) 的值分别用命题变项 \(a_0\)、\(b_0\) 表示，即初始状态为 state 0。执行第一条语句 \(a = a \oplus b\) 后，程序状态变为 \(a_1\)、\(b_1\)。其中 \(a_1 = a_0 \oplus b_0\)，而 \(b_1 = b_0\)。异或可以用命题联结符表示：上一节讲联结符完备性时已经知道，\(p \oplus q \equiv (p \land \neg q) \lor (\neg p \land q)\)，因此这里可以用该式来连接。

### 逐步记录程序状态变化

**10:02**

接着执行第二条语句 \(b = b \oplus a\)。执行后得到 \(b_2 = b_1 \oplus a_1\)，而 \(a_2 = a_1\)。第三条语句是 \(a = a \oplus b\)，执行后 \(a_3 = a_2 \oplus b_2\)，\(b_3 = b_2\)。也就是说，程序中每执行完一条指令，就把整个程序状态与上一条指令执行前的状态用命题联结符连接起来，表示执行前后状态之间的逻辑关系。例如，\(a_1 = a_0 \oplus b_0\) 而 \(b_1\) 不变，所以 \(b_1 = b_0\)；到第二条语句，\(b_2 = b_1 \oplus a_1\)，而 \(a_2\) 不变，所以 \(a_2 = a_1\)。这样就可以用命题逻辑表达式表示整个程序执行过程中程序状态的变化。命题逻辑本身并没有直接表示程序执行过程中状态变化的能力，因此需要引入这些表达式，在执行一条指令之前和之后，把状态变化的关系明确表示出来。

### 写出 swap 的各步等价式

**11:52**

有了这些表达式之后，最后要证明的是 swap 成功。所谓 swap 成功，就是最终 \(a_3 = b_0\)，并且 \(b_3 = a_0\)。为此，先写出各条指令对应的等价式。第一条：\[a_1 \equiv (a_0 \land \neg b_0) \lor (\neg a_0 \land b_0)\] 且 \(b_1 \equiv b_0\)。这里用等价表示两边真值相同。第二条类似：\(a_2 \equiv a_1\)，\[b_2 \equiv (a_1 \land \neg b_1) \lor (\neg a_1 \land b_1)\]。第三条：\(a_3\) 等价于 \(a_2 \oplus b_2\) 展开后的式子，即 \[a_3 \equiv (a_2 \land \neg b_2) \lor (\neg a_2 \land b_2)\]，且 \(b_3 \equiv b_2\)。

### 证明目标是永真式

**13:11**

接下来要推出的是：如果上面这些式子都成立，那么应能推出 \(a_3 \equiv b_0\) 且 \(a_0 \equiv b_3\)。也就是说，要证明“上面这些条件 \(\to\) 这个结论”这个式子是一个永真式。问题是：SAT solver 适合用来证明永真吗？不能，为什么？

### SAT solver 与 CNF

**14:02**

因为 SAT solver 只能求出有没有解，也就是判断可满足性；它的输入是 CNF（合取范式），而不是直接判断永真。CNF 是若干子句的合取。要证明一个式子永真，需要证明在所有赋值下整个式子都为真；这对 SAT solver 来说并不直接。SAT solver 比较适合处理可满足性和矛盾：如果可满足，它能给出一个解；如果要证明矛盾，则要证明不存在任何赋值使式子为真。对于 CNF，如果在所有赋值下总会有某个子句为 false，那么整个式子就是不可满足的，也就是矛盾式。因此一般证明永真时，思路会转向证明矛盾。

### 用矛盾证明永真

**14:52**

所以要证明 \(p\) 永真，我们通常会证明 \(\neg p\) 是矛盾式。对于程序验证：要证明一个程序永远正确，就把程序对应的公式取反，然后证明取反后的公式永远是矛盾式。这里有一个问题：如果发现 \(\neg p\) 不是矛盾式，而是可满足的，说明什么？说明程序不正确；存在一个解释使程序为 false，也就是 assertion 为 false。

### 反例与程序 bug

**15:43**

也就是说，存在这样一个解，这个解就是触发程序 bug 的那个 test input。因此，要证明左边程序永真，就转化为证明右边的式子矛盾，或者永远不可满足。取反之后，蕴含 \(P \to Q\) 就变成了合取 \(P \land \neg Q\)，结论上带一个否定词。如果这个式子可满足，就说明我们有一个反例，使这个程序本身是错的。现在把这个式子直接输入 SAT solver 来检查。

还有就是：程序中有 if \(a\) 则 \(x = \text{true}\)，否则 \(x = \text{false}\)；if \(b\) 则 \(y = \text{true}\)，否则 \(y = \text{false}\)；最后 assert：\(x\) 是 true 或者 \(y\) 是 true。

### integer 与 bit 级建模

**25:28**

接下来讨论 integer。程序语言中的变量类型不只有 bool，还有 integer；此外还有 control flow 等，更复杂的情况后面再考虑，会更难一些。以 swap 为例：对布尔变量，swap 成立；对 integer，swap 仍然成立，因为可以对每个 bit 做异或操作。问题是怎么把它转换成命题逻辑。思路和之前处理布尔问题一样：程序执行完之后，程序状态发生变化，用命题逻辑表达式表示变化前和变化后状态之间的关系。区别在于，以前程序状态是布尔变量，现在 \(a\)、\(b\) 变成了 integer。用命题变量表示 32 位的 integer 其实很简单：做 32 个命题变量，每个命题变量表示其中一个 bit。也就是说，\(a\) 有 32 个 bit，\(b\) 有 32 个 bit，对于某个状态，\(a\) 和 \(b\) 就分别用这样一组命题变量表示；这其实就是 32 位整数的表示方式。

### operator 与 loop 的处理

**27:51**

此外，语言里还有很多 operator，比如各种逻辑 operator、bit operator。本质上它们都可以转换成命题逻辑，原因是这些 operator 最后都落在变量的每一个 bit 上；只要用命题逻辑符号建模这些 operator 对 bit 级别的操作，就可以对这些 operator 进行建模。最后还有 loop。对于循环，例如 \(i=3\)，while \(i>0\)，静态看代码就可以看出它循环三次。这种循环代码要转换成命题逻辑表达式，可以把 loop 展开（unroll）三次。但还有一类循环，其循环次数事先不知道，取决于输入；这种循环用命题逻辑、包括后面要学的谓词逻辑都解决不了。这就是为什么还要学第三部分霍尔逻辑，专门解决带循环变量的程序如何证明的问题。

### 程序正确性证明的整体流程

**29:54**

最后做一个大的 summary。我们拿到一个程序，最终要证明这个程序的正确性，到底应该怎样做？首先，要对这个程序的整个执行过程进行建模。建模方法是：每一个 bit 都用一个命题变量表示；例如 integer 可以变成 32 个 bit。用命题变量对程序变量建模之后，就可以用多个命题变量组合起来表示整个程序的状态。然后，用命题联结词对程序里面的 operator 进行建模。刚才说的所有算法其实都可以自动完成，后面会讲怎样自动去做；在命题逻辑这个板块里先不展开。用命题联结词把状态和状态之间的转换或者计算表示出来之后，就可以用命题逻辑表达式表示转换之前和转换之后两个状态之间的关系。转换成关系之后，就可以转换成一个命题逻辑表达式。后面要证的是：程序最终跑出来的状态满足某一个断言，叫 assertion。这个 assertion 我第一节课应该给大家讲过，是图灵在 1949 年提出来的。我要证的是这个式子永远满足这个 assertion；本身来讲，就要证非 assertion 这个命题与整个程序所代表的表达式的合取是不可满足的，用 SAT solver。如果它可满足，就找到这样一个 counterexample；如果不可满足，就证明它是对的。

### Firefox 安装包的依赖与冲突

**35:24**

以安装 Firefox 为例。安装包会带有版本信息，其中有几个关键字段：软件包本身，例如浏览器 firefox；它的可选项；它属于哪个 metadata；版本号；由谁提供（provider）。紧接着还有一个 depends 字段。其实所有软件都有依赖，Windows 也有，只不过 Windows 把信息隐藏了，而 Linux 会显式展示出来。

depends 表示：要装 Firefox，就必须把列出的依赖包全部装好。它依赖一些第三方库，就像写一个 Java 项目要装 JDK，写 C++ 要装编译器，写 Python 要装相应的库，否则软件根本跑不起来。例如 Firefox 会 depends 于 libatk1.0、libc6、libgcc 等，而且对版本有要求，例如必须大于等于 4.1.1。同时还有冲突（conflict）：例如要装 Firefox 3.0，就不能再装其他版本的 Firefox。这与最开始的 matching problem 一脉相承。

也就是说，要装这个包，就要求它所依赖的包必须装上；同时有些包不能同时存在。Linux 和 macOS 都有包管理器系统，它实际上和远端仓库相连。

### 包管理器与 SAT 求解

**37:47**

用户电脑会连接到包管理器的远端镜像，镜像上运行包管理器。大家可能熟悉的是 APT 和 yum，这是 Linux 常用的包管理器。包管理器具体怎么做？

其实很简单：把它变成一个 SAT 问题，然后跑 Z3 solver 求解。做一个简单抽象：要安装软件包 D，版本为 d0。装 d0 的依赖是：要么装 a0 或 a1，要么装 b0 或 b1；a 和 b 是另外两个软件。

继续往下看，包管理器会维护所有 package 的信息。a0 依赖 c0，同时与 b0 冲突，所以装 a0 就不能装 b0。a1 依赖 c1，b0 依赖 c0，b1 依赖 c1，并且 c0 与 c1 冲突。c0、c1 不再依赖其他包。

现在要成功安装 d0，你们点一个 apt-get install，或者在系统里点安装，背后都会默默跑一个 SAT solver 来求解：根据当前电脑的环境，能否找到一个满足解，使得安装这个包所需的软件之后，同时不和电脑里已有的任何 package 冲突。

### 把依赖关系形式化为命题公式

**39:44**

要装 d0，根据依赖关系可以推出 \(a0 \lor a1\)，并且推出 \(b0 \lor b1\)。同时，如果装 c0，而 c0 与 c1 冲突，那么 c0 能推出 \(\neg c1\)：装 c0 就一定不能装 c1。

把 dependency 转换成逻辑公式后，整个依赖变成：首先必须装 d0，所以 \(d0\) 为真。装 d0 意味着：
\[
\neg d0 \lor a0 \lor a1,\qquad \neg d0 \lor b0 \lor b1.
\]
这里的 \(\neg d0 \lor \cdots\) 就是 \(d0 \to \cdots\) 展开后的形式。对于 a0 类似：装 a0 推出 c0，且推出 \(\neg b0\)（因为 a0 与 b0 冲突），展开为：
\[
\neg a0 \lor c0,\qquad \neg a0 \lor \neg b0.
\]
后面几个类似。最后整个问题变成下面这些式子的合取：
\[
d0 \land (\neg d0 \lor a0 \lor a1) \land (\neg d0 \lor b0 \lor b1)
\land (\neg a0 \lor c0) \land (\neg a0 \lor \neg b0)
\land (\neg a1 \lor c1) \land (\neg b0 \lor c0)
\land (\neg b1 \lor c1) \land (\neg c0 \lor \neg c1).
\]

### EDA 与芯片验证

**42:42**

其中一个就是 EDA。EDA 是什么呢？就是说我们在烧芯片的时候，之前做形式化验证——在没有 coding agent 泛滥的年代——形式化主要用在芯片验证。为什么？因为烧一个芯片属于重资产，烧片成本太高。所以之前一定要用形式化这种“核武器”来证明芯片电路没有问题，然后才去烧；否则烧一次可能几千万甚至一个亿、几个亿就没了。所以最开始实际上是做芯片验证。

那么怎么样用 SAT/SMT 来做芯片验证呢？怎么证呢？首先我们知道芯片验证主要包含门电路，比如与门、或门等。这样一个电路，比如与门对应 \(a \land b\)，非门对应 \(\neg a\)，或门对应 \(a \lor b\)。

我要证什么呢？比如说对于这样一个电路，我就可以把它转换成什么？转换成命题逻辑表达式。这个命题逻辑表达式对应的就是，比如电路输出 \(d\)，那么 \(d\) 对应 \(a \land b\)；输出 \(e\) 对应 \(\neg c\)；\(f\) 就是 \(d \lor e\)。最后把上面这几个命题逻辑表达式取合取，就是整个命题逻辑表示。把这个表示出来之后，我证明的是什么呢？

一般做芯片时会有一些文档。文档里说，举个例子，比如我输入的是 \(FF\)，一定和 \(c\) 取反，这可能就是我的证明条件。你要根据芯片的功能去证明你的第一条、第二条。我们做芯片的时候，比如最开始设计的一个功能完整性是这样的一个芯片，在做的过程中需要优化成另外一个芯片。这两个芯片本身上都可以转换成命题逻辑表达式，然后我要证明优化之前和优化之后的芯片是等价的。
