### 从命题逻辑到谓词逻辑：量词、未解释函数与第三方库

**11:08**

这个问题是循环。那命题逻辑和谓词逻辑能解决的边界是什么？哪些情况能解决？

从命题逻辑到谓词逻辑，除了对程序的抽象变得更简单，表达能力也更强。这体现在引入了量词、谓词和函数。上节课学的 EUF 处理的是未解释函数（uninterpreted function）。因此可以把代码转成更复杂的表达式，从命题逻辑走到谓词逻辑。这样不仅能更好地表达和抽象程序，还能表示程序调用了第三方库的情况，把第三方库表示成未解释函数。

例如，一个程序调用了一个没有源码、不知道具体内容的函数，要证明它时，就可以把它变成未解释函数。未解释函数就是一个函数，不管它具体是什么；只要利用 \(x=y\) 时 \(f(x)=f(y)\) 这样的性质，就可以证明带有这种函数的程序。于是这个函数完全可以对应一个第三方库。比如调用 `printf` 时，不需要看 `printf` 下面的代码，也可以证明某些带 `printf` 的程序。

引入了这样的谓词之后，就可以解决之前解决不了的问题。

### 自动验证、半自动验证与霍尔逻辑

**13:11**

从控制流上讲，一个典型的之前解决不了的问题是 unbounded loop，也就是没有边界的循环。这个问题之前讲过几次，接下来要看它到底怎么解决。

这里还有一个变化：交互式证明（interactive proof），也就是半自动化验证。前面命题逻辑和谓词逻辑这两部分都叫自动化验证。它们的做法是把程序直接转换成命题逻辑表达式，通过符号执行，加上用状态进行建模，转换成命题逻辑的表示，然后直接放到 SAT 或 SMT solver 中求解。

而交互式证明本质上需要人一点点去推、去写证明。后面会看到，写的这个证明本质上就是公理系统；霍尔逻辑是一个特殊的公理系统。

Claude 最近爆出来的工作，就是用大量证明来证明一段汇编是正确的。回头有一篇公众号文章可以分享给大家，会发到群里，讲 Claude 怎么样写很多证明来证明一段汇编是对的。

从形式化验证角度看，先要弄清楚什么是公理系统，以及公理系统两个非常重要的性质：可靠性（soundness）和完备性（completeness）。

### 程序测试的局限与 SMT 转换

**15:05**

在验证之前，其实要做程序分析。最直接的方法是程序测试。做程序正确性（program correctness）的 Dijkstra，也就是提出最短路径算法的 Dijkstra，曾经说过：程序测试只能证明 bug 存在，不能证明 bug 不存在。这也是为什么需要形式化验证这样的工具。

最开始学的形式化方法是基于 SMT 的程序分析。把程序转成 SMT 时，比如程序

```c
if (c >= 0) return a; else return b;
```

可以转换成类似的表达式。证明左边就变成证明右边。

对于带循环的函数，如果循环次数明确，那么无论循环怎么执行、输入是什么……

### 循环展开与霍尔逻辑的引入

**16:22**

从程序验证的角度看，证明左边这个命题就变成证明右边这个命题，实际上是等价的。对于带 loop 的函数，如果循环的次数是明确的——无论输入是什么，循环都执行三次——就可以直接把循环展开，再基于展开后的断言来处理。

对于一直举的那个例子，谓词逻辑实际上搞不定。问题出在循环的 bound（边界）上：这个循环的边界是 A，而 A 依赖于函数的输入，函数的输入又可以取任意值。因此可以说它的 bound 是任意的，这种循环称为 bound 不确定的无限循环。

### 霍尔逻辑与图灵奖

**17:27**

这种情况下没有办法展开循环，因此需要更强的工具。这三位提出的霍尔逻辑，就是一个面向程序验证的公理系统。

我们今天学的所有逻辑，无论是命题逻辑还是谓词逻辑，本身都是数学的一部分；即使不是计算机专业，数学专业也会学这两种逻辑。命题逻辑和谓词逻辑是计算机领域的人从数学中拿过来做验证的，所以先有命题逻辑和谓词逻辑，再有程序验证。霍尔逻辑正好相反：它发现命题逻辑和谓词逻辑不够用，于是为了形式化验证提出了一个新的逻辑系统。Dijkstra 最短路径、challse 等工作，都与这一方向有关。

后面两位因为霍尔逻辑获得了图灵奖。霍尔逻辑本质上是建立在命题逻辑和谓词逻辑基础之上的。我统计了一下，图灵奖得主中大概有七八位是因为形式化或形式化相关的工作而获奖。所以形式化验证一直是计算机理论中非常主流的方向。

### 公理系统的要素

**19:13**

霍尔逻辑本质上是为形式化验证而开发的一个逻辑系统，而这个逻辑系统本质上就是一个公理系统。我们之前在命题逻辑中已经对公理系统作了铺垫，后面在谓词逻辑中又做了一个公理系统，并手动验证过规则。回顾一下：什么是公理系统？

公理系统有两个元素：第一是公理，第二是推理规则。它的作用是根据公理和推理规则推出更多新的定理。

### 符号、永真式与形成规则

**20:25**

一般定义一个新的逻辑——尤其是面向程序证明的逻辑——的公理系统时，首先要定义一些初始符号，用来表示这个公理系统中如何进行运算。例如 A、B、C 表示命题，还有否定词、析取词、括号等，这些都是之前学过的。

在这里再引入一个新符号：一竖一横。写在公式前面时，它表示这个公式是永真的，是一个永真式。

然后是推理规则。在霍尔逻辑里，我们管它叫推理规则。推理规则是说，根据这些规则可以推出新的规则。另外还有形成规则：假设有一套符号系统，形成规则规定怎样把这些符号表示成合法的表达式。比如之前说的合式公式，就是一种形成规则。

### 命题逻辑与谓词逻辑的公理系统

**21:40**

虽然现在讲霍尔逻辑，但本质上之前讲的命题逻辑和谓词逻辑都是公理系统。这两页 slide 展示了：无论是学命题逻辑还是学谓词逻辑，除了新加的符号之外，本质上都要从公理系统来解读。所以现在讲的公理系统是一个承上启下的知识点：之前做了铺垫，这里进行凝练。凝练的作用是说明命题逻辑和谓词逻辑都是公理系统；同时，我们根据公理系统定义规则，重新定义一个新的逻辑，叫作霍尔逻辑。

所以有形成规则。形成规则规定：有了那些符号之后，怎样形成一个合法的表达式，比如合式公式（well-formed formula，WFF）。每一个命题都是 WFF，A 和 B 是 WFF，这些都是命题逻辑里的形成规则。谓词逻辑里也有对应的形成规则，对应的也是 WFF。有的时候我们还会定义。

### 符号的完备性与公理的引入

**22:50**

之前讲过一个事情：如果公理系统只定义了否定词、析取这些符号，那么在定义这两个符号时，要保证它们的完备性。今天一直在推这个问题：为什么在公理系统上定义符号时，要保证这两个符号的完备性？有了这两个符号的完备性之后，就可以引入更多的符号，比如 die 等。

符号体系建立好之后，就可以引入公理。

### 四条基本公理

**23:44**

公理一般怎么表示？举个例子，比如 \(p \lor p \to p\)，我们把它称为一条公理。写的时候可以在它前面加上一个符号，表示这个式子是永真的，可以作为 ground truth，大家不用自己去做这个推理。

现在假设要建立一个公理系统，尝试基于命题逻辑来建。这个公理系统有四个基本公理：

1. \(p \lor p \to p\)；
2. \(p \to p \lor q\)；
3. \(p \lor q \to q \lor p\)；
4. \(q \lor r\) 能推出什么，\(p \lor q\) 则……

### 公理系统与四条公理

**24:38**

第四条公理是
\[
(q\to r)\to((p\lor q)\to(p\lor r)).
\]
于是一个由四条公理构成的公理系统为：
\[
\begin{aligned}
A_1 &: (p\lor p)\to p,\\
A_2 &: p\to(p\lor q),\\
A_3 &: (p\lor q)\to(q\lor p),\\
A_4 &: (q\to r)\to((p\lor q)\to(p\lor r)).
\end{aligned}
\]
建立这样的公理系统之后，就可以讨论它能推出哪些定理。

### 三条推理规则

**24:53**

系统有三条推导规则。第一条是代入规则：如果一个公式是永真式，就可以把其中的命题变项替换成任意命题。例如 \(p\lor\neg p\) 是永真式，把 \(p\) 换成 \(r\lor s\)，得到的 \((r\lor s)\lor\neg(r\lor s)\) 仍是永真式。第二条是分离规则：若 \(A\) 成立，且 \(A\to B\) 成立，则 \(B\) 成立。第三条是置换规则：若公式 \(A\) 成立，则可以把 \(A\) 替换为与它等值的公式 \(B\)。

### 用公理系统证明第一条定理

**25:53**

接着要建立定理
\[
(q\to r)\to((p\to q)\to(p\to r)).
\]
它不在四条公理中，需要由公理和推理规则推出。先引入公理四：
\[
(q\to r)\to((p\lor q)\to(p\lor r)).
\]
公理是永真式，所以可以用代入规则把其中的 \(p\) 换成 \(\neg p\)，得到
\[
(q\to r)\to((\neg p\lor q)\to(\neg p\lor r)).
\]
再利用等值式 \(\neg p\lor q\equiv p\to q\) 和 \(\neg p\lor r\equiv p\to r\)，用置换规则把括号中的式子替换掉，就得到
\[
(q\to r)\to((p\to q)\to(p\to r)).
\]
这是系统中推出的第一条定理。

### 证明 \(p\to p\)

**27:20**

第二条定理是 \(p\to p\)。它看起来自然，但并不在公理中，必须证明。

先由公理二，把 \(q\) 换成 \(p\)，得到
\[
p\to(p\lor p).
\]
由公理一得到
\[
(p\lor p)\to p.
\]
再把刚证明的定理作为引理：
\[
(q\to r)\to((p\to q)\to(p\to r)).
\]
用代入规则先把 \(q\) 换成 \(p\lor p\)，再把 \(r\) 换成 \(p\)，得到
\[
((p\lor p)\to p)\to((p\to(p\lor p))\to(p\to p)).
\]
由 \((p\lor p)\to p\) 和上式，使用分离规则推出
\[
(p\to(p\lor p))\to(p\to p).
\]
再由 \(p\to(p\lor p)\) 和上式，使用分离规则推出
\[
p\to p.
\]
这就是在公理系统中对 \(p\to p\) 的构造证明。

### 构造证明的意义与其他证法

**29:34**

这里不能因为 \(p\to p\) 看起来显然，就直接把它当成公理或现成规则使用；当前系统里没有这样的规则。若要自己构建公理系统，可以另外规定推导规则，但那是另一个系统；现在讨论的是一个示例公理系统，已经有前面的推理规则，需要在这些规则下完成推导。具体变形问题可以线下继续讨论。利用公理三还可以推出等值式，同一个结论往往有很多种不同的证法。这个证明的目的是让大家体会：即使结论非常简单，只要它没有被列为公理，就必须按公理和推理规则一步步构造证明；如果直接把结论当成规则，就失去了这个教学目的。

### 引入公理系统的目的

**30:48**

引入公理系统的目的，是为了介绍两个非常重要的性质：completeness（完备性）和 soundness（可靠性）。后面学习形式化验证时，也离不开这两个词。之前面向程序形式化验证时提过它们，现在是在公理系统这个场景下更形式地定义。

### 完备性与可靠性的定义

**31:23**

完备性的意思是：如果命题 \(p\) 是永真式，那么 \(p\) 一定能在该系统内被证明。也就是说，系统可以证明所有永真式。可靠性的意思是：如果 \(p\) 在该系统中被证明了，那么 \(p\) 一定是永真式。

### 完备但不sound、sound但不完备

**32:09**

可以反过来考虑两类系统。若一个系统是 complete 但不 sound，那么所有永真式都能被证明，但系统中证明出来的公式不一定都是永真式。若一个系统是 sound 但不 complete，那么凡是被证明的公式都一定是永真式，但并非所有永真式都能在该系统中被证明；某个公式没有被证明，不等于它不是永真式。

### SAT 求解器与公理系统

**32:43**

如果把 SAT 求解器看成一个公理系统，那么它是 sound 还是 complete，还是两者都具备？SAT 求解器本身是证明一个式子是否可满足的。如果 SAT 求解器说一个式子是可满足的，它找到一个解，就能证明这个式子可满足；如果它说式子不可满足，也能证明它不可满足，也就是说，它的回答是真的。

但是，如果一个式子本身是可满足的，它一定会被 SAT 求解器求出来吗？大家都知道 DPLL 算法，它一定会被求出来吗？不一定。原因在于 SAT 本质上是一个 NP 问题，计算量非常大，不能保证对任意公式都在多项式时间内求出来，所以求解器可能会卡住。如果你们做过 lab 1，应该能意识到这个问题吧？比如刚刚那个问题，很有可能就是考试的问题。你们做的 lab 肯定可以理解、可以回答这个问题。

### 形式化验证：sound 但不 complete

**34:49**

所以形式化验证本身是 sound，但不是 complete。这是什么意思？我们构建一个形式验证系统，例如霍尔逻辑；如果我说能证明这个程序满足某个规约，那么它一定真的满足该规约，没有任何 bug。但并不是所有满足该规约的程序都能被我证明。

本质上讲，这就是把形式化验证放到公理系统的 sound/complete 框架里来理解。当然，SAT 求解器只能求这个命题，也就是这个式子是否可满足。

### 公理系统的完备性

**35:46**

我们看一下刚刚构建的公理系统：它是既 sound 又 complete。先尝试证明 complete：如果 A 是永真，那么 A 一定能在系统中被证明。刚刚的公理系统实际上引入了四条公理和三条推导规则；只要任意命题在这里面是永真，就一定能由这四条公理和三条推导规则推出来。

首先有一个先验知识：对任意命题 A，都可以把它转成 CNF。转成 CNF 之后，如果前提是 A 永真，那么在证明过程中就可以应用这个前提。如果 A 永真，那么每一个子句 \(A_i\) 都应当是永真。CNF 中的 \(A_i\) 本身是析取子句。一个析取子句要成为永真，一定可以写成 \(P\lor\neg P\) 这样的形式，否则它不可能是永真。

所以根据假设，可以推出 \(A_i\) 具有 \(\neg P\lor P\) 这样的形式。再根据推导规则，\(A_i\) 可以写成 \(\neg P\lor P\lor Q\) 的形式，其中 Q 是任意式子、可以任意引入。于是每个 \(A_i\) 都能在系统中被证明；因此 A 这个式子实际上也能在系统中被证明。

接下来要反过来证 soundness。

### 公理系统的可靠性

**38:19**

反过来证：如果 P 在系统中被证明，那么 P 一定是永真。这个更简单。首先，之前介绍的所有公理都是永真；所有定理都从公理出发。新的定理根据公理和推导规则得到，因此它们也是永真。

说白了，因为推导规则保真：如果 A 是永真，\(A\to B\) 是永真，那么能推出 B 是永真；如果 A 本身永真，且 \(A\to B\) 也永真，那么 B 永真。于是所有后面推出的结论都是永真。这些推导实际上更简单。前面铺垫这么久，介绍了这个公理系统；它本质上起承上启下的作用。

### 霍尔逻辑的引入

**39:39**

接下来讲一个为程序验证而引入的新的公理系统，鼎鼎大名的霍尔逻辑。它为什么、怎么体现为程序验证而发明？首先它回答了一个问题：什么是程序的正确性；第二个问题是如何形式化地证明程序的正确性。我们想一下如何去定义程序的正确性。

想这个问题时，回想一下：在命题逻辑和谓词逻辑里，我们是怎么定义、证明程序的正确性的？我们证明的都是什么性质？

### 从断言到程序正确性

**40:45**

我们之前证明的多种性质都是断言（assertion）。例如，执行 \(z=x+y\) 后断言 \(z>x\)，要证明的是执行完这段代码后该断言永远为真。断言并不是命题逻辑和谓词逻辑自带的；逻辑本身已经存在了几百年，而断言是 1949 年由图灵提出，用来表示程序的正确性。对霍尔逻辑来说，首先要做的事情就是重新定义什么叫程序的正确性。

### 霍尔三元组

**41:46**

这就是霍尔三元组，整个霍尔逻辑都围绕霍尔三元组来定义。程序执行被分成三个部分：程序执行前的状态，称为前置条件（precondition）；程序本身；以及程序执行完之后的状态，称为后置条件（postcondition）。霍尔三元组默认把状态机抽象掉，写成 \(\{P\}\,C\,\{Q\}\)：\(P\) 是前置条件，\(C\) 是程序，\(Q\) 是后置条件。

这里的等号含义不同。例如前置条件 \(x=1\) 中的等号是谓词，表示程序执行前 \(x\) 的状态为 1；程序 \(x:=x+1\) 中的等号是 C 语言或 Python 里的赋值运算符；后置条件 \(x=2\) 表示执行后状态变为 2。霍尔三元组的前置条件和后置条件本身都是谓词逻辑表达式。

### 部分正确性

**43:40**

有了霍尔三元组后，程序正确的定义称为部分正确（partially correct）。它不证明停机问题，而是先假设程序能够执行结束。若程序 \(C\) 执行前状态满足 \(P\)，执行后状态能够推出 \(Q\)，就称 \(\{P\}\,C\,\{Q\}\) 部分正确。要证明一个程序，需要提供三样东西：程序本身、前置条件和后置条件；然后让验证器证明：如果执行前状态满足前置条件，那么执行完之后是否满足后置条件。

### 逐行验证

**44:58**

例如，一段用 C 语言写的代码，如果要证明它的正确性，就要为每一行代码写出 \(\{P\}\,C\,\{Q\}\)，再检查从 \(P\) 出发执行 \(C\) 后能否推出 \(Q\)。这就是经典的霍尔三元组验证方式。后面会看到，很多推导规则实际上可以自动推导。

### 规约

**45:42**

记 \(\{P\}\,C\,\{Q\}\)，其中 \(P\) 是前置条件，\(C\) 是程序，\(Q\) 是后置条件。因为不考虑终止，所以称为部分正确；停机问题不可判定，图灵已经证明过。需要手写的前置条件和后置条件称为规约（specification），本质上用来描述一个程序是否正确。

### 一个简单的程序语言

**46:39**

下面开始构建一套非常简单的语言，一个迷你 C 语言。它有变量 \(A,B,C\)，常量 \(1,2,3\)，以及简单的表达式；表达式支持加、减、乘，不支持除法。它还支持基本的布尔计算，例如大于、等于、小于，并用 \(b_1,b_2\) 表示布尔变量。

### 语句

**47:35**

语句支持以下几种：第一种是 \(\mathrm{skip}\)，什么都不做；第二种是赋值 \(a:=e\)；第三种是顺序执行 \(s_1;s_2\)，即执行完 \(s_1\) 后接着执行 \(s_2\)；第四种是条件语句，如果 \(b_1\) 成立就执行 \(s_1\)，否则执行 \(s_2\)，即 \(\mathrm{if}\ b_1\ \mathrm{then}\ s_1\ \mathrm{else}\ s_2\)；最后一种是 \(\mathrm{while}\) 循环。

### 语言范围与公理系统

**48:13**

我们不考虑 C 中的一些特性，例如堆、指针、break、continue、function、operator、面向对象，以及 struct、union 等；只做一个非常简单的语言。接下来要考虑的是：用这个语言写出的程序如何用霍尔三元组证明其正确性。为此要构建一个基于霍尔三元组的公理系统，并用这个公理系统证明程序正确。构建公理系统最开始要讲什么？

### 构造霍尔逻辑的公理系统

**49:08**

构建这套公理系统时，首先要引入初始符号。谓词逻辑中的全称量词、存在量词、蕴含、否定等符号都要引入；语言中还会用到 `if`、`while`、赋值等符号。随后引入 \(\vDash\)。这个符号就是之前讲过的竖横符号，用来表示公式成立；在这里可以作简化，省略掉。

接着定义形成规则。按照霍尔逻辑的规则，霍尔三元组写成 \(\{P\}\,C\,\{Q\}\)。其中 \(P\)、\(Q\) 的形成规则应符合谓词逻辑的形成规则，程序 \(C\) 的形成规则应符合此前定义的程序形成规则。

初始符号和形成规则确定后，后面就说明如何用这些符号和形成规则表示霍尔三元组，再讨论如何证明。

### 证明程序的基本思路

**50:30**

如果要证明一个程序，先把前置条件 \(P\) 和后置条件 \(Q\) 写出来，然后证明霍尔三元组 \(\{P\}\,C\,\{Q\}\)，也就是证明在前置条件 \(P\) 下执行程序 \(C\) 后能否推出后置条件 \(Q\)。

## 离散数学｜第 8 节（14:50）

### 霍尔三元组的例子

**05:18**

在讲完符号和形成规则之后，我们来看霍尔三元组如何表示程序的正确性。下面是一些例子，从形式上看，左边这些都是合法的霍尔三元组。第一个例子中，程序是 \(a:=3\)，前置条件可以取 \(a=0\)；执行完 \(a:=3\) 后，可以满足后置条件 \(a=3\)。第二个例子中，初始条件为 \(a=2\)，执行 \(a:=a+1\) 后，要证明 \(a=3\)。第三个例子是：前置条件为 \(a=1\)，程序执行后为 \(a=2\)，却要证明后置条件 \(a=10\)。第四个例子的前置条件是 \(a=1\)、\(b=5\)；如果 \(a=1\)，执行 \(a:=b\)，那么执行完这段代码后，要证明后置条件 \(a=5\) 且 \(b=5\)。

这些例子中，哪一个程序不满足规约，或者哪一个程序有问题、证明会出错？第三个。因为程序执行后 \(a=2\)，不能满足执行后 \(a=10\) 这样的规约。

### 霍尔三元组的含义

**06:50**

这就是霍尔三元组。霍尔三元组本质上是在定义 \(\{P\}\,C\,\{Q\}\)，看程序 \(C\) 是否满足这个霍尔三元组。什么叫满足 \(\{P\}\,C\,\{Q\}\)？就是当 \(C\) 执行之前，初始状态满足 \(P\)，执行之后能够推出 \(Q\)。接下来的问题是：怎样证明程序的正确性？

### 证明思路

**07:38**

再多说一点：霍尔三元组为什么要这样设计？它实际上是为程序设计的一种逻辑。再想一下 \(\{P\}\,C\,\{Q\}\)。如果要证明它，基本证明思想是：假设有 \(P\)，再假设执行 \(C\)，根据 \(P\) 和 \(C\) 先推出一个 \(Q'\)，然后证明 \(Q'\) 蕴含 \(Q\)。

### 霍尔三元组的一个简单例子

**08:20**

例如要证明程序 \(a:=1\)，前置条件是 \(a=0\)，后置条件是 \(a>0\)，这就构成一个霍尔三元组。根据前置条件 \(a=0\) 和执行 \(a:=1\)，可以得到执行后的状态满足 \(a=1\)；而 \(a=1\) 又能推出 \(a>0\)。因此，这个三元组成立。

### 为什么霍尔逻辑面向程序

**08:49**

接下来要问：为什么这种推导规则、这种对程序正确性的定义是为程序设计服务的？以前的做法是把程序性质写成一个断言（assertion），再把它转成一堆谓词逻辑表达式或命题逻辑表达式；那种做法并不是为程序设计服务的。二者的区别在哪里？有同学提到前置条件。以前其实也有前置条件，只是那时它是作为函数参数出现的。

那么有了前置条件之后有什么好处？还有预期的结果：在执行之前先定义这样一个前置条件。大家想一下霍尔三元组 \(\{P\}C\{Q\}\)：有了前置条件 \(P\)，就能确定执行前系统应满足的状态。

霍尔三元组之所以是为程序设计服务的，我们把它定义成 \(\{P\}C\{Q\}\)，并且有前置、后置条件，原因在于中间的 \(C\) 可以是一条语句（statement），也可以是一段代码。

### 可组合性

**10:44**

霍尔逻辑最大的特性是可组合性。假设有代码 \(C_1\) 执行完，然后有代码 \(C_2\) 继续执行；一段程序可能有很多很多代码，比如上百万行。我可以对每一行代码分别写出 \(\{P_1\}C_1\{Q_1\}\)、\(\{P_2\}C_2\{Q_2\}\) 等。也就是说，把对甚至上百万行代码的证明解耦成对每一行代码的证明。每一行代码只要都能写成 \(\{P\}C\{Q\}\) 的形式即可。

前提是程序串行执行：上一行代码的后置条件可以推出下一行代码的前置条件。这样，前置条件就使当前代码能够与它前面代码的后置条件组合起来，进而完成大量程序、海量程序的验证。

因此，霍尔三元组这种验证逻辑可以称为可组合的验证逻辑，它具有很强的可组合性。这个霍尔逻辑在 lecture note 上，教科书上没有。

### 与命题逻辑、谓词逻辑的对比及代价

**12:33**

霍尔逻辑实际上是专门为程序验证加入的逻辑。正是因为霍尔逻辑具有可组合性，理论上可以用它来证明上百行代码。那么命题逻辑和谓词逻辑呢？

能不能用命题逻辑证明一个上百行代码的程序，只在后面加一个 assertion？首先，assertion 这种断言能表示的性质很少。假设可以把上百万行代码一口气转成一个谓词逻辑表达式，再证明这件事，在工程上是不可行的。

霍尔逻辑解决这个问题：它把对一堆代码、对大量代码的验证解耦成分别对每一行代码的验证，然后再证明这些代码之间规约的关系。这就是霍尔逻辑为什么是为程序语言设计的。

当然，它的问题是很费人：一行代码至少要写两行，至少有一个前置规约和一个后置规约。之前有统计，证明一行 C 语言要写十行霍尔逻辑。还有统计说，证明约九千三百行的操作系统微内核需要花二十人年；而且这二十人年需要懂形式化验证的人，这样的人非常少。

讲完霍尔逻辑为什么是为形式化验证设计的，下一个问题就是：怎样根据 \(P\) 和 \(C\) 推出 \(Q'\)，再证明 \(Q'\) 能推出 \(Q\)。

### skip 的公理

**14:25**

这就是基本的证明思路。先看最简单的程序 \(\mathrm{skip}\)，它什么都不做。如果 \(C\) 是 \(\mathrm{skip}\)，那么 \(Q'\) 就与 \(P\) 相同：执行完 \(\mathrm{skip}\) 之后仍然能推出 \(P\)。

这里涉及公理，需要针对语言定义一些公理，称为公理系统。公理系统描述的是：前置条件加上什么样的语言结构，可以推出怎样的后置条件。

### 赋值语句与替换

**15:09**

因为我们的语言其实非常简单，就是那些运算符，所以可以对每一个运算符单独建模：看每一个运算符需要什么样的前置条件，能够进行怎样的推导。现在看 \(a:=e\) 是什么意思。这里的 \(e\) 是一个表达式，而 \(:=\) 实际上表示赋值：把表达式 \(e\) 算出的结果赋给变量 \(a\)。

这里引入一个新的符号，就是 \(a/e\)，表示用 \(a\) 替换 \(P\) 里面的 \(e\)。那么这个规则是否合法？假设在执行 \(a:=e\) 之前，系统状态满足用谓词表达式 \(P\) 表示的前置条件，那么执行后推出的系统状态应当怎样表示？我就把 \(P\) 里面的 \(e\) 用 \(a\) 来替换。大家想一下这个是否可行——不可行。

### 赋值语句与前后状态

**16:32**

如果前置条件是 \(a=0\)，执行 \(a=1\)，按“把 \(P\) 中的 \(e\) 换成 \(a\)”的办法，因为 \(a=0\) 中没有 \(e\)，替换后仍然是 \(a=0\)，这显然不对；执行完 \(a=1\) 后应推出 \(a=1\)。因此这个推导规则不成立。

另一种写法是把后置条件写成 \(P \land a=e\)。以前置 \(a=5\)、执行 \(a=a+1\) 为例，会得到 \(a=5 \land a=a+1\)，这同样不对。原因是 \(a=5\) 描述执行前的状态；在 \(a=a+1\) 中，右边的 \(a\) 是执行前的 \(a\)，左边的 \(a\) 是执行后的 \(a\)。执行前后是两个不同的量，后置条件关心的是执行后的 \(a\)。

### 引入变量表示执行前的值

**18:43**

为了区分执行前后的 \(a\)，可以引入一个新变量 \(v\) 表示执行前的 \(a\)。直观上也可以说成 \(a_0\)、\(a_1\)，这里统一用 \(v\)。

设前置条件为 \(P\)，执行赋值 \(a=e\)。设 \(e_v\)、\(P_v\) 分别表示把 \(e\)、\(P\) 中的 \(a\) 换成 \(v\) 后得到的表达式，则后置条件可写成
\[
\exists v\,(a=e_v \land P_v).
\]
其中存在量词表示存在执行前的 \(a\) 的值。

例如，前置为 \(a=1\)，执行 \(a=a+1\)。令 \(v\) 表示执行前的 \(a\)，则前置给出 \(v=1\)，赋值后的关系为 \(a=v+1\)，于是后置为
\[
\exists v\,(a=v+1 \land v=1),
\]
化简得 \(a=2\)。这就是霍尔三元组的基本做法：根据前置和代码推出后置。

### 正向与反向证明霍尔三元组

**21:02**

对霍尔三元组 \(\{P\}\,C\,\{Q\}\)，可以从前往后证明：根据前置 \(P\) 和代码 \(C\) 推出一个后置 \(Q'\)，再看 \(Q'\) 能否推出规约中的 \(Q\)。如果 \(Q' \to Q\)，就证明了 \(\{P\}\,C\,\{Q\}\) 成立。

也可以反过来做：根据代码 \(C\) 和后置 \(Q\) 推出一个前置 \(P'\)，再看规约中的前置 \(P\) 能否推出 \(P'\)。如果 \(P \to P'\)，同样相当于证明了 \(\{P\}\,C\,\{Q\}\)。前面是从前向后推，这里是反着来。

对赋值语句 \(a=e\)，如果后置条件是 \(P\)，则它的前置条件可以通过把 \(P\) 中的 \(a\) 替换成 \(e\) 得到。

### 由后置条件反推前置条件

**22:40**

假设代码 \(a=e\) 执行完之后，状态满足后置条件 \(P\)。这里的 \(P\) 中的 \(a\) 是执行后的 \(a\)。那么执行前应满足什么条件？如果先把 \(P\) 中的 \(a\) 替换成 \(e\)，得到的谓词就应成立，因为执行 \(a=e\) 后，\(e\) 的值就是新的 \(a\)。所以在赋值之前，\(e\) 应满足 \(P\) 所描述的条件。于是根据后置和代码可以反推出前置：把后置条件 \(P\) 中的 \(a\) 直接替换成 \(e\)。

例如，代码为 \(a=b+1\)，后置条件为 \(a=42\)，则前置条件是 \(b+1=42\)。又如代码为 \(a=42\)，后置也是 \(a=42\)，则前置是 \(42=42\)，即为真。再如代码为 \(a=a-b\)，后置为 \(a>3\)，则前置是 \(a-b>3\)。

根据后置推前置，就是假设程序执行完之后状态满足后置条件，反推出执行前必须满足的条件。

### 前置与后置：正推和反推

**24:34**

先看从后置条件和代码反推前置条件。例如，若执行完某段代码后要满足 \(a>3\)，而代码是 \(a=a-b\)，那么执行前需要满足 \(a-b>3\)。也就是说，只要执行后的状态满足后置条件，就可以反推出执行前必须满足的条件。

与它相对，从前置条件和代码正推后置条件比较直接：执行前状态满足某个条件，执行后希望满足什么条件。正推的缺点是会引入量词；反推虽然方向相反，却不会引入量词。

**25:37**

原因在于，正推公式中的变量可能同时指执行前和执行后的值。例如前置条件里出现的 \(a\) 是执行代码之前的 \(a\)，而代码执行后 \(a\) 的值会改变。为了在同一公式里区分这两个时刻，就必须用量词绑定旧值；否则无法说明公式中的 \(a\) 究竟是哪一个。

反推时，后置条件已经描述执行后的状态。以赋值语句 \(a=e\) 为例，若执行后 \(a\) 满足某个条件 \(P\)，那么执行前 \(e\) 必须满足 \(P\)；把后置条件中的 \(a\) 用 \(e\) 替换，就得到前置条件。因此这里不需要用量词，也不需要额外的时序逻辑去区分执行前后。

正推和反推的推理逻辑并不完全相同。反推的依据是：执行后 \(a\) 能满足 \(P\)，则执行前 \(e\) 一定满足 \(P\)，否则执行后不可能满足 \(P\)。如果暂时没有完全理解，可以在后续练习中继续体会。下面继续看具体例子。

### 正推：由前置条件推出后置条件

**27:31**

仍以霍尔三元组
\[
\{a=1\}\quad a=a+1\quad \{a=2\}
\]
为例。如果从前往后推，根据前置条件 \(a=1\) 和代码 \(a=a+1\) 推后置条件，需要引入一个旧值 \(v\)，写成
\[
\exists v\,(v=1\land a=v+1).
\]
也就是说，执行前 \(a\) 的值为 \(v\)，且 \(v=1\)；执行后 \(a=v+1\)，由此可推出 \(a=2\)。

一般地，要证明 \(\{p\}\,c\,\{r\}\)，可以先根据 \(p\) 和 \(c\) 推出一个后置条件 \(q\)，再证明 \(q\Rightarrow r\)。

### 后置条件的加强与推理规则

**28:24**

如果一个人给出的规约是 \(\{p\}\,c\,\{r\}\)，要证明它，可以改为证明 \(\{p\}\,c\,\{q\}\) 且 \(q\Rightarrow r\)。这里 \(q\Rightarrow r\) 表示 \(q\) 比 \(r\) 更强，\(r\) 比 \(q\) 更弱。

这对应下面这条推理规则：横线上方的两个前提同时成立，就能推出横线下方的结论：
\[
\frac{\{p\}\,c\,\{q\}\qquad q\Rightarrow r}{\{p\}\,c\,\{r\}}.
\]
例如要证明
\[
\{a=1\}\quad a=a+1\quad \{a=2\},
\]
就可以先证明一个更强或更具体的后置条件，再由它推出 \(a=2\)。

**29:19**

具体做正推时，根据 \(a=1\) 和 \(a=a+1\)，得到的后置条件可以写成
\[
\exists v\,(v=1\land a=v+1).
\]
这里用 \(v\) 表示执行前的 \(a\)，并在赋值后用 \(v+1\) 替换 \(a\)。接着证明这个后置条件能推出 \(a=2\)，而这是显然成立的。于是该霍尔三元组成立。

### 反推：由后置条件推出前置条件

**29:59**

还有另一种方式，就是倒着推：根据代码 \(c\) 和后置条件 \(r\)，先推出“执行完 \(c\) 后要满足 \(r\)，执行前至少需要满足什么条件”，记这个前置条件为 \(p'\)；再证明原来的前置条件 \(p\) 能推出 \(p'\)。这样也能证明 \(\{p\}\,c\,\{r\}\)。

**30:28**

看反推的例子。设要证明
\[
\{a=n\}\quad a=a+1\quad \{a=n+1\}.
\]
先根据后置条件 \(a=n+1\) 和赋值语句 \(a=a+1\) 反推前置条件。把后置条件中的 \(a\) 用赋值语句右端的 \(a+1\) 替换，得到
\[
a+1=n+1,
\]
它等价于 \(a=n\)。

另一方面，原来的前置条件 \(a=n\) 本身可以推出 \(a+1=n+1\)。把这两点合起来，就得到
\[
\{a=n\}\quad a=a+1\quad \{a=n+1\}.
\]

### 蕴含式由谓词逻辑证明

**31:58**

这里最后留下的形如 \(p\Rightarrow p'\) 或 \(q\Rightarrow r\) 的蕴含式，用什么来证明？不是再靠霍尔逻辑的赋值公理，而是用谓词逻辑。实际中可以直接使用 SMT solver 这类工具。程序验证最终仍要回到谓词逻辑中的基本推理，例如等式的代入和化简。

### 程序结构的霍尔逻辑建模

**32:42**

前面已经用霍尔逻辑对赋值（等号）进行了建模，下面开始对程序的结构建模。常见的结构包括顺序语句 \(S_1;S_2\)、条件分支 `if B then S_1 else S_2`，后面还要讲 `while` 循环。对于这些代码，要看在 Hoare 三元组 \(\{P\}\,C\,\{Q\}\) 中如何确定前置条件和后置条件。先讲顺序组合规则，这也体现了霍尔逻辑为什么是面向程序设计的。

### 顺序组合规则与一个例子

**33:19**

在程序串行执行的前提下，要证明 \(\{P\}\,C_1;C_2\,\{Q\}\)，等价于分别证明
\[ \{P\}\,C_1\,\{R\},\qquad \{R\}\,C_2\,\{Q\}. \]
也就是先证明 \(P\) 和 \(C_1\) 满足中间条件 \(R\)，再由 \(R\) 和 \(C_2\) 推出 \(Q\)。这说明证明大规模程序时可以做拆分。

例如要证明
\[ \{b>3\}\quad a=2b;\ a=a-b\quad \{a\ge4\}, \]
可以先分别处理这两条赋值语句，再把结果组合起来。

### 从后往前证明

**34:21**

大家先试着自己证明，从前往后推或从后往前推都可以。

以从后往前证为例。后置条件是 \(a\ge4\)，最后一条语句是 \(a=a-b\)。对赋值语句，把右侧表达式代入后置条件中的 \(a\)，得到这条语句所需的前置条件：
\[ a-b\ge4. \]
再把它作为上一条语句 \(a=2b\) 的后置条件，同样把 \(a=2b\) 代入，得到
\[ 2b-b\ge4, \]
也就是 \(b\ge4\)。课程中约定前面原子命题里的变量都是自然数，因此初始条件 \(b>3\) 可以推出 \(b\ge4\)。所以以 \(b>3\) 为前置条件，执行 \(a=2b\)、\(a=a-b\) 后，可以得到 \(a\ge4\)。再根据已经找到的
\[ \{P\}\,C_1\,\{R\},\qquad \{R\}\,C_2\,\{Q\}, \]
用顺序组合规则就得到
\[ \{b>3\}\quad a=2b;\ a=a-b\quad \{a\ge4\}. \]

### 从前往后证明的引入

**38:36**

因此把从后往前的证明过程反过来看，从前往后推也能得到同样的结论。从前往后推时，出发点就是 \(b>3\)。

### 从前往后证明的基本思路

**40:12**

有没有人愿意说一下从前往后推具体怎么推？请先给出一个基本思路：假设 \(b>3\)，接下来先推什么？从前往后推的基本思路是什么？

### 赋值语句与条件推导

**40:49**

推导的基本思路是把赋值语句写成一个等式，再把它与已有的条件合并，逐步得到下一阶段的条件。以 \(b>3\) 为前提，先处理赋值 \(v:=2b\)，得到 \(v=2b\)。把 \(v=2b\) 和 \(b>3\) 一起作为下一条语句的前提。下一条赋值是 \(a:=v-b\)。这一步出现了变量 \(a\)，需要引入存在量词，把两条赋值关系合写成
\[
\exists v\,(a=v-b\land v=2b\land b>3).
\]
接下来要证明这个式子能推出 \(a\ge 4\)。先化简：由 \(v=2b\) 与 \(a=v-b\) 可得 \(a=b\)，于是条件化为
\[
a=b\land b>3.
\]
课程中定义的语言只有整数，没有小数，所以由 \(b>3\) 可得 \(a>3\)，进而得到 \(a\ge 4\)。这就是这一赋值序列的推导过程。

### if-then-else 的推理规则

**43:50**

下一个推理规则处理 if-then-else。设程序写成
\[
\text{if } b \text{ then } c_1 \text{ else } c_2,
\]
要证明
\[
\{P\}\ \text{if } b \text{ then } c_1 \text{ else } c_2\ \{Q\},
\]
就要分别证明两个分支：
\[
\{P\land b\}\ c_1\ \{Q\},
\qquad
\{P\land \neg b\}\ c_2\ \{Q\}.
\]
直观地说，执行前 \(P\) 成立；若 \(b\) 为真，则执行 \(c_1\) 后应满足 \(Q\)；若 \(b\) 为假，则执行 \(c_2\) 后应满足 \(Q\)。因此要把条件变量 \(b\) 或其否定分别加入两个分支的前置条件。这个规则的好处是消去 if-else 结构：上一个规则消去了分号，这里则把 if-else 去掉。

### 用 if 规则证明最大值例子

**45:50**

下面用这个规则证明一个例子：
\[
\{\text{true}\}\ \text{if } a<b \text{ then } c:=b \text{ else } c:=a\ \{c=\max(a,b)\}.
\]
由于临近下课，老师只快速讲解，具体推演留给大家课后完成。
按 if 规则，需要分别证明两个分支。先倒着推：把 \(c=\max(a,b)\) 作为后置条件，对 \(c:=b\) 作代入，得到前置条件
\[
b=\max(a,b).
\]
对另一分支，同样把 \(c=\max(a,b)\) 作为后置条件，对 \(c:=a\) 作代入，得到前置条件
\[
a=\max(a,b).
\]
也就是把 \(c\) 分别换成两个分支中被赋的值 \(b\) 和 \(a\)。之后还要根据 \(\max\) 的性质，把这些前置条件与分支条件 \(a<b\) 或 \(\neg(a<b)\) 结合起来构造证明。

### 用 if-else 规则验证 max 程序

**49:03**

由此可以构造出 if 语句所需的 Hoare 三元组。这里 \(\max\) 不是未解释函数，而是有确定语义的函数 \(\max(a,b)\)，因此可以直接用它进行推导。

前置条件取为 \(\text{true}\)。当 \(a<b\) 成立时，有 \(b=\max(a,b)\)；当 \(a<b\) 不成立时，有 \(a=\max(a,b)\)。于是两个分支分别满足：

\[
\text{true}\land a<b \Rightarrow b=\max(a,b),
\]

\[
\text{true}\land \neg(a<b) \Rightarrow a=\max(a,b).
\]

因此，若条件成立，执行 \(c:=b\) 可以推出后置条件 \(c=\max(a,b)\)；若条件不成立，执行 \(c:=a\) 也可以推出同一个后置条件。根据 if-else 规则，得到：

\[
\{\text{true}\}\ \text{if } a<b \text{ then } c:=b \text{ else } c:=a\ \{c=\max(a,b)\},
\]

这就是前面推导中所构造的式子。

### 赋值语句的存在量词形式

**50:57**

引入存在量词是为了记录赋值语句执行前的旧值。设 \(v\) 表示执行 \(a:=e\) 之前 \(a\) 的值，后置条件为 \(P\)，则前置条件可以写成包含旧值 \(v\) 的形式：

\[
\{\exists v.\ a=v\land P[v/a]\}\ a:=e\ \{P\}.
\]

执行 \(a:=e\) 后，程序状态中 \(a=e\)，并且应满足后置条件 \(P\)。这里的 \(v\) 只是用来指代执行前的 \(a\)，并不是执行后的 \(a\)。

### 存在量词中旧值 \(v\) 的含义

**53:00**

关于存在量词中的 \(v\)：它不是赋值后的 \(a\)，而是执行这段代码之前 \(a\) 的值。也就是说，\(\exists v\) 中的 \(v\) 用来保存执行赋值语句前 \(a\) 的旧值，以便描述执行前后的状态变化。
