## 计算机系统基础（1）｜第 3 节（09:55）

### 回顾：冯·诺依曼架构与信息表示

**00:16**

同学们，我们首先回顾一下上节课讲的内容。上节课在讲数据的表示，核心要点其实就是这张图。

这张图是我上课之前临时让 AI 加的，临时加了一点 PPT，可能不一定特别好看，但大概能表达一个意思。

上节课说过，经典冯·诺依曼架构的计算机有三个重要的组成部分：内存、处理器和 IO。对应到这张图里面，这是处理器——CPU，也就是 central processing unit，中央处理单元；这个是 memory，也就是主存，存放我们上节课所说的所有编码。为什么要做信息的编码？就是因为这里面所有的表达都是用 0 和 1 来存储的。我们说计算机是二进制的，是 0/1 存储，所以需要通过 0 和 1 去表达不同的含义、不同的信息。这也是这份 PPT 核心在讲的一件事——information representation。书里面也在讲这件事：怎样用不同的 encoding 去表示信息。

第三部分是 IO。IO 涉及计算机所有对外的输入输出。大家可以想一想：一个程序是怎么放到计算机上的？CPU 要运行一个程序，而这个程序是一个代码文件，需要输入；用户要跟它交互，就需要键盘输入；我们还要发网络包去访问远端的大模型。这些都需要跟外部交互，所以叫 input/output，也就是 IO。

### 存储层次：程序与文件在磁盘上

**08:17**

输入输出（input/output，IO）在这里先简化处理：例子中只考虑一个文件，所以 IO 只需要和存储器，也就是磁盘（disk）或 SSD 这样的存储设备打交道。

先想一想：运行一个程序，或者加载一个所谓的模型文件，这个东西存在哪里？顾名思义，看图也知道它存在磁盘上，存在 SSD 上。买电脑、买笔记本时大家会看配置，要挑内存大的，还要挑 1T 的 SSD；32G 内存这样的电脑显然跑得更快。

电脑关机、合上、断电的时候，所有数据不能丢，不能说合上笔记本所有文件都丢了。SSD 做的事情就是持久化保存所有数据：所有模型文件、编译出来的程序、安装的应用程序，都放在非易失性（non-volatile）存储中。非易失或持久化存储的意思很简单：断电之后，数据还在。

既然数据都存在磁盘和 SSD 上，主存有什么用？

### CPU 的取指执行循环与同一段 0/1 的解释

**09:57**

主存的作用和 CPU 的行为直接相关。CPU 做的一件事情就是执行指令：执行一条加法指令，执行完再执行下一条乘法，再下一条跳转，再下一条比较判断，等等，不停地做。可以理解成 CPU 在做抓取：看当前是哪条指令，然后执行它，执行完之后执行下一条。它就是一个执行指令的大循环，一直在执行指令。

那执行的指令从哪来？CPU 唯一能拿指令的地方只有内存。而且在执行指令的过程中，如果要去加两个数，这两个数也得知道在哪。比如程序里写了 int a 和 int b，有一条表达式 a + b，那就要把 a 和 b 都读到 CPU 内部做相加操作。所有的数据访问，无论是取指令、执行指令，还是取数据，这些指令和数据都只能来自内存。因为指令最后也无非是编码成一段数据。

所以这里说的是信息编码（information encoding）：所有东西在内存里最后都是 0 和 1。同样一段 0/1，CPU 把它理解成什么？如果当前把它当成编码去看，就要根据指令的编码规则去看它定的是 add 指令、乘法指令还是别的什么指令；如果把它当成一个立即数、当成一个 int 去看，就要用上节课说到的 Binary to Unsigned，或者 Binary to Two's Complement，也就是有符号数和无符号数的解释。这些都涉及相同的一段 0/1：真正使用数据时，我们把它解释成什么。有的解释在 CPU 里面由硬件自己完成，例如解析指令；有的则要到更高一层，比如应用层去看。

### 从文件格式到字符编码

**12:29**

到了用户程序，比如 Ollama 去解析这段数据时，它会尝试按 ASCII 去理解，也就是按照字符编码去理解。它发现这个东西对应到 GGUF 这几个字母，正好是 tiny GGUF 文件前面的一些 magic number，或者固定的 character。

因此我们要说编码：任何信息都要通过某一种编码方式，最后存成 0 和 1，以字节的方式存在主存里。接下来就要说什么是字节。

### 主存是字节数组

**13:21**

上节课说到什么是字节。字节是主存里面最小的一个寻址单元。

刚才说 CPU 是一个大循环去执行指令，主存的特征是什么呢？抽象来看，这些部件其实都非常简单；当然它们内部真正的构造非常精密、非常复杂。从抽象视角看，CPU 就是一个不停地取指令、执行指令的循环。主存则是一个巨大的数组：一个字节的数组，每一个 entry 是一个字节，每一个字节有一个地址，可以寻址的最小单元就是一个字节。比如地址 0、地址 1、地址 2、地址 3 等。

我们在程序里声明的变量，或者一个全局变量，最后得真正放在内存里。放到内存里之后，最终要通过数据的地址去访问：可以取指针，用指针去访问它，其实都是用它的地址去访问它。所以最小的寻址单元就是字节。这也意味着，即便布尔变量只需要 0 和 1，只需要一个 bit 来表示，真正存储的时候也会存到一个字节。这就是为什么它一定要存到一个字节，而不是用一个 bit 就能表示布尔变量；原因在于主存的硬件属性：要去访问里面的数据，最少也是访问一个字节的数据。

### 数据何时从磁盘进入内存

**15:22**

还有一个问题：在最开始断电的时刻，我们说数据都在磁盘上。无论像 tiny GGUF 这样的模型文件，现在也没有要运行它；开机的时候，就算打开了、上了电，机器启动了，它其实也还存在磁盘上。那它什么时候到内存里来呢？

我们要访问任何一个文件的时候，刚才说 CPU 所有的指令只能直接操作内存，只能操作 memory。它要访问数据、执行指令，都只能访问内存。但真正要执行的指令，或者要去读取的数据在哪里？都在磁盘上。比如我们要去读一个 binary，一个编译出来的程序，它也在磁盘上。

### 从源代码到可执行文件

**16:24**

上学期应该写过程序，也用过编译器，比如 GCC、g++。用 g++ 编译 hello.c 后，如果不指定输出文件名，最后会生成一个可执行程序 a.out。可能有些人平时直接用 IDE，或者通过 agent IDE 来写代码；不管怎样，你写的是一个源代码文件。源代码文件是可读的（readable）。但是对 CPU 来说，它不能直接读源代码，也不能直接执行源代码。因此中间需要 g++ 这样的编译器，把源代码编译成 a.out 或 output 可执行文件。在终端里，可执行文件和源文件显示的颜色通常不同，后缀名也不同；它们最后都以文件形式存储。

### 可执行文件的组成

**17:48**

如果打开一个编译出来的文件，会发现里面一部分是 code，一部分是 data。在 Linux 下通常是 ELF 格式；在 Windows 下可能是 EXE 格式的可执行文件。它都是从源代码，比如 .cpp 文件，通过 g++ 编译得到的。真正要让 CPU 去读的 0/1 指令，以及要读的 0/1 数据，都存放在这样的文件里。这个文件最初在磁盘上，尚未进入内存。

### 操作系统加载与 CPU 执行

**18:51**

因此，可执行文件需要在某个时刻被加载到内存中，再由 CPU 执行。这件事只有操作系统能做。例如在命令行运行 Ollama 时，操作系统会找到对应的 Ollama 程序，把它加载到内存；同时找到指定的 tiny GGUF 文件，把它从磁盘搬到内存。数据搬运的工作都由操作系统完成。搬完之后，从文件角度看，如果不加解释，里面也只是 0 和 1。接着我们会告诉 CPU 当前从哪里取指令。例如让 CPU 去地址 0 取指令，它就从地址 0 取出一段 0/1 编码，并把它当作指令翻译。指令中又编码了另一个地址，即 data location，相当于给 CPU 一个 data pointer。它就知道该地址指向一个 character，并把它按 character 来理解。整个过程就是这样。上节课讲到这里。

### 整数溢出与安全漏洞

**20:44**

上节课最后说到一种经常出现的问题：CVE，也就是安全漏洞。它常常来自符号问题、截断、integer overflow，或者类似的情况，比如整数溢出导致负数变成正数。这些问题会造成安全漏洞，攻击者可能加以利用。接下来继续往下讲。

### 不同宽度操作数的比较规则

**21:21**

这里讨论宽度不同的操作数进行比较。这种比较容易出错。它实际上涉及两点原则。

第一点，如果参与比较的两个整数类型都小于 int，那么小于 int 的类型其实只有 char 和 short。它们都会先提升到 int。提升之后，如果发现还有一个更大的类型，比如 64 位的 long long，就继续扩展到最大的那个类型，也就是扩展到 64 位再比较。我们假设默认都是 64 位机器：int 是 32 位，long long 是 64 位，long 也是 64 位。如果符号不同，比如一个是 unsigned int，一个是 long；如果宽度相同，例如一个是 unsigned long，一个是 long，就会取 unsigned，把 signed 转成无符号数。

这里还有一个原则：比如从 16 位的 short 扩展到 int，位数不够，需要补 16 位。补什么由原来的类型和符号位决定。如果原来是 unsigned 类型，高 16 位全部补 0；如果原来是 signed，就按原来的符号位扩展。如果符号位是 1，表示它是负数，高 16 位全部补 1；否则高 16 位全部补 0。看几个简单的 case。

### 例：unsigned short 与 −1 比较

**23:31**

第一个 case：\(-1\) 和 unsigned short 的 1 相比，谁大谁小？\(-1 < 1\) 是否成立？按规则，unsigned short 小于 int，宽度不够，所以要把 unsigned short 先提升为 int 类型。提升为 int 时，要看原来的类型。原来是无符号整型，因此要补充高 16 位，因为它现在只有 16 位。由于它是 unsigned，高 16 位全部补 0。补完之后它仍然等于 1，然后按 int 去解释。

### 混合类型比较

**24:30**

它仍然是前面 31 位全是 0、最低位是 1，也就是值 1。因此 \(-1 < 1\) 显然成立，条件计算的结果是 true。

接着看下一个例子：short 的 -1 和 unsigned 的 1。

### short 的 -1 与 unsigned 的 1 的比较

**24:53**

unsigned 的位宽和 int 一样，也就是 unsigned int，位宽是 32 位，所以它先不用动。而 short 比 32 位小，因此需要先把 short 扩展，扩展到 32 位。再看这个例子：一个操作数是有符号数，另一个是无符号数，最终比较的目标类型必须是无符号类型。

所以要把 short 的 -1 转换成 unsigned int。转换时要看它原来的类型：它原来是有符号数。有符号的 short -1，它的 16 位分别是什么？确定全是 1。因为 -1 比较好记：如果按有符号数解释，全是 1 时，除最高位外其余位都是正的权重，最高位是负的权重，加起来一定是 -1。无论 8 位、16 位还是 32 位都是这样，所以 -1 的编码就是全 1。

另一个计算方式是先看它的相反数，也就是对应的正数。比如 1 的编码前面全是 0、最低位是 1。要求它的负数，就把这个编码取反加一：先按位取反，0 变 1、1 变 0，取反之后再加 1，这样就变成全 1。这是一个比较简单、可以口算的方式。

现在要把 short 的 -1 扩展到 32 位。short 本身有 16 位，一共有 16 个 1，后面还有 8 个 1 就不写了。扩展到 32 位时，前面还得补 16 位。补什么呢？因为它是有符号数，扩展时按照原来的最高位（符号位）扩展。原来符号位是 1，所以补 16 个 1。补完之后，如果按照 int 解释，它的值还是 -1，所以扩展之后值没有变。

但它最终要解释成 unsigned。32 位 unsigned 全 1 是什么值？是 UINT_MAX，也就是它能表示的最大正数。显然最后结果大于 1，而且远大于 1。所以这个条件的结果是 false。大概就是这样。

### 隐式转换与程序漏洞

**28:49**

如果比较条件左右两边的类型不一致，就会发生隐式类型转换，非常容易出错。很多程序漏洞就是由这类情况造成的。C 和 C++ 中这类 bug 比较多，因为类型检查没有那么严格；而一些其他语言相对而言，在你编码时就不允许出现类似问题，这类漏洞就可以避免。

### 位运算

**29:24**

下面再讲一些运算，即位运算。比如两个数都是通过某种编码方式得到的，例如 B2U（binary to unsigned）这样的编码方式。当我们对两个数做与、或、非、取反、异或时，实际效果相当于把这两个整数看成两个 bit vector。因为所有真正的整数，最后的编码都是 0/1；两个 vector 按位对齐后，最低位和最低位、最高位和最高位分别进行运算，所以都是按位计算。它还可以表达一些额外意思，比如作为集合运算。这是一个小小的扩展。

### 用位向量表示集合

**30:30**

比如用一个整数，一个四位整数，但实际上没有四位整数这种说法，我们只是举个例子，也可以把它想象成一个八位整数。比如表达课程选择：这四位从高到低分别表示四门课。如果一个同学选了某门课，就把对应位标成 1。每个同学有自己的一个四位 vector。

比如甲同学的 vector 是 1101，说明他的选课列表里选了 ICS、编译和图形学。乙同学的 vector 是 0110，说明他选了编译和操作系统，另外两门没选。

这时这两个 vector 就可以做一些计算。这是很经典的，LeetCode 上如果大家以前刷过，里面会有类似题目：怎样用非常精简的数据和代码表达这些含义。其实只需要用 8 个比特，8 个比特就可以编码“哪个同学选了哪门课”的信息。并且用一行代码、一个计算符号就可以计算出一些信息。比如最受同学欢迎的课是什么？所有同学都选的课，只要把这两个 vector 做一个交集。如果两个人都选了，只有两个 1 才会在结果 vector 中保留为 1。得到的结果是 0100，意味着编译课是最受大家欢迎的。

**32:35**

如果对两个 bit vector 做并集，就可以判断学校最终要开哪些课：有同学选的课都要开。对单个 vector 取反，表示某位同学没选哪些课；做异或（对称差）运算，则对应只有一个同学选的课。

### 掩码计算

**32:59**

位运算还有一些很有意思的用法，比如掩码计算，它在计算机中非常常见。看一些例子：假设一个 int 只有 4 位，把它与上 0xF，意思就是只保留最后的四位。

**34:12**

0xF 的二进制表示是什么？假设我们讨论的是一个 8 位的数字，那么它是前面四个 0、后面四个 1，即 0000 1111。任意一个 x 与它做与操作，无论 x 前面四位是什么，结果的前四位一定都是 0；后四位则保持原样。这就是所谓的掩码：把不想保留的高位全部清零，保留低位。

我们可以设置任意一个 mask 来做到这一点，只保留其中某些位、把另一些位清零：做与操作时，只要把要保留的位填 1，不想保留的位设成 0。例如把 mask 设成 0011 0011，任意 x 与它运算的结果就是 00XX 00XX，相当于隔两位做一次掩码。这就是常见的掩码计算。

**36:06**

如果换成或操作，例如或上 0x80：在 8 位下，0x80 的最高位是 1，其余全是 0，即 1000 0000。任意一个 x 或上 0x80，就意味着把它的最高位设成 1；如果把这个数解释成有符号数，就相当于把符号位设成 1，其他位保持不动。反过来，如果要清除 bit 7，就与上 0x80 的取反。这些都是常见的掩码计算：可以设置任意 mask 去做与和或操作。

### 子网掩码

**37:06**

这些掩码计算在实际中有什么案例？举两个计算机中常见的例子。每台机器都有一个 IP 地址。在 Windows 的网络管理器之类的界面里，可以配置 DNS，例如把 DNS 的 IP 设成 8.8.8.8；也可以设置自己的 gateway（网关）；还有一个地方叫子网掩码（subnet mask）。常见的子网掩码形如 255.255.255.0。

它做的事情是：给定任意两个 IP，在路由器这一层，或者机器自己，把 IP 与子网掩码做与操作，得到的结果相当于把最后的最低 8 位清零，把前面的前缀保留下来。如果保留下来前缀相同，就可以判断它们在同一个局域网里；如果前缀不一样，就知道它们不在同一个子网下。掩码计算在计算机里其实时时刻刻都在发生。

还有一个例子是文件的权限。先问一下大家：你们之前应该用过 shell、用过终端吧？现在大一，课程对开发环境的要求是 Windows 还是 Linux，还是不限制？大家平时用 Windows 或者 Linux 的时候，会去用命令行终端吗？有同学用，有同学不用，也不一定非要用到。

### CLI、MCP 与 agent 的工具调用

**39:50**

大家在用 agent 的时候应该听过 CLI；在 CLI 之前比较火的是 MCP，它们都是 agent 使用工具的方式。为什么需要 MCP？一个比较重要的原因是：大模型做完推理之后，要去调用工具，比如调用浏览器去搜索当天的信息。例如问它今天在上海发生了什么比较有意思的新闻——大模型是一个训练出来的静态模型。

### 工具调用与大模型的信息缺口

**40:43**

大模型是训练出来的静态模型。假设它去年完成训练，那么它自然不会知道今天发生了什么，训练时也没有见过今天的信息，不可能未卜先知。因此在向大模型提问时，它缺少两类信息：既不知道今天发生了哪些新闻，也不知道当前日期。给它一个 prompt，它无法知道今天是哪一天。

这时大模型需要返回一个结果给 agent，要求至少调用两个工具。第一个工具告诉它当前日期，例如读取系统日历；第二个工具拿着今天的日期，到浏览器里搜索今天上海发生了哪些事。这就是所谓的工具调用。工具之所以能增强最终的智能能力，是因为它给大模型提供了更多信息。有了新闻列表之后，再让大模型判断其中哪条比较有意思，这是语义层面的任务，它可以给出排序，比如哪条最好玩、哪条最奇葩。

### MCP 协议

**42:04**

这似乎扯得有点远。Anthropic 提出了一个协议，用统一规范规定 agent 或大模型如何调用不同工具。因为外部有各种浏览器、百度查天气、查日历、计算器等工具和应用程序，所以定一个统一规则，称为 MCP 协议，约定调用外部工具的方法。这样一来，大家可以采用统一方式，便于共享；软件接口一致之后，对技术发展也会有促进作用。

### 移位运算：逻辑右移与算术右移

**00:00**

左移时，超出的位被丢弃，后面补 0。右移则有两个名称，不像左移那样只有一个：一个叫逻辑右移（logical shift right），一个叫算术右移（arithmetic shift right）。逻辑右移和算术右移都是把比特往右推，区别在于空出来的高位补什么。

逻辑右移通常作用于无符号数：被推出去的位直接丢弃，前面空出的位一律补 0。

算术右移通常作用于有符号数：移出去的位同样丢弃，但空出的位要根据原来的最高位决定，这一点和符号扩展类似。有符号数扩展到更大位数时，前面补 0 还是补 1 由最高符号位决定；算术右移也一样，如果原来最高位是 1，就继续补 1。这样至少能保证正负属性不变：原来最高位是 1 表示负数，移完之后仍然是负数。

### 移位与乘除法的关系

**01:40**

在不发生溢出的情况下，移位相当于乘除 2 的幂：\(x\) 左移 \(k\) 位相当于 \(x \times 2^k\)，右移 \(k\) 位相当于除以 \(2^k\)。因为二进制表示中每一位对应相应的 2 的幂，左移一位并在后面补 0，结果就是乘以 2。

移位操作比乘除指令快。因此在一些计算中，编译器可能不会优先使用乘法或除法指令，而是把运算拆解成两条指令：一条加法和一条移位。用加法和移位替换乘法，可能获得更好的性能，甚至两条指令执行起来会比一条乘法指令更快，因为乘法相对较慢。

### 运算符优先级：一个例子

**03:02**

接下来是运算符优先级问题，这也是程序出现逻辑错误时常见的诱因：少打了括号，或者没有搞清楚优先级。

看一个例子，取 \(x = 6\)。

第一个表达式是 \(x \& 1 == 0\)。老师请一位同学判断结果。如果按同学猜测的优先级，先算 \(x \& 1\)，得到 0，再算 \(0 == 0\)，结果为真，也就是 1。但实际结果不是这样：C 语言中 `==` 的优先级高于 `&`，所以会先算 \(1 == 0\)，得到 0，再算 \(x \& 0\)，结果也是 0。\(x = 6\) 的二进制是 110。

第二个表达式涉及移位和加法：\(x << 1 + 2\)。这里要判断先移位还是先加。实际先算加法，\(1 + 2 = 3\)，再算 \(6 << 3\)，也就是 \(6 \times 2^3 = 48\)，所以结果是 48。

第三个表达式继续验证同样的优先级规则。老师强调，这些规则没有必要死记，因为规则很多、很复杂；实际做法是加括号，不要依赖优先级。

### 编译警告与括号

### 浮点编码的挑战

**08:02**

浮点编码有一个比较大的挑战。我们要编码一个浮点数，比如 float：之前说过 float 和 double 是两种浮点数类型，float 是 32 位，double 是 64 位，不是 44 位，在 32 位和 64 位平台上都是这样。

这就很挑战了，不像整数是可以数的：1 就是 1，2 就是 2，每个整数都有精确的编码与之对应。浮点数没法这样做：只有这么多位，而要表示的小数可能是无限位的，还会遇到无限循环小数，这些东西到底该怎么表示？

### 十进制小数与科学计数法

**09:44**

先看十进制小数，例如 12.375。它的形式是前面有一堆数、中间有一个点、后面有一堆数。求它数值的方式是每一位的权重为 10 的若干次方：小数点后第一位是 0.1，也就是 \(10^{-1}\)；再下一位是 0.01，也就是 \(10^{-2}\)，即百分之一。每一位乘上对应的权重再求和。

这样一个数还可以用科学计数法表示，例如 \(12.375 = 1.2375 \times 10^{1}\)。

### 二进制小数

**10:54**

二进制小数可以用同样的规则去写：中间有一个点，前面是整数部分，后面是小数部分。每一位对应 2 的若干次幂，整数部分和之前的 B2U（Binary to Unsigned）一样，是 \(2^{i}\)；小数部分则是 \(2^{-i}\)。小数点后第一位 0.1 就是二分之一，也就是 \(2^{-1}\)；再下一位 0.01 就是四分之一，也就是 \(2^{-2}\)。

它表示的有理数就是对这些项求和，即 \(\sum 2^{i} \cdot b_i\)，也就是对这个 bit vector 求和。

把小数点向前移到最高位，例如上面这个例子就变成 \(1.100011 \times 2^{3}\)，表示的正是 12.375。这时可以看到，用类似科学计数法的方式去表示一个浮点数是有好处的。

### 为什么采用科学计数法

**12:14**

那为什么要用科学计数法来表示呢？这里问了一下 AI，Grok 给的答案我觉得还可以，他是这么解释的：想象一下一个计算器。计算器上面有一小块 LED 屏幕，它里面能显示的位数是很有限的，只能显示屏幕那么宽，不像 terminal 或者屏幕可以非常大。

比如要表示一个很大的数，如果一位一位去表示需要九个格子；以前用卡西欧计算器，上面只能放下几个数字，十来个可能就到头了。如果是一个很小的数，又需要十个格子。假如计算器只能显示四个有效数字，那么能显示的东西就非常少，甚至根本显示不全。

所以它采用的一个方法就是用科学计数法：有效数字（尾数）部分都是 3.75，后面配以 \(10^{8}\)、\(10^{-7}\) 这样的指数。这样更加节约，可以用更少的位数去表达一个比较大的数或者一个很小的数，也就是节约我们编码的位数。

### 用乘 2 法求小数部分的二进制表示

**14:16**

那么 12.375 具体是怎么写成这样的？整数部分可以直接写，也就是小数点之前的部分；小数部分 0.375 是怎么写出来的？

之前我们说过，短除法把十进制数转成二进制，这里就反过来用乘法。以十进制的 0.2 为例，看看它的二进制小数表示如果用刚才说的二进制小数的方式去表示，会长成什么样。做法是每次乘 2：

- 0.2 乘 2 得 0.4，结果小于 1，说明小数点后第一位是 0；
- 0.4 再乘 2 得 0.8，仍小于 1，说明再后面一位还是 0，所以前两位都是 0；
- 0.8 乘 2 得 1.6，大于 1，说明第三位是 1；把整数部分去掉，让 0.6 继续乘；
- 0.6 乘 2 得 1.2，大于 1，说明小数点后第四位是 1。

这样小数点后依次得到 0、0、1、1，而此时剩下的部分又是 0.2 了。既然又是 0.2，就说明它是一个循环小数：用二进制来表达的话，就是循环小数。

### 乘 2 取整与二进制小数

**16:02**

继续乘下去，过程会不断循环，于是十进制 \(0.2\) 的二进制表示成为 \(0.00110011\ldots\) 这样的循环小数。为什么用不断乘 2 的方式可以得到二进制小数？可以这样理解：对二进制小数乘以 2，相当于把小数点右移一位。因此，如果乘 2 后整数部分大于等于 1，就说明当前这一位是 1；如果乘 2 后结果仍小于 1，就说明当前这一位是 0。按照这个原理，就可以逐位得到小数部分。

### IEEE 754 浮点数编码

**18:25**

采用类似科学计数法，可以用有限的位宽表达较大的数值范围。浮点数在历史上曾有很多不同的编码。20 世纪 80 年代以前，计算机还处于比较早期的阶段，出现过许多为了浮点计算速度等目标而定制的浮点格式，但彼此并不统一。

后来 IEEE 754 标准被提出，由 William Kahan 教授等人推动，一直沿用到今天，并成为 IEEE 国际标准。这一标准也与 Intel 处理器的浮点设计有关。Kahan 于 1989 年获得图灵奖，IEEE 754 是他很重要的一项贡献。

IEEE 754 的编码非常简洁，也易于理解。其核心形式是：\[ (-1)^s \times M \times 2^E \] 其中 \(E\) 是指数。以 32 位浮点数为例，最高位是符号位 \(s\)，用 1 位表示：最高位为 0 表示正数，因为 \((-1)^0=1\)；最高位为 1 表示负数，因为 \((-1)^1=-1\)。除符号位外还剩 31 位，将其分成两部分：中间 8 位是阶码，即 exponent，经过一个简单计算后对应到 \(2^E\) 中的 \(E\)；后面 23 位对应乘的底数部分 \(M\)，称为 fraction，表示小数部分。32 位浮点数下，exponent 为 8 位，fraction 为 23 位。

64 位浮点数可以表达更大的范围：exponent 有 11 位，fraction 有 52 位。fraction（尾数）的位数越多，能够表示得越精确，比如可以表示 \(1.0000001\) 这样的数；阶码的位数则更多决定数值范围。

### 规格化值与阶码偏置

**22:20**

具体来说，exponent 这 8 位和真正的 \(E\) 之间是什么关系？fraction 部分和 \(M\) 之间又是什么关系？IEEE 754 定义了两种值：规格化值（normalized value）和非规格化值（denormalized value）。先看 normalized value。

对于 float，阶码部分不能全为 0，也不能全为 1；满足这个条件的都称为规格化值。除这两种情况外，大部分浮点数都是规格化的。

规格化值的真正幂次为：\[ E = \mathrm{EXP} - \mathrm{bias} \] 其中 \(\mathrm{EXP}\) 是 8 位阶码所表示的数值，\(\mathrm{bias}\) 是一个固定的偏置常数。对于 32 位浮点数，\(\mathrm{bias}=127\)。它的计算方式是 \(2^{m-1}-1\)，其中 \(m\) 是阶码的位数；阶码有 8 位，所以 \(2^7-1=128-1=127\)。

为什么会有这样一个看起来不那么直观的偏置？它的道理其实并不难理解。

### 为什么采用偏置指数

**24:18**

最直观的想法，是直接用这 8 位来表示指数 \(e\)。但指数 \(e\) 可正可负，比如 \(2^{10}\) 或 \(2^{-50}\)，所以指数必须能表示正负。有同学问，为什么不直接用有符号数？因为如果直接把最高位当作符号位，确实能表示正负，但会少掉一位：原来 8 位能表示 \(2^8=256\) 个数，现在只剩 7 位，只能表示 \(2^7=128\) 个数。为了节省这一位，不采用单独的符号位。如果按这种方案另加符号位，它就不是 IEEE 754 这个标准了。

另一种方案是把它当成补码来解释。无论用补码还是符号位，都要考虑指数域全 0 和全 1 不能随便占用，因为全 0、全 1 还要用来表示特殊值。偏置指数采用的做法是：让指数编码值减去一个偏置，把整个可表示范围平移，使它既能覆盖原来的 0 到 255，又能表示小于 0 的指数部分。这样 8 位指数能表达的指数范围更大。与有符号数方案的区别也在于，它保留了全 0 和全 1 的编码空间。核心是节约编码位数。这是规范的规定；后面会看到全 0、全 1 还能用来表示其他特殊值。这就是解码。

### 规格化浮点数的解码

**28:44**

解码时，指数部分用编码值减去偏置，前提是指数域不能全 0 或全 1。剩下的 23 位是尾数部分：把 fraction 看作小数部分，并在前面加上一个 1，得到 \(1.fraction\)。如果这 23 位全为 0，则 \(M=1.0\)，是最小值；如果全为 1，则 \(M=1.111...111_2 = 2 - 2^{-23}\)，非常接近 2，只比 2 小一点点，这是最大值。为什么把尾数写成 \(1.\) 开头？因为它省掉了一位：整数部分的 1 不存储，相当于多得到一位有效位。

### 查看 float 的二进制位

**30:04**

下面看一个规格化值的例子：float 值为 12345。我们需要看它的 exponent 和 fraction 分别是什么。用代码会比较容易：可以把 float 的 32 位直接打印出来。不能直接把 float 赋值给 unsigned；代码第 13 行用的是 memcpy。如果把第 13 行改成 `unsigned u = f;` 行不行？这里用 memcpy 的原因，是它把一个 memory buffer 从 source 拷贝到 destination，不做任何类型转换。由于 float 和 unsigned 都是 32 位，memcpy 相当于把 float 的 32 位内容按字节直接拷贝到 unsigned 中；拷贝后的 0/1 编码和原来的 float 完全一样。接下来只需要做简单操作：exponent 部分是把得到的 unsigned 值右移 23 位，去掉 fraction，再做一个 mask；fraction 部分则保留最后 23 位。

### 非规格化值的引入

**32:27**

从前面得到的位可以知道它的 exponent 分别是多少。因为这是一个正数，所以符号位一定是 0，进而可以得到 exponent 和 fraction。刚才说的是规格化值（normalized value）。有同学问：为什么还需要非规格化（denormalized）表示？

### 非规格化数的阶码与尾数

**32:52**

非规格化表示用来表达一些特殊的数。第一种是 exponent 全为零的情况，这时就是非规格化。此时阶码不再是 \( \text{exponent} - \text{bias} \)，而是 \(1 - \text{bias}\)。尾数的计算方式也变了：不再是 \(1.\text{fraction}\)，而是 \(0.\text{fraction}\)，fraction 是多少就是多少。这样它其实表达的是一个非常接近零的数。当 fraction 为零时，表达的就是零。

### 正零、负零与接近零的数

**33:45**

零有正零和负零两个表达，因为符号位不同。当 exponent 的八位全为零、fraction 的二十三位全为零时，最高位符号位为 0 代表正零，为 1 代表负零。如果 fraction 不为零，即小数部分不为零，由于指数 \(1-\text{bias}=-126\)，一个小数再乘以 \(2^{-126}\)，得到的就是非常小的数，非常接近零。这样通过非规格化的方式表达了一些非常接近零的数。浮点数要表达的是实数域，实数域在接近零的地方也非常密集，有无穷多个数，所以需要用这种方式表达接近零的数。

### 指数全为一时：无穷大

**34:50**

还有一种特殊值是 exponent 全为一。刚才 exponent 全为零时表达一个很小的数；exponent 全为一时要表达两种特殊值。第一种是 fraction 部分全为零，这时表示无穷大。这样既有很小的数，最大的数也能表示出来。中间的部分也能表达，但它是离散的表达，没有办法精确表达每一个数，因此可以覆盖实数轴上整体范围。当运算溢出时，就会得到正无穷和负无穷。

### NaN 与 IEEE 754

**35:34**

另一种情况是 exponent 全为一，而 fraction 部分不全为零。这时表示 NaN（not a number，非数）。什么情况会发生这种情况？比如一些非法的数，或者没有办法确定结果的运算，最后的结果就是 NaN。IEEE 754 标准规定了如何用 32 位的 float、用 32 位有限的 bit 去刻画一个浮点数，其实就是类似二进制科学计数法。

### 浮点数的组成与 64 位编码

**36:36**

浮点数有一个符号位、一个指数位和一个小数部分，用来刻画一个浮点数。64 位浮点数的编码方式类似，只是 exponent 部分和 fraction 部分的位数更多。浮点数大致有规格化和非规格化两类；非规格化下面表达很小的数。另外两类分别表示无穷大和非数。

### 8 位浮点 FP8 的格式

**37:13**

最后有一个小练习。自制一个 8 位浮点 FP8，它参考 IEEE 754 的规则。现在很多模型不会真的用 FP32，大概也就到 FP8，甚至 FP4、FP16 等更小的表示。我们看一个 8 位浮点，它的格式是这样：符号位是一位，跟之前一样；剩下七位中有四位表达 exponent，三位表达 fraction。四位 exponent 对应的 bias 是 \(2^{4-1}-1=7\)。

### 计算 2.5 的 8 位浮点编码

**39:12**

计算 2.5 要把它拆成两部分，先把 0.5 转成后面的那部分。0.5 是十进制的二分之一，二进制为 0.1。整数部分 2 是 10，所以 \(2.5=10.1_2=1.01_2\times 2^1\)。然后指数要加 7，看看它的 exponent 是多少。fraction 部分就是 0.01，即 01，因为要把第一位扔掉；编回的编码就是这个样子。

### 浮点数指数编码的补充讨论

**42:09**

关于浮点数的指数编码，讨论中补充了这些点：指数域的全 0 和全 255 不能按普通指数解释；指数编码范围是 0 到 255，使用时还要减去偏置值 127。如果尾数相加出现进位，会涉及指数部分的处理；这种设计对计算电路的实现比较好，但不能表示某些形式，讨论中也提到了负零。
